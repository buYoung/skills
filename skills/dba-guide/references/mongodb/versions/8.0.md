# MongoDB 8.0

Checked: 2026-11-27 against https://www.mongodb.com/docs/manual/release-notes/8.0/ and https://www.mongodb.com/docs/manual/release-notes/8.0-compatibility/.

Read this when the server reports 8.0.x, when upgrading from 7.0, or when planning 8.0 → 8.3 or 8.0 → 9.0.

## Lifecycle

- Major release. 8.0.0 shipped on 2024-10-02. End of life is 2029-10-31 for both self-managed and Atlas Dedicated.
- Latest public patch on 2026-11-27: 8.0.38 (2026-11-10). 8.0.39 (2026-11-18) is Atlas-only. The official `mongo:8.0` image reported 8.0.38.
- Critical advisories:
  - SERVER-95067 and SERVER-94559 affect 8.0.0-8.0.3.
  - SERVER-131805 affects 8.0.0-8.0.33. Run 8.0.34 or later; 8.0.37 carries many CVE fixes.
- 8.0.30 added `maxConcurrentMultiDocumentTransactions` (default 10000, SERVER-108215). A patch upgrade from 8.0.29 or older can start rejecting new transactions with `TooManyOpenTransactions` (code 509; enforced on the 8.0.38 container with the limit set to 1). See [transactions](../transactions-and-consistency.md#multi-document-transactions).

## Changed Defaults

| Item | 7.0 | 8.0 | Source |
| --- | --- | --- | --- |
| `w: "majority"` acknowledgment | after a majority applied the write | after a majority wrote the oplog entry; an immediate secondary read outside a causally consistent session may not see the write | compatibility |
| Secondary oplog application | single buffer | write and apply in parallel; `metrics.repl.buffer.count/maxSizeBytes/sizeBytes` deprecated, replaced by `metrics.repl.buffer.write.*` and `metrics.repl.buffer.apply.*` | compatibility |
| Ticket metrics location | `serverStatus().wiredTiger.concurrentTransactions` | `serverStatus().queues.execution` | compatibility; image shows `queues.execution` on 8.0, absent on 7.0 |
| Equality to `null` | also matched `undefined` | does not match `undefined` values or array elements (also `$eq`, `$in`, `$lookup` on null local field) | compatibility |
| Hedged reads with `nearest` | on by default | off by default; explicit hedging logs a warning | compatibility |
| `tcmallocReleaseRate` | 1 (0-10) | 0, now in bytes per second | compatibility |
| TCMalloc | per-thread caches | per-CPU caches; changes Transparent Huge Pages advice to enable THP (see [configuration](../configuration.md#operating-system)) | release notes, production notes |
| Slow-op threshold basis | `durationMillis` | `workingMillis` (excludes lock and flow-control waits) | release notes |
| Direct shard connections | most commands allowed | only listed commands, unless the user holds `directShardOperations` | compatibility |
| Index build write concern | nodes that finished the build | nodes that replicated the commit oplog entry | index build page |

## Removed or Deprecated

- Deprecated:
  - Index filters (use query settings).
  - LDAP authentication and authorization (still work through 8.x).
  - The `undefined` BSON type.
  - `cleanupOrphaned` (use `$shardedDataDistribution`).
  - `timeField` as a shard key.
  - `tcmallocAggressiveMemoryDecommit`.
  - `enableFinerGrainedCatalogCacheRefresh`.
- `queryHash` was deprecated; `planCacheShapeHash` duplicates it.
- Removed: the `storeFindAndModifyImagesInSideCollection` parameter, and the Queryable Encryption `rangePreview` algorithm (use `range`).
- `$accumulator`, `$function`, and `$where` were deprecated in 8.0. 9.0 reversed this.

## Worth Adopting

- Query settings:
  - `setQuerySettings` attaches index hints or a reject flag to a query shape without code changes; manage them with `removeQuerySettings` and `$querySettings`.
  - On the 8.0 image, `setQuerySettings` with `indexHints` returned a `queryShapeHash`. The same command fails on 7.0 with `no such command`.
  - `queryShapeHash` appears in explain, the profiler, `$currentOp`, slow logs, and `$queryStats`.
- `defaultMaxTimeMS` cluster parameter: a default time limit for read operations.
- Sharding:
  - `moveCollection` and `unshardCollection` (with abort commands) place unsharded collections on chosen shards.
  - `reshardCollection` accepts `forceRedistribution: true` to redistribute data on the same key, and is much faster than in 7.0.
  - A config shard (embedded config server) can hold application data; switch with `transitionFromDedicatedConfigServer` and `transitionToDedicatedConfigServer`.
- `bulkWrite` command: mixed inserts, updates, and deletes across collections in one request.
- `$lookup` is allowed in transactions that target sharded collections.
- Slow-query logs report `queues.execution.totalTimeQueuedMicros`, which separates ticket queueing from execution time. Profiler filters can use `workingMillis`.
- `compact` gains `freeSpaceTargetMB` and `dryRun`; `autoCompact` runs background compaction.
- Auditing can emit the OCSF schema (`auditLog.schema: OCSF`, Enterprise/Atlas).
- Queryable Encryption range queries (`$lt`, `$lte`, `$gt`, `$gte`) on encrypted fields.
- Express plan stages (`EXPRESS_IXSCAN`, `EXPRESS_CLUSTERED_IXSCAN`, `EXPRESS_UPDATE`, `EXPRESS_DELETE`) appear in explain for simple point operations.

## Upgrading Into This Series

Only 7.0 with FCV 7.0 can upgrade to 8.0; 6.0 must go to 7.0 first. Use the rolling procedure in [the versions index](index.md#upgrade-paths), then `setFeatureCompatibilityVersion: "8.0", confirm: true`. The FCV change performs an implicit reconfig that adds `term` to the replica set config.

Blockers and checks:

- Linux kernel and TCMalloc. This affects all packages, including Docker images:

  | MongoDB | Kernel 6.19-7.0.13 | Kernel 7.0.14+ |
  | --- | --- | --- |
  | 7.0.x | supported | supported |
  | 8.0.0-8.0.20 | crashes about 60 s after start, can corrupt data | supported |
  | 8.0.21-8.0.29, 8.3.0-8.3.8 | exits at startup | exits at startup |
  | 8.0.30+, 8.3.9+, 9.0.x | exits at startup | supported |

  On distributions whose kernel string looks like `7.0.0-XX-generic`, 8.0.21-8.0.36, 8.3.0-8.3.15, and 9.0.0-9.0.3 exit even on fixed kernels; use 8.0.37, 8.3.16, or 9.0.4 or later. Check `uname -r` on every host before the binary swap.
- Transparent Huge Pages: 7.0 wants THP disabled, 8.0+ wants it enabled (except PPC64LE/s390x). Change the host setting when you swap binaries.
- Null semantics: find queries and `$lookup` that rely on `null` matching `undefined`. Search application code and stored views.
- Non-time-series `system.buckets.*` collections: on 8.0.4 and earlier, drop or rename them before upgrading. On 8.0.5 and later, after. Find them with:

  ```javascript
  db.getCollectionInfos({ $and: [ { name: { $regex: /^system\.buckets/ } },
                                  { "options.timeseries": { $exists: false } } ] })
  ```
- Tools that connect directly to shard members. They need `mongos`, or the maintenance-only `directShardOperations` role (the release notes warn it can break the cluster when misused).
- Monitoring that reads `wiredTiger.concurrentTransactions` or `metrics.repl.buffer.count`. Switch it to `queues.execution` and `metrics.repl.buffer.write/apply`.
- Shutdown can take longer after bulk ingestion because more data is flushed. Allow for it in restart timeouts.
- Minimum OS levels rose: RHEL 8.8, RHEL 9.3, SLES 15 SP5, Amazon Linux 2023.3.
- Downgrade policy stated in the 8.0 notes:
  - Single step back to 7.0 only.
  - Binary downgrades are not supported for Community Edition.
  - After an FCV change, an Enterprise binary downgrade needs MongoDB support.
  - Treat raising FCV to 8.0 as one-way.

## Managed Service Notes

- Atlas Free and Flex clusters stay on 8.0 (Atlas versions page, 2026-11-27).
- On Atlas Dedicated: 7.0 → 8.0 and 8.0 → 9.0 are offered, and 8.0 → "Latest Version With Auto Upgrades". For upgrades to 8.0, Atlas asks you to check storage capacity and enable storage auto-scaling because of write-blocking behavior.
