# MongoDB 9.0

Checked: 2026-11-27 against https://www.mongodb.com/docs/manual/release-notes/9.0/ and https://www.mongodb.com/docs/manual/release-notes/9.0-compatibility/.

Read this when the server reports 9.0.x, when planning an upgrade from 8.0 or 8.3, or when an Atlas cluster on Auto Upgrades has moved to 9.0.

## Lifecycle

- Major release. 9.0.0 shipped on 2026-09-28. End of life is 2031-10-31 for both self-managed and Atlas Dedicated. Extended Lifecycle Support can be bought for majors (Enterprise Advanced).
- Latest public patch on 2026-11-27: 9.0.8 (2026-11-10). The official `mongo:9.0` image reported 9.0.8.
- 9.0.1, 9.0.4 and 9.0.7 contain CVE fixes; run the latest patch (9.0.8). Known issue SERVER-133518 (9.0.0-9.0.2, fixed in 9.0.4): a shard can hang during step-up and stay unavailable for primary reads and writes until the hung node is restarted.
- From 9.0, self-managed and Atlas Manual Upgrade clusters receive only majors and the annual `x.5` Feature Update release. Other 9.x minors go only to Atlas Auto Upgrade and Atlas Infinite clusters.

## Changed Defaults

| Item | Before 9.0 | 9.0 | Source |
| --- | --- | --- | --- |
| Concurrent multi-document transactions | no limit before 7.0.48, 8.0.30 and 8.3.7; from those patches the same parameter and default apply (SERVER-108215) | `maxConcurrentMultiDocumentTransactions` default `10000`; new transactions beyond it fail with `TooManyOpenTransactions` (code 509) | 9.0 release notes; 7.0, 8.0, 8.3 release notes; parameter reference |
| Per-operation query memory | unbounded | `internalQueryMaxMemoryUsageBytesPerOperation` = greater of 1 GB or 20% of process memory; failures return `ExceededMemoryLimit` (146) or `QueryExceededMemoryLimitNoDiskUseAllowed` (292) and log id `12932700` | release notes |
| Single expression memory | — | `internalQueryMaxSingleExpressionMemoryUsageBytes` 100 MB | release notes |
| `$queryStats` collection | off unless rate-limited on | on by default, sampling 1% of reads (`internalQueryStatsSampleRate` 0.01) and 1% of writes (`internalQueryStatsWriteCmdSampleRate` 0.01) | release notes |
| BSON validation of ingested data | `net.wireObjectCheck` option | always validates; `net.wireObjectCheck`, `--objcheck`, `--noobjcheck` deprecated | release notes |

## Removed or Deprecated

- `prefixPreview`, `suffixPreview`, and `substringPreview` Queryable Encryption query types were removed. Use `prefix`, `suffix`, or `substring` with the `string` algorithm. `fleDisableSubstringPreviewParameterLimits` can no longer override limits.
- `mongocryptd` is deprecated. Use the Automatic Encryption Shared Library.
- `net.wireObjectCheck` and the `--objcheck` and `--noobjcheck` options are deprecated.
- serverStatus renames: `shardingStatistics.databaseVersionUpdateCounters` (8.3) became `shardingStatistics.databaseShardingMetadataStatistics` with new fields. `metrics.changeStreams.showExpandedEvents` became `metrics.changeStreams.option.showExpandedEvents`. Update dashboards that use either name.
- The `checkMetadataConsistency` inconsistency type `ShardCatalogCacheCollectionMetadataMismatch` was removed.

## Worth Adopting

- Schema validation level `constraint`: guarantees every document in the collection satisfies the validator (see [data-modeling](../data-modeling.md#schema-validation)). It makes downgrade harder; see below.
- Query settings per command: `find`, `distinct`, and `aggregate` accept a `querySettings` document that applies to that execution only. Stored settings win on conflicting fields.
- `setQuerySettings` additions. Both require FCV 9.0.
  - `queryKnobs` overrides internal parameters for one query shape.
  - A per-shape `maxTimeMS`.
- `$queryStats` changes:
  - It covers `update`, `insert`, and `delete`.
  - Its output now groups metrics into `metrics.cursor`, `metrics.queryExec`, `metrics.queryPlanner`, and `metrics.writes`.
  - Scripts that read `metrics.docsExamined` must move to `metrics.queryExec.docsExamined`.
- Initial sync visibility: `replSetGetStatus.initialSyncStatus` reports `phase`, `totalAttempts`, and `bytesPerSecond` during logical initial sync.
- Monitoring additions:
  - Change stream cursor metrics under `metrics.changeStreams.cursor.*`, and `currentOp.cursor.changeStreams.optime`.
  - `metrics.operation.writeConflictRetryLimitHit` and `metrics.query.operationsFailedDueToMemoryLimit`.
- `sessionCatalogPartitions` (9.0.1) reduces session-catalog lock contention with many sessions.
- `useInternalAuthzForX509` makes X.509 clients use internal authorization while LDAP authorization is configured.
- Audit messages add `directRemote` (mongo schema) and `direct_endpoint` (OCSF schema). These record the real TCP peer behind a PROXY protocol header.
- New `mongosh` helpers `sh.shardDrainingStatus()` and `sh.getTransitionToDedicatedConfigServerStatus()`.

## Upgrading Into This Series

Allowed sources: 8.0 (FCV 8.0) or 8.3 (FCV 8.3). From 7.0, upgrade to the latest 8.0 first. The procedure is the rolling one in [the versions index](index.md#upgrade-paths). Raising FCV to 9.0 also performs an implicit `replSetReconfig` that adds `term` to the replica set config.

Blockers and checks:

- Linux kernel. Read the kernel/TCMalloc table in the [8.0 file](8.0.md#upgrading-into-this-series). 9.0.x exits at startup on kernels 6.19 through 7.0.13. On distributions with Ubuntu-style `7.0.0-XX-generic` release strings, 9.0.0-9.0.3 exit even on fixed kernels. Use 9.0.4 or later.
- Sharded clusters with `ShardingTaskExecutorPoolMinSize` greater than 1 (SERVER-136226, open). Every node opens at least that many connections to each config server, which can exhaust the config servers. With dedicated config servers, set `ShardingTaskExecutorPoolMinSizeForConfigServers` to `1` before upgrading. With embedded config servers, the release notes say to contact MongoDB Support.
- ODMs that sync indexes at startup (SERVER-89953). The release notes say that at FCV 9.0 `listIndexes` reports `collation: { locale: "simple" }`. A new index on the 9.0.8 image at FCV 9.0 showed no collation field, so check your own deployment's `listIndexes` output after raising FCV. Mongoose `syncIndexes()`, and possibly Doctrine ODM or Beanie (`allow_index_dropping: true`), then drop and rebuild unchanged indexes on every start. Stop calling `syncIndexes()` at startup, or upgrade Mongoose to 9.10.4 or 8.24.5, before raising FCV. Preview with `diffIndexes()`.
- Server-side JavaScript. Review `$function`, `$accumulator`, `$where`, and `mapReduce` code for local-time `Date` methods: results change silently because evaluation is now in UTC. On `ppc64le` these operations fail; rewrite them as aggregation stages before upgrading.
- Error code changes:
  - `$group` with an empty accumulator field name now errors.
  - 2dsphere key extraction failures return `510` and `511` instead of `16755`, `16756`, `183934`, and `183493`.
  - Queries can fail with `QueryKilledError` when an indexed field becomes multikey during the query; re-run them.
- Change streams opened with read preference `primary` or `secondary` return resumable error `11602` (`InterruptedDueToReplStateChange`) after an election changes the node's role. Drivers resume automatically. Hand-written `getMore` loops must resume with `resumeAfter`.
- Cross-database `renameCollection` on replica sets now holds exclusive locks on source and target for the whole operation. It blocks writes and DDL on both; most reads are lock-free.
- Time series:
  - Databases with more than 5,000 time series collections may see longer upgrades and write latency spikes. Drop unneeded collections first.
  - Non-time-series collections named `system.buckets.*`: on 8.0.5 or later, drop or rename them after the upgrade; on 8.0.4 or earlier, before it.
  - Do not change FCV between 8.x and 9.0 while `mongodump --oplog` runs against a deployment with time series collections.
- Queryable Encryption collections that use the 8.2/8.3 public-preview prefix/suffix/substring types are incompatible with the 9.0 GA feature. Re-create them, or migrate the decrypted data through a 9.0 driver. `mongodump` does not decrypt.
- Downgrade from 9.0: first update or drop views that use `$convert` from object to `binData`, and collections at validation level `constraint`. Then lower FCV to `8.3` (or `8.0` when going back to 8.0) with `confirm: true`, and replace binaries (secondaries first, then the primary). Downgrade only to the latest patch of the target.

Known open issue: SERVER-136961 (8.3.0+ and 9.0.0+). A node that shuts down uncleanly and then restarts into file copy based initial sync crashes on every restart. Restart it with `initialSyncMethod: logical`, or empty its `dbPath` and restart.

## Managed Service Notes

- Atlas Dedicated clusters on Manual Upgrades can select 9.0 (upgrade path 8.0 → 9.0). Pin the FCV before upgrading if a downgrade must stay possible (up to 4 weeks).
- Atlas Infinite (public preview) always runs the latest 9.x and cannot choose a version. See [managed-services](../managed-services.md).
