# MongoDB 7.0

Checked: 2026-11-27 against https://www.mongodb.com/docs/manual/release-notes/7.0/ and https://www.mongodb.com/docs/manual/release-notes/7.0-compatibility/.

Read this when the server reports 7.0.x, or when planning the 7.0 → 8.0 step before its end of life.

## Lifecycle

- Major release. 7.0.0 shipped on 2023-08-15. End of life is 2027-08-31 for both self-managed and Atlas Dedicated, the earliest of the covered series. Plan the move to 8.0 now.
- Latest public patch on 2026-11-27: 7.0.48 (2026-11-10, 16 CVE fixes). 7.0.49 (2026-11-18) is Atlas-only. The official `mongo:7.0` image reported 7.0.48.
- Critical advisories span 7.0.0 to 7.0.15 (several issues), plus SERVER-131805 in 7.0.0-7.0.44. Run 7.0.45 or later.
- 7.0.48 added `maxConcurrentMultiDocumentTransactions` (default 10000, SERVER-108215). A patch upgrade from 7.0.47 or older can start rejecting new transactions with `TooManyOpenTransactions` (code 509; enforced on the 7.0.48 container with the limit set to 1).

## Changed Defaults

| Item | Before 7.0 | 7.0 | Source |
| --- | --- | --- | --- |
| Storage engine tickets | static maximum (value not restated in the 7.0 pages checked) | dynamically adjusted maximum (never above 128 read and 128 write); ticket usage drops after upgrade by design | WiredTiger page, release notes |
| `setFeatureCompatibilityVersion` | no confirmation | requires `confirm: true` | release notes |
| Journaling | optional | always on; `storage.journal.enabled`, `--journal`, `--nojournal` removed (from 6.1) | compatibility |
| Auto-splitting | — | none; the balancer distributes by data size; `sh.enableAutoSplit()` is a no-op (from 6.x) | compatibility, release notes |
| AutoMerger | — | enabled by default | release notes |
| `coordinateCommitReturnImmediatelyAfterPersistingDecision` | true | false (from 6.1) | compatibility |

## Removed or Deprecated

- Free Monitoring was removed: `cloud.monitoring.free`, `--enableFreeMonitoring`, `db.enableFreeMonitoring()`, `db.disableFreeMonitoring()`, `setFreeMonitoring`.
- SNMP was removed; its options stop `mongod` from starting (from 6.1).
- `addShard` `maxSize` was removed (from 6.2).
- Deprecated: `storageDetails`, and `taskExecutorPoolSize` on Linux.
- `$natural` accepts only `1` or `-1`.

## Worth Adopting

- `analyzeShardKey` and `configureQueryAnalyzer`: measure a candidate shard key before sharding or resharding (see [replication-and-sharding](../replication-and-sharding.md#evaluate-a-shard-key-before-using-it)).
- Compound wildcard indexes. They need FCV 7.0. A pre-7.0 `mongod` will not start with them present.
- Queryable Encryption with equality queries is GA. It is incompatible with the 6.x preview.
- `$changeStreamSplitLargeEvent` splits change events larger than 16 MB.
- `mongos` supports `fsync` with `lock: true` from 7.0.2. This makes the self-managed sharded `mongodump` procedure possible (see [backup-and-recovery](../backup-and-recovery.md#sharded-clusters)).
- Slow-query logs carry `queryFramework` (`classic` or `sbe`). The 7.0 image runs with `internalQueryFrameworkControl: forceClassicEngine`; 8.0 and later images show `trySbeRestricted`.

## Upgrading Into This Series

From 6.0 (FCV 6.0) only. 6.0 reached end of life on 2025-07-31; its procedures are in the legacy docs. Before upgrading:
- Drop views on `system.buckets`.
- Remove `maxSize` from `addShard` usage.
- Remove SNMP and journaling options from configuration files.

Leaving 7.0 for 8.0: see [8.0](8.0.md#upgrading-into-this-series). The main host-level changes are the THP flip (disable on 7.0, enable on 8.0) and the kernel/TCMalloc table. Upgrade to the latest 7.0 patch first.

Downgrade policy from the 7.0 notes:
- Only 7.0 → 6.0.
- No binary downgrade for Community Edition.
- No FCV change to or from a rapid release.
- An Enterprise binary downgrade after an FCV change needs MongoDB support.

Before downgrading, remove compound wildcard indexes, custom time series bucketing, and the other backward-incompatible features listed on the compatibility page.

## Managed Service Notes

- Atlas Dedicated 7.0 reaches end of life on 2027-08-31. The lifecycle policy says Atlas notifies at least six months ahead, then upgrades clusters left on the version to the current default target version (not necessarily 8.0) during the maintenance window.
