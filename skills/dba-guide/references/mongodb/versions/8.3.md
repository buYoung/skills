# MongoDB 8.3

Checked: 2026-11-27 against https://www.mongodb.com/docs/manual/release-notes/8.3/, https://www.mongodb.com/docs/v8.3/release-notes/8.3/ (which also lists the 8.2 changes), and https://www.mongodb.com/docs/v8.3/release-notes/8.3-compatibility/.

Read this when the server reports 8.3.x, when moving from 8.0 or 8.2 to 8.3, or when deciding whether a self-managed deployment should run a minor release.

## Lifecycle

- Minor release. 8.3.0 shipped on 2026-05-04. Self-managed end of life is 2029-10-31. The Atlas Auto Upgrade track lists end of life as "TBD, no sooner than October 2026".
- Latest public patch on 2026-11-27: 8.3.17 (2026-11-10). The official `mongo:8.3` image reported 8.3.17.
- The release notes say minor releases do not support every feature, notably Atlas Live Migration and `mongosync`. Use a major release if you depend on them.
- Critical advisory SERVER-131805 affects 8.3.0-8.3.12. A recovered cross-database `renameCollection` participant can drop the target after stepdown. 8.3.13 is the minimum for that advisory. CVE fixes landed in 8.3.3, 8.3.4, 8.3.7, 8.3.8, 8.3.9, 8.3.11, 8.3.13 and 8.3.16, so run the latest patch (8.3.17).
- 8.3.7 added `maxConcurrentMultiDocumentTransactions` (default 10000, SERVER-108215): a patch upgrade from 8.3.6 or older can start rejecting new transactions with `TooManyOpenTransactions`. See [transactions](../transactions-and-consistency.md#multi-document-transactions).

## Changed Defaults

| Item | Before | 8.3 | Source |
| --- | --- | --- | --- |
| Plan selection | multi-planner | multi-planning with a cost-based ranker (CBR) backup for eligible queries (listed under 8.3.3) | release notes |
| `2dsphereIndexVersion` | an earlier index version (`3` on the 7.0 and 8.0 images) | `4` | compatibility; images |
| `diagnosticDataCollectionDirectorySizeMB` (FTDC) | 200 | 500 | release notes |
| Profiler/slow log | — | `slowinprogms` / `slowOpInProgressThresholdMs` default 5000 ms logs in-progress slow queries once | release notes; `db.getProfilingStatus()` on 8.3 and 9.0 shows `slowinprogms: 5000` |
| `validate` with `full: true` | enabled `checkBSONConformance` | no longer enables it automatically; also checks for documents over 16 MB | release notes |
| `$text` `TextOr` stage | unbounded memory | limited to 100 MB; spills with `allowDiskUse: true`, else fails | release notes |
| Upsert producing an oversize document | error 17419 or 17420 | `10334` `BSONObjectTooLarge` | release notes |
| `$facet` over 100 MB | error 4031700 | `ExceededMemoryLimit` | compatibility |
| DDL on sharded clusters | could run on shards | DDL and `applyOps` only through `mongos` | release notes |
| `SCRAM-SHA-1` with `--tlsFIPSMode` | allowed | startup error `SCRAM-SHA-1 is not allowed in FIPS mode.` | release notes |

Changes first made in 8.2 and therefore also present in 8.3 (relevant when going 8.0 → 8.3):

| Item | 8.0 | 8.2+ |
| --- | --- | --- |
| `orphanCleanupDelaySecs` | 900 | 3600 |
| `terminateSecondaryReadsOnOrphanCleanup` | — | new, default `true` |
| Index build memory during initial sync | — | `initialSyncIndexBuildMemoryPercentage` 10% of RAM, bounded 200 MB-16 GB (also 8.0.13, 7.0.26) |
| Geospatial index generation | legacy coordinates could win | GeoJSON coordinates take priority; rebuild affected geospatial indexes if documents carry both |

| `cpuNanos` | in `operationMetrics` | in `$queryStats` metrics (Linux only) |

## Removed or Deprecated

- `removeShard` is deprecated. Use `startShardDraining`, `shardDrainingStatus`, `stopShardDraining`, and `commitShardRemoval`.
- The serverStatus `service` field was removed. The 8.0 image reports `service: [ 'shard' ]`; 8.3, 9.0, and 7.0 have no `service` field.
- The `config.csrs.indexes` namespace was removed.
- Time series:
  - `refineCollectionShardKey` accepts only the logical meta and time fields.
  - An index named `_id_` and a hint of `_id_` are rejected.
  - A `timeField` may not start with `$`.
- A replica set that used to be a sharded cluster cannot be converted back into a sharded cluster without MongoDB Support.

## Worth Adopting

- Cost-based ranking:
  - Explain gains `costEstimate`, `cardinalityEstimate`, `numKeysEstimate`, `numDocsEstimate`, and `estimatesMetadata` (8.3.3).
  - serverStatus gains `metrics.query.cbr.*`.
  - Re-check plans for top query shapes after upgrading.
- Memory tracking: `inUseTrackedMemBytes` and `peakTrackedMemBytes` appear in `$currentOp`, the profiler, and slow-query logs. `peakTrackedMemBytes` also appears in explain and `$planCacheStats`. This finds the operations that use the most memory.
- serverStatus additions:
  - `serverStatus({ none: 1, <section>: 1 })` returns only the sections you name. The 7.0.48 and 8.0.38 images already honor the same form and return only the named sections plus the base fields (`host`, `version`, `process`, `pid`, `uptime*`, `localTime`, `ok`; 8.0 also `service`).
  - `lockContentionMetrics: 1` adds lock contention data.
  - `queues.execution` gains prioritization and deprioritization fields. The 9.0 image also shows them: `usesThroughputProbing`, `heuristicDeprioritization`, `lowPriority`, and others.
- Shard draining is now controlled by explicit commands (listed above), and new commands transition between embedded and dedicated config servers. `mongod --replicaSetConfigShardMaintenanceMode` converts a replica set directly into an embedded config shard.
- Overload protection:
  - Pre-auth connection limits: `capMemoryConsumptionForPreAuthBuffers`, `preAuthMaximumMessageSizeBytes`, `messageSizeErrorRateSec`.
  - `ingressRequestRateLimiterApplicationExemptions`.
  - `overloadAwareServerSelectionEnabled` (opt-in).
  - `cachePressureQueryPeriodMilliseconds`: under storage cache pressure the oldest transaction is aborted.
- Balancer: `activeBalancerWindowDOW` sets the balancer window by day of week. It is lost on downgrade.
- Shard servers include `mongos`-originated queries in their query stats. Slow-query logs gain `originalQueryShapeHash`.
- 8.2 features included in 8.3:
  - `--wiredTigerCacheSizePct` / `storage.wiredTiger.engineConfig.cacheSizePct`.
  - Negative zstd levels (`zstdCompressionLevel` -7..22).
  - Standardized spill fields in explain.
  - Ingress connection establishment rate limiting (`ingressConnectionEstablishmentRateLimiterEnabled`, default `false` on the image).
  - `targetedMirroring` for `mirrorReads`.
  - `validationAction: "errorAndLog"` (8.1).

## Upgrading Into This Series

Sources: 8.0 with FCV 8.0, or 8.2 with FCV 8.2. All cluster members must be running before you start. Use the rolling procedure in [the versions index](index.md#upgrade-paths), then `setFeatureCompatibilityVersion: "8.3", confirm: true`.

Checks:

- Kernel:
  - 8.3.0-8.3.8 exit at startup on kernels 6.19 and later.
  - 8.3.9 and later need kernel 7.0.14 or later.
  - With Ubuntu-style kernel version strings, use 8.3.16 or later.
- Applications that match on error codes 17419, 17420, or 4031700. Update them for `10334` and `ExceededMemoryLimit`.
- Sharded-cluster automation that issues DDL directly against shards. Route it through `mongos`.
- Geospatial data with both legacy and GeoJSON coordinates (behavior change since 8.2). Validate geo queries and rebuild indexes where results change.
- FIPS deployments that list `SCRAM-SHA-1` in `authenticationMechanisms`. Remove it, or the server will not start.
- Stricter `wildcardProjection` validation for compound wildcard indexes (also in 8.2.4, 8.0.18, 7.0.29). Existing indexes keep working, but recreating them from old definitions may fail.
- Downgrade from 8.3 (to 8.2, or to 8.0 when that is the previous step) is a single step. First remove:
  - 2dsphere version 4 indexes;
  - views and validators that use 8.3 expressions, parameters, or variables (including `$$IDX` and `arrayIndexAs`);
  - collections marked validated under 8.3 semantics;
  - `errorAndLog` validation actions.

Known open issue SERVER-136961 also applies (see [9.0](9.0.md#upgrading-into-this-series)).

## Managed Service Notes

- Atlas offers 8.3 only on the "Latest Version With Auto Upgrades" track. Atlas Dedicated clusters on Manual Upgrades choose majors (7.0, 8.0, 9.0).
