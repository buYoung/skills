# Memcached 1.6

Checked: 2026-11-27. Read this when the server reports `VERSION 1.6.x`, when choosing a 1.6 patch, or when moving from 1.5.

## Lifecycle

- 1.6.0 released 2020-03-08; latest 1.6.45 released 2026-07-09 (https://memcached.org/, release notes index). No later release on 2026-11-27.
- No published end-of-support. Upstream fixes land only in the next 1.6 patch; run the latest.
- Security floor (interpretation of the release notes): 1.6.42 (2026-05-18) was "a major security focused release" fixing memory corruption and crashes without CVEs, and 1.6.43 (2026-07-02), 1.6.44 (2026-07-06) and 1.6.45 (2026-07-09) fixed more crash and security bugs, including ASCII auth enforcement and binary-protocol refcount overflows. Any instance reachable by untrusted clients should run 1.6.45.

## Changed Defaults

Defaults in 1.6.45 from `memcached -h` and `stats settings` (official image):

| Setting | Option | Default |
| --- | --- | --- |
| item memory | `-m` | 64 MB (`maxbytes 67108864`) |
| max connections | `-c` | 1024 |
| worker threads | `-t` | 4 |
| max item size | `-I` | 1 MB (min 1k, max 1024m) |
| slab growth factor | `-f` | 1.25 |
| minimum chunk | `-n` | 48 bytes |
| largest slab chunk | `-o slab_chunk_max` | 512 KB (`524288`) |
| UDP | `-U` | 0 (off; since 1.5.6) |
| TCP backlog | `-b` | 1024 |
| protocol | `-B` | auto-negotiate (ascii/binary) |
| requests per event | `-R` | 20 |
| hash | `-o hash_algorithm` | murmur3 (jenkins, xxh3 available) |
| segmented LRU | `lru_segmented` | yes; `hot_lru_pct 20`, `warm_lru_pct 40`, `hot_max_factor 0.20`, `warm_max_factor 2.00` |
| LRU crawler | `lru_crawler` | yes (`lru_crawler_sleep 100`, `tocrawl 0`) |
| temporary TTL LRU | `temp_lru` / `temporary_ttl` | no / 61 |
| slab rebalancing | `slab_reassign` / `slab_automove` | yes / 1 (`slab_automove_ratio 0.80`, `window 10`) |
| idle client timeout | `-o idle_timeout` | 0 (off) |
| flush_all | `-F` disables | enabled |
| cachedump/metadump | `-X` disables | enabled |
| TLS minimum | `-o ssl_min_version` | tlsv1.2 |
| extstore item size | `-o ext_item_size` | 512 bytes |
| extstore write buffer | `-o ext_wbuf_size` | 4 MB (the docs page says 8 MB; the 1.6.45 binary reports 4 MB) |

1.6.0 changes from 1.5: extstore compiled in by default (still off until `ext_path` is given), idle connection memory reduced to 400–500 bytes, per-thread read/response buffer pools with limits `-o read_buf_mem_limit` and `-o resp_obj_mem_limit` (the latter name is from the 1.6.0 notes; `memcached -h` in 1.6.45 lists only `read_buf_mem_limit`, and 1.6.45 starts with `-o resp_obj_mem_limit=10` but logs `DEPRECATED: resp_obj_mem_limit no longer used. See read_buf_mem_limit`).

## Removed or Deprecated

- Binary protocol: officially deprecated in 1.6.0; still supported with fixes but no new commands. SASL authentication works only over the binary protocol.
- 1.6.43: `lru_crawler metadump` and `mgdump` output now begins with `OK\r\n` before the data stream. Dump parsers written for older output must accept it.
- 1.6.41: `slabs_mover=2` start option is strongly discouraged (rare crash, poor hit rates).

## Worth Adopting

| Feature | Since | Why it changes a decision |
| --- | --- | --- |
| Meta protocol (`mg`, `ms`, `md`, `ma`, `mn`, `me`) | complete in 1.6.0 | stampede protection (`N`, `R`, `W`/`Z` flags), serve-stale (`md ... I`), TTL and last-access introspection, opaque pipelining; replaces binary protocol |
| Response batching | 1.6.0 | pipelined requests answered with fewer syscalls; 1.5 keys-per-syscall gains apply automatically |
| CAS override `E` flag | after 1.6.27 (docs) | store an external version (row version, clock) as CAS for cross-pool consistency |
| Built-in proxy | 1.6.23 (docs) | route by key prefix, pools, zones; needs a proxy-enabled build (the official image is one) |
| New slab page mover | 1.6.34 (per 1.6.41 notes) | memory moves between slab classes; regressions fixed in 1.6.41 — avoid 1.6.34–1.6.40 if slab rebalancing stalls |
| Unified protocol parser | 1.6.40 | proxy and core share one parser; the `lru` tuning command was broken in 1.6.40 and fixed in 1.6.41 |
| `mg` with `C<cas>` and `v` | 1.6.40 | returns `HD` without the value if CAS matches, `VA` if changed: cheap revalidation of tiered caches |
| TLS certificate reload on `SIGHUP` | 1.6.40 | rotate certificates without the `refresh_certs` command |
| Extstore compaction fix | 1.6.41 | frequently accessed items could be lost during compaction since extstore was written |

## Upgrading Into This Series

From 1.5:

1. Inventory clients that use the binary protocol (including SASL). They keep working, but plan a move to meta or text protocol.
2. Check for `-o modern`/`no_modern` start options: `modern` "enables options which will be default in future" (currently nothing); `no_modern` reverts to 1.4-era defaults and should be removed.
3. If you rely on warm restart, 1.5.18 or later can restart into 1.6; earlier versions start empty.
4. Re-baseline memory per connection; many-connection deployments use far less memory after 1.6.0.
5. Roll one node at a time and watch hit ratio and backend load.

Within 1.6: go directly to 1.6.45; read the notes from your version forward for output changes (1.6.43 dump format) and regressions fixed later (1.6.34 mover, 1.6.40 parser).

## Managed Service Notes

ElastiCache offers Memcached 1.6.22, 1.6.17, 1.6.12 and 1.6.6 (plus older 1.5 and 1.4 versions) on 2026-11-27, all far behind upstream 1.6.45, so none of the 2026 upstream security fixes are guaranteed there (AWS may patch independently). In-transit encryption starts at ElastiCache 1.6.12; extstore is not supported; from 1.6.17 the `lru_crawler`, `lru` and `slabs` admin commands are unavailable. Details in [managed-services.md](../managed-services.md).
