# Valkey 8.1

Checked: 2026-11-27. Read this when the server reports `valkey_version:8.1.x`, when moving from 8.0, or when choosing the long-lived 8.x line.

## Lifecycle

- First release 2025-03-31. Maintenance support ends 2028-03-31; security support ends 2030-03-31, the extended window for the 8.x major (https://valkey.io/topics/releases/).
- Latest patch on 2026-11-27: 8.1.12 (2026-11-18, security).
- RDB version 11. Files stay loadable by 8.0, 7.2 and Redis OSS 7.2.

## Changed Defaults

No default value of an existing setting changed between 8.0 and 8.1 in the official images for the settings checked (persistence, replication, lazyfree, io-threads, slowlog, latency monitor). New settings; defaults as shown in the 8.1 image:

| Setting | Default | Purpose |
| --- | --- | --- |
| `commandlog-execution-slower-than` | 10000 (µs) | slow-execution log threshold |
| `commandlog-slow-execution-max-len` | 128 | entries kept |
| `commandlog-request-larger-than` / `commandlog-reply-larger-than` | 1048576 bytes | large request/reply thresholds |
| `commandlog-large-request-max-len` / `commandlog-large-reply-max-len` | 128 | entries kept |
| `rdb-version-check` | `strict` | `relaxed` tries to load RDB files from newer Valkey versions |
| `import-mode` | `no` | suspend expiration and eviction while bulk-importing |
| `log-format` / `log-timestamp-format` | `legacy` | `logfmt` (and `json` from 9.1); `iso8601`, `milliseconds` |
| `active-defrag-cycle-us` | 500 | defrag time slice |

8.1.0 GA: with `hide-user-data-from-log yes`, the input buffer is no longer logged on protocol errors. 8.1.0-rc2 enabled `TCP_NODELAY` on server-initiated cluster bus and replication connections.

## Removed or Deprecated

- `io-threads-do-reads` is deprecated and has no effect; I/O threads always do reads. Remove it from config files.
- `dynamic-hz` is deprecated; server cron jobs adapt by default.
- Streams use 8 more bytes each to track their internal size (8.1.0-rc1 notes; AWS lists this under 8.0).
- 8.1.10: `sanitize-dump-payload` becomes a no-op; payloads are always validated.
- 8.1.8: strict CRLF parsing (malformed line endings rejected).

## Worth Adopting

- New hashtable for keys, sets, hashes and sorted sets, plus embedded hash values: lower memory per key. The official images show `MEMORY USAGE` of a 2-field hash at 48 bytes on 8.1 versus 64 on 8.0 and 72 on 7.2 (single sample, see [memory-and-configuration.md](../memory-and-configuration.md)).
- `SET key value IFEQ expected` (compare-and-set on a string without Lua or `WATCH`); see [data-modeling.md](../data-modeling.md).
- `COMMANDLOG GET <count> slow|large-request|large-reply`: one log for slow commands and for large requests and replies. `SLOWLOG` still works.
- `BGSAVE CANCEL` to stop a running or scheduled background save.
- `LATENCY LATEST` adds sum and count; `INFO clients` adds `paused_reason`, `paused_actions`, `paused_timeout_milliseconds`; `CLIENT LIST` shows client capabilities.
- Up to 256 I/O threads; replication stream reads offloaded to I/O threads; faster TLS with I/O threads.
- `import-mode yes` on a target while loading data from another system, so keys do not expire or get evicted mid-import; set it back to `no` afterwards.
- `rdb-version-check relaxed` tries to load RDB files from newer Valkey versions and aborts on unknown content. 8.1.12 accepted a 9.0.8 file with the `VALKEY` magic that held only strings, and exited on one with a field-TTL hash (`Unknown RDB encoding type 22`); test with your own data before counting on it as a rollback path from 9.x.

## Upgrading Into This Series

From 8.0:

1. Remove `io-threads-do-reads` and `dynamic-hz` from config files.
2. Re-baseline memory: after the upgrade, `used_memory` usually drops; do not shrink `maxmemory` until a full key population has been rewritten or reloaded (savings apply to keys as they are written or loaded).
3. If log shippers parse server logs, keep `log-format legacy` until parsers are updated.
4. Rolling upgrade, replicas first. Nodes on 8.0 and 8.1 can replicate with each other while new commands (`SET ... IFEQ`) are unused.

## Managed Service Notes

- ElastiCache "8.1 for Valkey" adds the Bloom filter data type (plain self-hosted 8.1 images do not have `BF.*`) and `COMMANDLOG`; `COMMANDLOG` is unavailable on serverless 8.1 and 8.2 caches.
- ElastiCache "8.2 for Valkey" is upstream 8.1 plus the valkey-search module (vector search), with search parameters `search-fanout-target-mode`, `search-default-timeout-ms`, `search-enable-partial-results`. There is no upstream Valkey 8.2.
