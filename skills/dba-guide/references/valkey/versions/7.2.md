# Valkey 7.2

Checked: 2026-11-27. Read this when the server reports `valkey_version:7.2.x`, or when moving Redis OSS 7.2 or older to Valkey.

## Lifecycle

- First release 2024-04-16 (7.2.5 GA; 7.2.4 RC1 was the first build, based on Redis OSS 7.2.4). Maintenance support ends 2027-04-16; security support ends 2029-04-16 (https://valkey.io/topics/releases/).
- Latest patch on 2026-11-27: 7.2.16 (2026-11-18, security release for CVE-2026-130822).
- RDB version 11, the same as Redis OSS 7.2. Files move both ways between Redis OSS 7.2 and Valkey 7.2.

## Changed Defaults

Compared with Redis OSS 7.2.4, Valkey 7.2 keeps the Redis defaults. Values from the official `valkey/valkey:7.2` image (7.2.16) that later series change:

| Setting | 7.2 value | Changes in |
| --- | --- | --- |
| `lazyfree-lazy-eviction`, `-expire`, `-server-del`, `-user-del`, `-user-flush`, `replica-lazy-flush` | `no` (all observed in the 7.2 image) | 8.0 sets them to `yes` |
| `repl-backlog-size` | 1048576 (1 MB) | 8.0: 10 MB |
| `hide-user-data-from-log` | not present | present and `yes` in 8.0 |
| INFO mode field | `redis_mode:` | 8.0 renames to `server_mode:` |

## Removed or Deprecated

Nothing removed relative to Redis OSS 7.2.4. Changes inside 7.2 patch releases that alter behavior:

- 7.2.14: requests with malformed CRLF line endings are rejected as protocol errors instead of being parsed leniently. Clients that send bare `\n` in inline commands break.
- 7.2.15: listpack payloads are always validated on RDB load and `RESTORE`; `sanitize-dump-payload` is accepted but has no effect. AOF replay no longer applies ACL checks, which fixes silent data loss when the default user is disabled.

## Worth Adopting

- `valkey_version` and `server_name` INFO fields for inventory (`redis_version` stays `7.2.4`).
- The `server` Lua namespace (`server.call(...)`) next to the `redis` namespace; both work.
- `ValkeyModule_` API; modules compiled against the Redis module API still load (7.2.6 fixed a macro bug that crashed some Redis modules, so use 7.2.6 or later with third-party modules).

## Upgrading Into This Series

From Redis OSS 7.2 or older (supported path, https://valkey.io/topics/migration/):

1. Confirm the source is Redis OSS 7.2.x or older (`INFO server` without `server_name:valkey`, `redis_version` 7.2.x or lower). Redis CE 7.4 and later files are not compatible; stop and use a logical migration.
2. Pick a method: copy a fresh RDB after `SAVE` with clients disconnected (downtime equals load time), make Valkey a replica with `REPLICAOF <redis-host> <port>` and promote it (`REPLICAOF NO ONE`), or `MIGRATE ... COPY REPLACE KEYS` for a subset. For Redis Cluster, add Valkey nodes as replicas (`--cluster add-node ... --cluster-replica`), `CLUSTER FAILOVER` on each, then remove the Redis nodes.
3. If AOF is enabled in the Valkey config, disable it for the first start from a copied RDB; otherwise Valkey loads the (empty) AOF and ignores the RDB.
4. Compare `INFO keyspace` key counts on both sides before switching clients.
5. Keep the Redis config file: Valkey accepts Redis 7.2 directives. Check monitoring that keys on `redis_version` or the `redis` process name.

Behavior differences from Redis OSS 7.1/7.0 that AWS lists for the move to Valkey 7.2 (they come from Redis 7.2 itself): time is frozen during command and script execution; blocked stream commands released because the key vanished return `-NOGROUP` or `-WRONGTYPE` instead of `-UNBLOCKED`; client-side tracking for scripts tracks keys the script reads, not the declared keys.

## Managed Service Notes

- ElastiCache offers "7.2.6 for Valkey" (released 2024-10-10) on node-based and serverless caches. It is the only Valkey version ElastiCache can roll back to Redis OSS (target 7.1).
- MemoryDB offers "7.2.6" for Valkey (released 2024-10-08).
