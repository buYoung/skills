# Valkey 8.0

Checked: 2026-11-27. Read this when the server reports `valkey_version:8.0.x`, or when moving from 7.2 (or Redis OSS 7.2) to 8.x.

## Lifecycle

- First release 2024-09-15. Maintenance and security support both end 2027-09-15; there is no extended security period (https://valkey.io/topics/releases/).
- Latest patch on 2026-11-27: 8.0.13 (2026-11-18, security).
- 8.0.8 is revoked. Never install it; go from 8.0.7 to 8.0.9 or later.
- RDB version 11. Files stay compatible with 7.2 and Redis OSS 7.2.

## Changed Defaults

| Setting | 7.2 | 8.0 | Source |
| --- | --- | --- | --- |
| `repl-backlog-size` | 1 MB | 10 MB | 8.0.0-rc2 release notes (#911); images |
| `lazyfree-lazy-eviction`, `lazyfree-lazy-expire`, `lazyfree-lazy-server-del`, `lazyfree-lazy-user-del`, `lazyfree-lazy-user-flush`, `replica-lazy-flush` | `no` | `yes` | 8.0 `valkey.conf`; images. Not listed in the 8.0 release notes. |
| `hide-user-data-from-log` | absent | `yes` | 8.0 `valkey.conf`; images |
| `pidfile` default name | `redis.pid` | `valkey.pid` | 8.0.0-rc1 notes |
| `syslog-ident` | `redis` | `valkey` | 8.0.0-rc1 notes |
| INFO field | `redis_mode` | `server_mode` | images |

Consequences: `DEL` of a large key now frees memory in a background thread (like `UNLINK`), so `used_memory` drops after a delay and `lazyfree_pending_objects` can be non-zero; with `hide-user-data-from-log yes`, crash and assertion logs no longer show keys or values, so set it to `no` temporarily if you need them for a bug report.

## Removed or Deprecated

- Error replies no longer contain "Redis". Applications or tests that match error text containing "Redis" break.
- `redis-trib` removed (use `valkey-cli --cluster`).
- Sentinel: `master-reboot-down-after-period` replaced by `primary-reboot-down-after-period` in `sentinel.conf`.
- `CLUSTER SLOTS` is un-deprecated.

Behavior changes that can break applications (8.0.0-rc1/rc2 notes, also listed by AWS):

- A nested `MULTI` or a `WATCH` inside `MULTI` now aborts the transaction.
- `SCAN` no longer returns keys that are logically expired, and errors on invalid `TYPE`.
- `BITCOUNT` and `BITPOS` return errors for invalid arguments on missing keys instead of 0.
- Empty values for `dir`, `dbfilename`, `cluster-config-file` are rejected.
- In disk-based replication, a replica flushes its old data only after validating the received RDB.
- 8.0.0-rc2 blocked unsubscribe commands from clients not in subscribed mode; 8.0.2 reverted that.

## Worth Adopting

- Asynchronous I/O threads (`io-threads N`, default 1). Reads, parsing, writes and polling move off the main thread; commands still execute on the main thread. Enable when the main thread is CPU-bound on network work; see [memory-and-configuration.md](../memory-and-configuration.md).
- Dual-channel full sync (`dual-channel-replication-enabled yes` on primary and replica, needs `repl-diskless-sync yes`): the RDB streams over a second connection and the replica, not the primary, buffers the backlog during sync. Size replica memory for it.
- `CLUSTER SLOT-STATS` per-slot key count, CPU and network bytes (enable `cluster-slot-stats-enabled` for CPU and network counters; key counts need no config, checked on the 9.0 and 9.2 images).
- Per-client `tot-net-in`, `tot-net-out`, `tot-cmds` in `CLIENT LIST`/`CLIENT INFO`.
- Memory: the key is embedded in the main dictionary entry; AWS reports up to 20% more data per node without application change.
- `availability-zone` config, returned in `INFO` (and in `HELLO` from 8.1).
- `CLIENT KILL MAXAGE`, `HSCAN ... NOVALUES`, `ZSCAN ... NOSCORES`, `SCRIPT SHOW`.
- Standalone replicas can redirect writes to the primary for clients that support it (`-REDIRECT`).

## Upgrading Into This Series

From 7.2 (or Redis OSS 7.2):

1. Search application code and tests for error-string matches containing "Redis", nested `MULTI`/`WATCH`, and reliance on `SCAN` returning expired keys.
2. If you depend on synchronous `DEL` freeing memory immediately (for example to stay under `maxmemory` in a tight loop), set `lazyfree-lazy-user-del no` explicitly; otherwise accept the new default.
3. Review `repl-backlog-size`: an explicit 1 MB in an old config file keeps the old value. Size it to cover write volume during the longest expected replica disconnect.
4. Update Sentinel configs that use `master-reboot-down-after-period`.
5. Upgrade replicas first, fail over, upgrade the old primary.

Rollback: 8.0 writes RDB 11, so 7.2 and Redis OSS 7.2 can load its files as long as no 8.0-only data is involved; 8.0 introduced no new data type.

## Managed Service Notes

- ElastiCache "8.0 for Valkey": the ElastiCache `valkey8` parameter family changed `repl-backlog-size` to 10485760 and `maxmemory-samples` to default 3 (self-hosted default 5), added `extended-redis-compatibility` with default `yes` (self-hosted default `no`), and removed the `lazyfree-*` and `replica-lazy-flush` parameters from the parameter group. Valkey 8 parameter groups are incompatible with Redis OSS 7.2.4 groups.
- ElastiCache Serverless for Valkey 8.0 is documented as scaling request rate faster than earlier engines; MemoryDB does not list an 8.x Valkey engine on 2026-11-27.
