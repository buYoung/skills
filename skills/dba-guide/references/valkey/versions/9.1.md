# Valkey 9.1

Checked: 2026-11-27. Read this when the server reports `valkey_version:9.1.x`, or when moving from 9.0.

## Lifecycle

- First release 2026-05-19. Maintenance support ends 2029-05-19; security support ends 2031-05-19 (https://valkey.io/topics/releases/). The table already lists the 5-year security window for 9.1.
- Latest patch on 2026-11-27: 9.1.4 (2026-11-18, security).
- RDB version 80, the same as 9.0.

## Changed Defaults

- The hardware clock is enabled by default (9.1.0-rc1, #3103). On arm64 the official 9.1 image reports `monotonic_clock:ARM CNTVCT @ 24 ticks/us`; 9.0 reports `POSIX clock_gettime`. 9.1.2 fixed a frozen monotonic clock on hosts with unsynchronized TSC, and 9.1.3 stopped using raw TSC when the kernel clocksource is not `tsc`; run 9.1.3 or later on virtual machines.
- The Lua engine is a module, statically linked by default (rc1 #2858, rc2 #3392). `MODULE LIST` now returns `lua`, and `INFO` has a `# Scripting Engines` section. Monitoring that alerts on "any module loaded" needs an exception.
- Embedded string threshold raised from 64 to 128 bytes (rc2, #3397): more small strings stored inline, lower memory and higher `GET` throughput.
- Failing to save the cluster config file no longer exits the process (rc1, #1032). Watch logs for save failures instead of relying on a crash.
- New: `hash-seed` (empty default; immutable) for a stable `SCAN` order across nodes and restarts; `tls-auto-reload-interval` (0 = off); `cluster-config-save-behavior` (default `sync`); `log-format json`.
- Strict TLS certificate validation at config load was added in rc1 and reverted in rc2; the project deferred it to the next major.

## Removed or Deprecated

- `CLUSTER SHARDS` and `CLUSTER SLOTS` replies gain an `availability-zone` field per node. AWS notes that clients that parse these replies strictly (older go-redis) can reject them; upgrade such clients first.
- 9.1.1: the implicit `alldbs` ACL rule is omitted from `ACL LIST`, `ACL SAVE` and `CONFIG REWRITE` so older versions can parse the output.
- 9.1.2: `MOVE` and `COPY` check access to the current database; `HGETEX` requires write permission.

## Worth Adopting

- Database-level ACLs: `ACL SETUSER app on >pw ~* +@all db=0,1` restricts which numbered databases a user can `SELECT`; `alldbs` and `resetdbs` manage the list. The 9.2 release notes document the rules (`db=`, `alldbs`, `resetdbs`) in `valkey.conf`. See [security.md](../security.md).
- `HGETDEL`, `MSETEX` (several keys, one expiration), `HSETEX` with `NX`/`XX`, `CLUSTERSCAN` (cluster-wide key scan from one client), `CLUSTER KEYSLOT` in standalone mode.
- Automatic TLS reload (`tls-auto-reload-interval`) and TLS client authentication by SAN URI (`tls-auth-clients-user URI`).
- Observability: cumulative active-time metrics for the main thread (`used_active_time_main_thread` in `INFO cpu`) and I/O threads, TLS certificate expiry fields in `INFO` (`tls_server_cert_expires_in_seconds`, etc.), cluster bus traffic bytes, `rdb_transmitted` replica state, dual-channel buffer memory in `INFO memory`.
- Replicas can reuse the received RDB as AOF preamble after a disk-based full sync, avoiding an immediate AOF rewrite.
- Lock-free I/O thread queues (8 to 17% throughput gain per the notes) and lower rehashing latency spikes.

## Upgrading Into This Series

From 9.0:

1. Use 9.1.3 or later. Earlier 9.1 patches had a listpack encoding incompatibility with 9.0 that caused RDB load and replication failures for entries of certain lengths, which hits exactly the mixed-version window of a rolling upgrade.
2. Check client libraries for strict `CLUSTER SHARDS`/`CLUSTER SLOTS` parsing.
3. Check monitoring and tooling that inspect `MODULE LIST` or the `# Modules` INFO section.
4. On virtual machines, after the upgrade check `INFO server` `monotonic_clock` and confirm expirations and background tasks progress (`expired_keys` increasing on a TTL workload).
5. Before writing `db=` ACL rules, confirm every node runs 9.1; 9.0 nodes do not understand them.

## Managed Service Notes

- ElastiCache "9.1 for Valkey" is available; AWS lists memory reductions for strings under 128 bytes, `HGETDEL`, `MSETEX`, `CLUSTERSCAN`, database-level ACLs, and an ElastiCache-only distributed KV cache feature on `cache.i8ge.48xlarge` nodes. Parameter family `valkey9`.
- MemoryDB lists no 9.1 engine on 2026-11-27.
