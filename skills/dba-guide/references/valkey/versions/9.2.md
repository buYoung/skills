# Valkey 9.2

Checked: 2026-11-27. Read this when the server reports `valkey_version:9.2.x`, or when moving from 9.1 to the latest stable line.

## Lifecycle

- First release 2026-11-19 per the support table and download page; the 9.2 release notes date 9.2.0 GA as 2026-11-18. Maintenance support ends 2029-11-19; security support ends 2031-11-19 (https://valkey.io/topics/releases/).
- Latest patch on 2026-11-27: 9.2.1 (2026-11-25, urgency MODERATE). The download page still shows 9.2.0 as latest; the `valkey/valkey:9.2` image runs 9.2.1.
- Use 9.2.1, not 9.2.0, with TLS: 9.2.0 refused to start or apply TLS config when a loaded certificate (for example an expired root left in a `tls-ca-cert-file` bundle) was outside its validity period.
- RDB version 81 (adds the Path Hash type).

## Changed Defaults

| Item | Before 9.2 | 9.2 |
| --- | --- | --- |
| Large sorted set encoding | `skiplist` | `btree` (B+ tree); `OBJECT ENCODING` reports `btree` |
| Small hash with field TTLs | always `hashtable` | `listpack` while small (image: `listpack`, `MEMORY USAGE` 72 bytes vs 248 on 9.1) |
| Active expiration of keys and hash fields | did not count as a change | increments the dirty counter, so `save` points (and `BGSAVE`) can fire more often |
| `ZRANGEBYSCORE`, `ZREVRANGEBYSCORE`, `ZCOUNT`, `ZRANGESTORE` with a bare `(` or empty bound | treated as 0 | rejected with an error |
| `rdbcompression` and `repl-compression` | coupled during full sync | independent |
| `cluster-announce-ip` | accepted `ip:port` strings | must be a valid IP or hostname |
| Empty `tls-ca-cert-dir` | accepted, handshakes failed later | rejected at startup and `CONFIG SET` |
| `EXEC` in slowlog/commandlog | not recorded as a whole | recorded when total time crosses the threshold |

New settings and defaults (official 9.2 image): `forkless-infrastructure-enabled no`, `forkless-policy require-fork`, `repl-compression no`, `repl-throttling-enabled no`, `maxmemory-scripts 0`, `hotkeys-top-k 0`, `hotkeys-sampling-percentage 1`, `hotkeys-window-seconds 1`, `maxclients-reserved 0`, `priority-subnets ""`, `priority-preemptive-poll-interval-us 2000`, `cluster-replica-priority 0`, `tls-alt-cert-file`/`tls-alt-key-file` empty. The config `bgsave-default-method` from the release candidates was renamed to `forkless-policy` before GA; configs written against an RC must be updated.

## Removed or Deprecated

- Path Hash commands changed during the RC phase: `PHEXISTS` → `PHPATHEXISTS`, `PHLONGEST` removed in favor of `PHPREFIXES`, `PHCARD` → `PHPATHCOUNT`, `PHDELPREFIX` → `PHPATHDEL key path [WITHSUBPATHS]`. Code written against 9.2 RCs breaks on GA.
- The `# Hotkeys` INFO section from the RCs was removed; use `HOTKEYS GET`.
- `forkless_fallbacks_*` counters moved from `INFO stats` to `INFO debug`.

## Worth Adopting

- Forkless snapshots and full syncs: set `forkless-infrastructure-enabled yes` at startup (immutable; 4 extra bytes per key), then `forkless-policy prefer-forkless`. Saves and full syncs run on a background thread instead of `fork()`, removing copy-on-write memory spikes on write-heavy primaries. New INFO persistence fields (`forkless_estimated_seconds_remaining`, save method and progress). Many 9.2.0 and 9.2.1 fixes target forkless code paths; rehearse under production write load before enabling, and keep `require-fork` as the rollback.
- Stream compression: `rdbcompression lz4` or `zstd` for whole-file RDB compression (readable only by 9.2+), `repl-compression lz4|zstd` for steady-state replication (negotiated per replica; older replicas get plaintext).
- ACL roles: `ACL SETROLE`, `ACL DELROLE`, `ACL GETROLE`, `ACL ROLES`, assigned with the `role=<name>` user rule (the 9.2.0 GA notes write `role:<name>`, which the 9.2.1 image rejects as a syntax error); `ACL DIGEST` to verify what `ACL LOAD` applied.
- `maxmemory-scripts` (absolute or percent of `maxmemory`) caps memory of cached `EVAL` scripts; `SCRIPT LOAD` now respects `maxmemory` (DENYOOM).
- Server-side hot key detection: `CONFIG SET hotkeys-top-k 20`, then `HOTKEYS GET`, `HOTKEYS RESET`.
- `repl-throttling-enabled yes`: slows client writes when a replica falls behind instead of disconnecting it and forcing a full sync.
- Admin connection reservation: `priority-subnets "10.0.0.0/8"` plus `maxclients-reserved 128` keeps 128 of `maxclients` for those subnets.
- Conditional writes: `DELEX key IFEQ|IFNE value`, `SET ... IFNE`, `EXEC` with `IFEQ`/`IFNE`/`NX`/`XX` conditions (optimistic locking without `WATCH`), `INCREX` (increment and set expiry atomically, with `LBOUND`/`UBOUND`/`SATURATE`/`ENX`/`PERSIST`), `MOVE ... REPLACE`, `SISMEMBER ... XX`, `ZRANGE ... XX`. `EXEC` conditions follow the command: `EXEC IFEQ key value`, `IFNE key value`, `NX key`, `XX key`, several allowed; when one fails `EXEC` returns nil and runs nothing.
- Streams: `XACKDEL`, `XDELEX` with `KEEPREF`/`DELREF`/`ACKED`.
- Path Hash data type (`PH*` commands) for longest-prefix and path lookups.
- `CONFIG INFO` (type, flags, enum values, ranges per config), `tls-alt-cert-file` (second certificate, e.g. post-quantum next to RSA), `cluster-replica-priority`, `cluster-replica-no-failover if-empty`, `CLUSTER MIGRATESLOTS ... AUTH user pass`, `last_successful_sync_duration_ms` in `INFO replication`, p99.9 in `valkey-benchmark`.

## Upgrading Into This Series

From 9.1:

1. Go straight to 9.2.1 or later.
2. Search code for sorted-set range queries that pass `(` or an empty string as a bound; they now fail.
3. Tooling that checks `OBJECT ENCODING` for `skiplist` must accept `btree`.
4. If you use RDB `save` points, expect more frequent saves on TTL-heavy workloads; check `rdb_changes_since_last_save` and fork/save frequency after the upgrade.
5. Validate `cluster-announce-ip` values and `tls-ca-cert-dir` before restarting; invalid values now stop the server.
6. Do not enable `rdbcompression lz4|zstd` or Path Hash keys until every node, replica and any restore target run 9.2, and no rollback to 9.1 is planned; 9.1 cannot read those files.
7. Remove any `bgsave-default-method` line from RC-era configs.
