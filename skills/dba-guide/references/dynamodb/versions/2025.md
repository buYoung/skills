# DynamoDB Service Changes in 2025

Checked: 2026-11-27 against https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/DocumentHistory.html

Read this when a design, runbook, or IAM policy dates from before 2025, or when an answer depends on PITR retention, MRSC, throttling diagnostics, or capacity-mode switching. Dates are documentation dates.

## Lifecycle

No release series; changes apply to all tables from their date.

## Changed Defaults

| Date | Change | What to do |
|---|---|---|
| 2025-01-07 | PITR recovery period configurable from 1 to 35 days (`RecoveryPeriodInDays`, default 35). Shortening it does not lower the price, which is based on table plus LSI size. | Keep 35 unless policy requires less; shortening immediately discards recovery points outside the new window. |
| 2025-08-12 | Provisioned-to-on-demand switches raised from once per 24 hours to four times per rolling 24 hours. On-demand to provisioned remains allowed at any time. | Bulk-load runbooks can switch to on-demand for a load and back the same day. |
| 2025-02-24 | NoSQL Workbench creates tables with default settings in on-demand mode. The capacity mode page calls on-demand the default and recommended mode. | Expect on-demand for tables made with console or NoSQL Workbench defaults. CloudFormation `AWS::DynamoDB::Table` still defaults `BillingMode` to `PROVISIONED`, and the CreateTable reference states no default. Read the actual mode from `describe-table` (`BillingModeSummary`). |
| 2025-12-20 | Documentation states all sizes are binary units (1 KB = 1024 bytes). | Use 1024-byte KB in item-size and capacity math. |

## Removed or Deprecated

| Date | Item | Replacement |
|---|---|---|
| 2025-04-25 (entry 2025-04-28) | `AmazonDynamoDBFullAccess` managed policy deprecated | `AmazonDynamoDBFullAccess_v2`, a scoped-down policy |
| 2025-07-17 | DynamoDB local 2.x becomes legacy when 3.0.0 ships | DynamoDB local 3.x; see [local-3.x](local-3.x.md) |

## Worth Adopting

| Date | Feature | Decision it changes |
|---|---|---|
| 2025-06-30 | MRSC global tables with an optional witness: exactly three Regions (three replicas, or two replicas plus a witness), RPO zero, strongly consistent reads in every replica. First documented 2024-12-03. | Choose MRSC over MREC when a multi-Region RPO of zero and cross-Region strong reads are required and the limits (no TTL, no LSI, no transactions, empty table at creation) are acceptable. See [global-tables-and-streams](../global-tables-and-streams.md). |
| 2025-08-14 | Throttling diagnostics: `ThrottlingReasons` in exceptions (`<Table|Index><Read|Write><LimitType>` plus resource ARN), 16 targeted CloudWatch metrics, and the Contributor Insights *throttled keys* mode. | Diagnose by reason code first; keep throttled-keys mode on permanently at low cost. See [capacity-and-performance](../capacity-and-performance.md). |
| 2025-12-12 | Contributor Insights graphs for partition plus sort key pairs; `dynamodb:FirstPartitionKeyValues` condition key. | Item-level hot-key evidence on tables with sort keys. |
| 2025-12-17 | GSI build monitoring: `OnlineIndexConsumedWriteCapacity` and `OnlineIndexThrottleEvents` show 0 during backfill; watch `OnlineIndexPercentageProgress` and the base table's `WriteThrottleEvents` instead. | Update dashboards that relied on the old metrics. |
| 2025-07-17 | Streams shard discovery with `ShardFilter` on `DescribeStream`. | Custom consumers find child shards without listing the whole stream. |
| 2025-06-11 | Streams Kinesis adapter for KCL 2.x and later with SDK v2 (migration guide to KCL 3.x). | Plan the migration off the KCL 1.x adapter. |
| 2025-10-03 | IPv6 for tables, streams, and DAX, including PrivateLink gateway and interface endpoints. | Dual-stack VPC designs. |
| 2025-03-26 | PrivateLink interface endpoints for DynamoDB Streams. | Private connectivity for stream consumers. |
| 2025-05-19 | DynamoDB local runs in AWS CloudShell (`dynamodb-local` alias). | Quick tests without Docker. |

## Upgrading Into This Series

- Replace `AmazonDynamoDBFullAccess` attachments with `AmazonDynamoDBFullAccess_v2` and test that automation still has the actions it needs.
- If a runbook assumes one provisioned-to-on-demand switch per day, update it.
- If a backup policy states "35 days of PITR", check `RecoveryPeriodInDays` on each table; it may have been shortened.
- Update throttling alarms to the specific `*ThrottleEvents` metrics; the aggregate `ReadThrottleEvents`, `WriteThrottleEvents`, and `ThrottledRequests` remain.
