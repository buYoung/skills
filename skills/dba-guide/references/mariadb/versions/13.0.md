# MariaDB 13.0

Checked: 2026-11-27. Read this when the server reports `13.0.x` or when deciding whether to run a rolling release instead of 12.3 LTS.

## Lifecycle

- Rolling release, an evolution of 12.3. 13.0.2 GA on 2026-09-15 (preview March 2026, then RC).
- Community end of life: Q4 2026 per the Foundation table. Rolling releases get no further patch releases after GA except emergency fixes; the supported move is to 13.1.
- Not offered on Amazon RDS (RDS lists 12.3 as the newest major).
- Official image tested: 13.0.2 (`13.0.2-MariaDB-ubu2604`).

## Changed Defaults

| Variable or behavior | 12.3 | 13.0 | Source |
| --- | --- | --- | --- |
| `binlog_row_event_max_size` | 8192 | 65536 | MDEV-37608; 13.0.2 image shows 65536, 12.3.3 image shows 8192 |
| `CREATE OR REPLACE TABLE` | not atomic | atomic | MDEV-25292 |
| `CHANGE MASTER` | keeps `Master_Server_Id` | resets `Master_Server_Id` in `SHOW SLAVE STATUS` | MDEV-15327 |
| Performance Schema digest hash | MD5 | XXH3_128 (FIPS-friendly) | MDEV-31669 |
| `default_master_connection` | session only | global scope too | MDEV-9247 |
| `init_rpl_role` | option only | visible as a variable (13.0.1) | MDEV-38202 |

The image also reports `binlog_format=ROW` and `innodb_autoinc_lock_mode=2`, the same as 12.3.3. The compiled defaults are still `MIXED` and `1`; both values come from the Galera package's `60-galera.cnf` (see the note in [12.3](12.3.md#changed-defaults)).

## Removed or Deprecated

Nothing removed is listed in the 13.0 notes. `information_schema.SYSTEM_VARIABLES` gains `IS_DEPRECATED` and `DEPRECATED_REPLACEMENT`; query them before each rolling upgrade.

## Worth Adopting

- `innodb_log_archive=ON`: the redo log becomes a sequence of `ib_<lsn>.log` files instead of the ring buffer, enabling InnoDB-level point-in-time recovery and incremental backup. Restrictions: `mariadb-backup` fails against a server with it enabled; the server refuses to start if `ib_logfile0` exists; encryption settings are frozen while it is on; it covers InnoDB only (no `.frm` or non-InnoDB metadata). Turning it off and restarting discards the archived history. Do not rely on it as the production backup method until a shipped tool supports the format.
- `UPDATE ... RETURNING` (single-table) with `OLD_VALUE()` returns pre- and post-update values in one round trip.
- `QB_NAME()` implicit query block names for views, CTEs and derived tables, and the path form `QB_NAME(name, path)`, so hints can target objects inside them.
- Audit plugin timestamp format option.
- Optimizer trace includes the statistics used.

## Upgrading Into This Series

From 12.3:

- Moving from LTS to rolling commits you to quarterly upgrades (13.0 → 13.1 → ...); returning to 12.3 requires restoring a pre-upgrade backup or a logical reload.
- 13.0 adds reversed executable comments (MDEV-7381), a new executable-comment form; test dump files and migration scripts that contain `/*! ... */` or `/*M! ... */` comments on 13.0 before switching (exact syntax: see the "Comment Syntax" page linked from the 13.0 notes).
- Tools that read `Master_Server_Id` after `CHANGE MASTER` see it reset.
