# MariaDB 10.6

Checked: 2026-11-27. Read this when the server reports `10.6.x` and you are planning its upgrade, or when a behavior differs between 10.6 and a newer LTS.

## Lifecycle

- LTS, first GA 2021-07-06. Community support ended 2026-07-06; Enterprise support to 2028-08-23, Extended to 2029-08-23 (MariaDB plc subscriptions).
- Last community release listed: 10.6.28 (2026-08-13).
- Amazon RDS for MariaDB: 10.6 end of standard support 2026-12-31; RDS Extended Support does not cover MariaDB. Plan the RDS major upgrade before that date.
- Action: upgrade. Target 10.11 only if you need the shortest step; otherwise go to 11.8 or 12.3 and read every intermediate note.

## Changed Defaults

Observed in the official `mariadb:10.6` image (10.6.28) compared with newer series:

| Variable | 10.6 | Later change |
| --- | --- | --- |
| `explicit_defaults_for_timestamp` | `OFF` | `ON` from 10.10 (so in 10.11) |
| `innodb_undo_tablespaces` | `0` (undo in system tablespace) | `3` from 11.0 |
| `innodb_snapshot_isolation` | `OFF` (variable added in 10.6.18) | `ON` from 11.6.2 (so in 11.8) |
| `histogram_type` | `DOUBLE_PREC_HB` | `JSON_HB` in the 11.4 image; 10.11 image still `DOUBLE_PREC_HB` |
| `collation_server` | `utf8mb4_general_ci` (image config) | `utf8mb4_uca1400_ai_ci` default from 11.5 |
| `innodb_change_buffering` | `none` (since 10.6.7) | variable removed in 11.0 |
| `have_ssl` | `DISABLED` without certificates | server auto-generates a certificate from 11.4 |
| `transaction_isolation` | not a system variable; use `tx_isolation` | system variable from 11.1 |
| `innodb_purge_batch_size` | `127` (since 10.6.20) | same |

Defaults introduced in 10.6 itself: `utf8` means `utf8mb3` (`old_mode` contains `UTF8_IS_UTF8MB3`); `innodb_flush_method=O_DIRECT` on Unix; `max_recursive_iterations=1000`; `innodb_read_only_compressed=OFF` from 10.6.6.

## Removed or Deprecated

- Removed in 10.6: TokuDB and CassandraSE engines; `SYS_DATAFILES`; the `innodb` and `none` checksum algorithms; many InnoDB variables (`innodb_buffer_pool_instances`, `innodb_file_format`, `innodb_large_prefix`, `innodb_log_files_in_group`, `innodb_page_cleaners`, `innodb_thread_concurrency`, `innodb_undo_logs`, and others). A `my.cnf` carried from 10.5 that sets them prevents startup.
- `innodb_force_load_corrupted` removed in 10.6.6.

## Worth Adopting

These exist on 10.6 and stay in later series:

- Atomic DDL: `CREATE`, `ALTER`, `RENAME`, `DROP TABLE` and `DROP DATABASE` are crash-safe; a multi-table `DROP TABLE` is atomic per table only.
- `SELECT ... FOR UPDATE SKIP LOCKED` (InnoDB) and `NOWAIT` for queue tables.
- `JSON_TABLE()`, `OFFSET ... FETCH`, ignored indexes (`CREATE INDEX ... IGNORED`, `ALTER TABLE t ALTER INDEX i IGNORED`) to test index removal without dropping.
- Bundled `sys` schema.

## Upgrading Into This Series

Not a target; it is no longer supported.

Upgrading out of 10.6 (to 10.11):

- Remove `innodb_version`, `wsrep_replicate_myisam`, `wsrep_strict_ddl` from option files (`wsrep_mode` replaces the last two). Keep `innodb_log_write_ahead_size` only when the target is 10.11.9 or later; 10.11.0-10.11.8 do not have it.
- `innodb_buffer_pool_chunk_size` becomes autosized.
- Tables compressed with a non-zlib InnoDB or Mroonga algorithm are unreadable until the matching compression provider plugin is installed.
- `explicit_defaults_for_timestamp` flips to `ON` in 10.11: a new `TIMESTAMP` column without `DEFAULT` no longer gets automatic `CURRENT_TIMESTAMP` and `ON UPDATE` behavior. Compare `SHOW CREATE TABLE` for tables created by migrations after the upgrade.
- 10.6 cannot read redo logs from newer versions; keep the pre-upgrade physical backup until the new version is accepted.

## Managed Service Notes

RDS for MariaDB offers 10.6.20-10.6.28 with end of standard support between November and December 2026. RDS 10.6.20 reverted two community changes that broke point-in-time recovery (MDEV-35528).
