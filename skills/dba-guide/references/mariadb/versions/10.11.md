# MariaDB 10.11

Checked: 2026-11-27. Read this when the server reports `10.11.x`, when upgrading from 10.6, or when planning the move from 10.11 to an 11.x or 12.x LTS.

## Lifecycle

- LTS, first GA 2023-02-16. Community, Enterprise and Extended support all end 2028-02-16.
- Latest community release on the check date: 10.11.20. The official image tested was 10.11.19.
- Contains the features of the short-term releases 10.7, 10.8, 10.9 and 10.10.
- Amazon RDS: 10.11 standard support until February 2028.

## Changed Defaults

Relative to 10.6:

| Variable or behavior | 10.6 | 10.11 | Source |
| --- | --- | --- | --- |
| `explicit_defaults_for_timestamp` | `OFF` | `ON` | 10.10 (MDEV-28632); image confirms |
| `CHANGE MASTER TO` without position | file/position | `MASTER_USE_GTID=slave_pos` when the primary supports GTID | 10.10 (MDEV-19801) |
| `mariadb` client `--ssl` | off | on by default | 10.10 (MDEV-27105) |
| `innodb_buffer_pool_chunk_size` | 128 MiB | autosized; deprecated and ignored from 10.11.12 | upgrade note, InnoDB variable docs |
| `innodb_buffer_pool_size_max` | n/a | added in 10.11.12; default 8 TiB of reserved address space on 64-bit from 10.11.17 | InnoDB variable docs; image shows `8796093022208` |
| `innodb_read_io_threads`, `innodb_write_io_threads` | static | dynamic | 10.11 notes |
| `innodb_snapshot_isolation` | `OFF` (from 10.6.18) | `OFF` (from 10.11.8) | image confirms |

Slow log variables gained new names in 10.11 (old names remain): `log_slow_query` (`slow_query_log`), `log_slow_query_file`, `log_slow_query_time` (`long_query_time`), `log_slow_min_examined_row_limit`.

## Removed or Deprecated

- Removed: `innodb_version`, `wsrep_replicate_myisam` and `wsrep_strict_ddl` (use `wsrep_mode`). `innodb_log_write_ahead_size` was removed in 10.8 and reintroduced in 10.11.9 (InnoDB variable docs; present as 512 in the 10.11.19 image), so on current 10.11 patches it can stay in option files.
- Deprecated: `innodb_change_buffering` (ignored from 10.9, removed in 11.0), `keep_files_on_create`, `innodb_prefix_index_cluster_optimization`, the `old` variable (merged into `old_mode`), `MASTER_USE_GTID=current_pos` (use `MASTER_DEMOTE_TO_SLAVE`), `DES_ENCRYPT`/`DES_DECRYPT`.

## Worth Adopting

- GTID replication by default and `CHANGE MASTER TO MASTER_DEMOTE_TO_SLAVE=1` for turning an old primary into a replica after failover.
- `binlog_alter_two_phase=ON` (from 10.8): long `ALTER TABLE` starts on replicas when it starts on the primary, removing the lag spike from big DDL.
- `UUID` and `INET4` data types; descending index key parts.
- JSON histograms (`histogram_type=JSON_HB`, available from 10.8; the 10.11 default is still `DOUBLE_PREC_HB`) for skewed columns, collected with `ANALYZE TABLE ... PERSISTENT FOR ...`.
- `SHOW ANALYZE [FORMAT=JSON] FOR <thread_id>` to see the live plan and counters of a running statement.
- `GRANT ... TO PUBLIC`, separate `READ_ONLY ADMIN` privilege, `password_reuse_check` plugin.
- `mariadb-dump --dump-history` and `system_versioning_insert_history` for moving system-versioned tables with their history.
- `ALTER TABLE ... CONVERT PARTITION ... TO TABLE` and `CONVERT TABLE ... TO PARTITION`.
- Hashicorp Vault key management plugin for data-at-rest encryption.

## Upgrading Into This Series

From 10.6, see [10.6](10.6.md#upgrading-into-this-series) for the option removals. Additional checks:

- Applications that create tables with bare `TIMESTAMP` columns: behavior changes with `explicit_defaults_for_timestamp=ON`.
- Replication setup scripts that run `CHANGE MASTER TO MASTER_HOST=...` without a position now get GTID mode; scripts that relied on file/position must set `MASTER_USE_GTID=no` explicitly.
- `innodb_buffer_pool_chunk_size` in option files is now ignored (from 10.11.12); remove it.

Upgrading out of 10.11 (to 11.4): the optimizer cost model changes (see [11.4](11.4.md#upgrading-into-this-series)). Rehearse with production-like data and compare plans.
