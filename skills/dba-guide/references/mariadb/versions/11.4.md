# MariaDB 11.4

Checked: 2026-11-27. Read this when the server reports `11.4.x`, when upgrading from 10.11, or when a query plan changed after leaving 10.x.

## Lifecycle

- LTS, first GA 2024-05-29 (Foundation table). Community support to 2029-05-29 (the last LTS with 5-year community binaries), Enterprise to 2030-01-16, Extended to 2033-01-16.
- Latest community release on the check date: 11.4.14. The official image tested was 11.4.13.
- Contains the features of 11.0, 11.1, 11.2 (short-term) and 11.3 (rolling).
- Amazon RDS: standard support until May 2029. The RDS calendar lists the 11.4 "community release date" as 2024-08-08, which does not match the Foundation GA date.

## Changed Defaults

| Variable or behavior | 10.11 | 11.4 | Source |
| --- | --- | --- | --- |
| Optimizer cost model | rule-adjusted, unitless | cost in time units, per-engine costs | 11.0 cost model page |
| `optimizer_switch` | — | several flags changed (see upgrade note) | upgrade note |
| `innodb_purge_batch_size` | 127 from 10.11.10 (older patches: 300 or 1000) | 127 from 11.4.4 | InnoDB variable docs; a patch-level change, not a 10.11 to 11.4 difference |
| `innodb_undo_tablespaces` | `0` | `3` (from 11.0) | InnoDB variable docs |
| Server TLS | off without certificates | on: a self-signed certificate is generated if none is configured | MDEV-31856; image shows `have_ssl=YES` |
| Client TLS | `--ssl` | clients require TLS and verify the server certificate by default; replication sets `MASTER_SSL_VERIFY_SERVER_CERT` by default | MDEV-31857 |
| `transaction_isolation` | option only | system variable; `tx_isolation` deprecated | 11.1 (MDEV-21921) |
| `histogram_type` | `DOUBLE_PREC_HB` | `JSON_HB` (observed in image) | container |
| `binlog_gtid_index` | n/a | `ON` | 11.4 |
| `innodb_snapshot_isolation` | `OFF` | `OFF` (variable from 11.4.2) | image confirms |
| `ALTER TABLE` default | COPY blocks writes | COPY runs with `LOCK=NONE` when possible (11.2) | 11.4 notes |

The official 11.4 image reports `collation_server=utf8mb4_uca1400_ai_ci`, although the release notes date the uca1400 default to 11.5. This comes from package configuration: the image's `/etc/mysql/mariadb.conf.d/50-server.cnf` sets `character-set-server = utf8mb4` and `character-set-collations = utf8mb4=uca1400_ai_ci`. The compiled defaults in 11.4.13 (`mariadbd --no-defaults --verbose --help`) are `latin1`, `latin1_swedish_ci`, and an empty `character-set-collations`. `GLOBAL_VALUE_ORIGIN` still reports `COMPILE-TIME` for `collation_server` and `character_set_server`, so check `my_print_defaults --mysqld` on the server rather than the origin column.

## Removed or Deprecated

Remove from option files before starting 11.4:

- `innodb_defragment` and all `innodb_defragment_*` variables (11.1), `debug_no_thread_alarm`, `old_alter_table` (use `alter_algorithm`), `innodb_change_buffering` and `innodb_change_buffer_max_size` (change buffer removed in 11.0), `date_format`, `datetime_format`, `time_format`, `max_tmp_tables`, `wsrep_causal_reads`.
- `engine_condition_pushdown` removed from `optimizer_switch`.

Deprecated: `innodb_purge_rseg_truncate_frequency` (ignored), `tx_isolation`, `tx_read_only`, `innodb_flush_method` (11.0; replaced by `innodb_log_file_buffering`, `innodb_data_file_buffering`, `innodb_log_file_write_through`, `innodb_data_file_write_through`), `mariadb-backup --innobackupex` mode, `innodb_file_per_table` (11.0.1).

## Worth Adopting

- Online `ALTER TABLE ... ALGORITHM=COPY, LOCK=NONE` for most changes that cannot be instant or in place; writes continue during the copy. Rehearse on a copy to measure duration and disk use.
- Binlog GTID index (`binlog_gtid_index=ON`): fast replica reconnects on large binlogs.
- `max_binlog_total_size` (alias `binlog_space_limit`) and `slave_connections_needed_for_purge` for size-based binlog retention.
- `binlog_row_image=FULL_NODUP`: smaller row events with full before-images.
- Sargable `DATE(col)`, `YEAR(col)` (11.1) and `UPPER(col)` with case-insensitive collations (`sargable_casefold=on`, 11.3): existing indexes start to serve these predicates.
- Semi-join strategies for single-table `UPDATE`/`DELETE` with subqueries.
- `innodb_truncate_temporary_tablespace_now` to shrink `ibtmp1` without restart; the system tablespace reclaims unused space at startup.
- `SHOW CREATE ROUTINE` privilege; `sys.privileges_by_table_by_level`.
- `mariadb-dump --parallel` with `--tab`.
- 44 MySQL collation aliases from 11.4.5 (help replication from MySQL).

## Upgrading Into This Series

From 10.11:

- Plans change. The cost model now measures cost in time units with engine-specific constants and removed hard-coded heuristics (the 10% rows rule for key lookups, InnoDB's 50% range cap). Rehearse: capture `EXPLAIN FORMAT=JSON` of the top queries on 10.11, replay on the upgraded copy, compare access types and `rows`. Remove `FORCE INDEX` hints only after verifying the new plan.
- Clients from 11.4 on require TLS and verify the server certificate. Verification of the server's auto-generated self-signed certificate succeeds only for accounts with a non-empty password using `mysql_native_password` or `ed25519` (on 11.6 and later, `parsec` too). Accounts without a password, or with other plugins, need a CA-signed certificate distributed to clients, `--ssl-fp`/`--ssl-fplist`, or `--disable-ssl-verify-server-cert`. Check replica `CHANGE MASTER` settings for `MASTER_SSL_VERIFY_SERVER_CERT`.
- Remove the options listed under Removed.
- `innodb_flush_method` still works but is deprecated; leave it or translate it to the four boolean variables.
- Replicas: an 11.4 replica can replicate from a 10.11 primary; not the reverse.
- From 11.4.11, an 11.x server can start on 10.x data files with `innodb_force_recovery=6` for emergency logical extraction only; it is not an upgrade path.

## Managed Service Notes

RDS offers 11.4.4-11.4.13. RDS 11.4.4 reverted two community changes that broke PITR (MDEV-35528). On RDS, `SHOW CREATE ROUTINE` is in the master user's privileges only on 11.4 and later, and `simple_password_check` and `cracklib_password_check` are available only from 11.4.
