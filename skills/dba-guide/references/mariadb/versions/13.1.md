# MariaDB 13.1

Checked: 2026-11-27. Read this when the server reports `13.1.x`, when moving from 13.0, or before restoring a dump taken on 13.1 into an older server.

## Lifecycle

- Rolling release, an evolution of 13.0. 13.1.2 GA on 2026-11-23. It is the current rolling release on the check date; 13.2 is in development.
- Community end of life: Q1 2027 per the Foundation table.
- Not offered on Amazon RDS.
- Docker Hub had no GA 13.1 image on the check date (only `13.1-rc`, 13.1.1), so no 13.1 image was run; defaults below come from the release notes only.

## Changed Defaults

| Variable or behavior | 13.0 | 13.1 | Source |
| --- | --- | --- | --- |
| `utf8` alias | `utf8mb3` (`old_mode` contains `UTF8_IS_UTF8MB3`) | `utf8mb4` (`UTF8_IS_UTF8MB3` removed from default `old_mode`) | MDEV-30041 |
| `mariadb-dump` generated columns | values dumped | written as `DEFAULT`; with `--complete-insert` left out of column list and values | MDEV-32362 |
| `mariadb-dump` DEFINER | wrapped in `/*!50017 ... */` | written plainly; no version comments for versions older than MySQL 5.7 | MDEV-30295 |
| `SHOW CREATE DATABASE` | `IF NOT EXISTS`, charset in comments | not wrapped in comments | MDEV-30295 |
| `innodb_adaptive_hash_index` | boolean | enumeration `OFF`/`ON`/`IF_SPECIFIED` (default `OFF`) | MDEV-37070 |
| `optimizer_record_context` | global and session | session only | MDEV-38701 |

New variables with their defaults: `innodb_table_lock_on_full_scan=OFF`, `innodb_tablespace_size_warning_threshold=0` (off), `innodb_tablespace_size_warning_pct=85`, `log_slow_max_query_length=4294967295`, `parsec_iterations=1024`, `optimizer_replay_context` (empty), `wsrep_sst_tmp_dir` (read-only, empty).

## Removed or Deprecated

None listed in the 13.1 notes.

## Worth Adopting

- `DENY` (negative grants): a deny overrides any grant at the same or lower level, including grants issued later; only `REVOKE DENY` removes it. Use it to carve exceptions out of broad grants (`GRANT SELECT ON *.* TO app; DENY SELECT ON hr.payroll TO app;`). `SHOW GRANTS` shows denies only to users with `SELECT` on the `mysql` database, so audits must run with that privilege.
- JSON `->` and `->>` operators (same meaning as in MySQL), easing application portability.
- `PARTITION BY RANGE COLUMNS ... INTERVAL`: partitions are added automatically as rows arrive; removes the cron job that pre-creates partitions.
- `innodb_table_lock_on_full_scan=ON` (session or global): locking full scans (`UPDATE`/`DELETE`/`SELECT ... FOR UPDATE` without `WHERE` or `LIMIT`, and reads under `SERIALIZABLE`) take one table lock instead of millions of row locks. Blocks all concurrent writers for the duration; use for batch jobs, not OLTP sessions.
- Per-table and per-index `ADAPTIVE_HASH_INDEX = YES|NO|DEFAULT` with `innodb_adaptive_hash_index=IF_SPECIFIED`; AHI counters in `ANALYZE FORMAT=JSON` (`r_ahi_stats`) and `Innodb_adaptive_hash_pages_added`/`_rows_added`.
- Tablespace size warnings in the error log (`innodb_tablespace_size_warning_threshold`).
- Optimizer context record and replay (`optimizer_record_context`, `optimizer_replay_context`) to reproduce a plan on another server.
- `INFORMATION_SCHEMA.VECTOR_INDEXES`; `XXH3()`/`XXH32()`; `parsec_iterations` (applies to passwords set after the change).
- Galera SST for tables with `DATA DIRECTORY` outside the datadir.

## Upgrading Into This Series

From 13.0:

- `utf8` now means `utf8mb4`. DDL that says `CHARACTER SET utf8` creates 4-byte columns: index prefix limits, row size and memory per row grow. The 13.1 notes do not say how a replica older than 13.1, whose `old_mode` still maps `utf8` to `utf8mb3`, applies replicated DDL that says `utf8`; while versions are mixed, write `utf8mb3` or `utf8mb4` explicitly in DDL and compare `SHOW CREATE TABLE` on both sides. To keep the old meaning, add `UTF8_IS_UTF8MB3` to `old_mode` in option files before the upgrade, e.g. `old_mode=UTF8_IS_UTF8MB3` (append to any existing flags).
- Dumps taken with 13.1 `mariadb-dump` differ: generated column values are not written, and DEFINER clauses are not in version comments. Restoring such a dump into an older server that rejects plain DEFINER syntax, or into a table where the column is not generated, behaves differently; rehearse restores to older targets.
- Monitoring that reads `innodb_adaptive_hash_index` as a boolean must accept `IF_SPECIFIED`.
- `log_slow_max_query_length` skips (does not truncate) longer statements in the slow log; leave the default unless the log fills with huge literals.
