# MariaDB 12.3

Checked: 2026-11-27. Read this when the server reports `12.3.x`, when upgrading from 11.8, or when evaluating the InnoDB-based binary log or optimizer hints.

## Lifecycle

- LTS, first GA 2026-05-28 (12.3.2; 12.3.1 was RC on 2026-02-12). Community support to 2029-06-12, Enterprise to 2031-11-03, Extended to 2034-11-03.
- Latest community release on the check date: 12.3.4 (2026-11-16). The official image tested was 12.3.3.
- Contains the features of the rolling releases 12.0, 12.1 and 12.2.
- Amazon RDS: available since 2026-08-07 (12.3.2, 12.3.3), standard support until June 2029.

## Changed Defaults

| Variable or behavior | 11.8 | 12.3 | Source |
| --- | --- | --- | --- |
| Galera package | installed with server packages | from 12.3.2, separate package (`mariadb-server-galera` on Debian/Ubuntu, `MariaDB-server-galera` on RHEL/SLES, depending on `galera-4`); removed from server package dependencies | 12.3.1 notes (MDEV-38744), Galera upgrade guide (MDEV-30953) |
| `DROP USER` with active sessions | silent | warning (error in Oracle mode) | MDEV-35617 |
| Foreign key constraint names | unique per database | unique per table | MDEV-28933 |
| `binlog_format` | `MIXED` | compiled default still `MIXED`; `ROW` where the Galera package's option file is installed (the official 12.3.3 image) | see below |
| `innodb_autoinc_lock_mode` | `1` | compiled default still `1`; `2` where the Galera package's option file is installed (the official 12.3.3 image) | see below |
| `master_use_gtid` after upgrade to 12.3.2 | kept | reset to `DEFAULT` (bug, fixed in 12.3.3, MDEV-39788) | upgrade note |

The 12.3.3 and 13.0.2 images report `binlog_format=ROW` and `innodb_autoinc_lock_mode=2`, while the 11.8.9 and older images report `MIXED` and `1`. The compiled defaults did not change: `mariadbd --no-defaults --verbose --help` prints `MIXED` and `1` on every image from 10.6 to 13.0, matching the variable reference pages. The values come from `/etc/mysql/mariadb.conf.d/60-galera.cnf`, which in 12.3.3 and 13.0.2 belongs to the `mariadb-server-galera` package and sets both lines uncommented in the `[galera]` group even though `wsrep_on` stays commented out. In 11.8.9 the same file belongs to `mariadb-client` and has both lines commented. `information_schema.SYSTEM_VARIABLES` shows `GLOBAL_VALUE_ORIGIN=CONFIG` for both on 12.3.3. Any server with the Galera package installed therefore runs `ROW` and `2` unless another option file overrides them. Check with `my_print_defaults --mysqld` and set both explicitly in your own option file so installing or removing the Galera package cannot change them silently.

## Removed or Deprecated

- Removed system variables: `big_tables`, `large_page_size`, `storage_engine` (use `default_storage_engine`). Remove them from option files; startup fails otherwise.
- New reserved words: `CONVERSION`, `TO_DATE`. Quote or rename identifiers that use them before upgrading.
- Deprecated: the systemd `MYSQLD_OPTS` environment variable; put options in option files.

## Worth Adopting

- InnoDB-based binary log (`binlog_storage_engine=innodb` with a bare `log_bin`): binlog stored in `.ibb` InnoDB-page files, recovered with InnoDB, one fsync per commit at `innodb_flush_log_at_trx_commit=1`, `sync_binlog` not needed, binlog files included consistently in `mariadb-backup`. Restrictions: GTID positioning only (no file/offset, no `MASTER_POS_WAIT()`, `BINLOG_GTID_POS()`, `RESET MASTER TO`), no Galera, no `encrypt_binlog`, no replication of `XA PREPARE`, no semi-sync until 13.2, `--init-rpl-role` unsupported, tools that parse binlog files directly need updates. Not available on RDS. See [replication](../replication-and-ha.md#innodb-based-binary-log-123-and-later).
- Optimizer hints (MySQL-style `/*+ ... */`): `NO_RANGE_OPTIMIZATION`, `NO_ICP`, `[NO_]MRR`, `[NO_]BKA`, `[NO_]BNL`, `[NO_]INDEX`, `[NO_]JOIN_INDEX`, `[NO_]GROUP_INDEX`, `[NO_]ORDER_INDEX`, `[NO_]INDEX_MERGE`, `[NO_]ROWID_FILTER`, `[NO_]SPLIT_MATERIALIZED`, `[NO_]MERGE`, `[NO_]DERIVED_CONDITION_PUSHDOWN`, `SEMIJOIN`, `SUBQUERY`, `JOIN_ORDER`, `JOIN_PREFIX`, `JOIN_SUFFIX`, `JOIN_FIXED_ORDER`, `QB_NAME`, `MAX_EXECUTION_TIME`. Prefer a hint over a global `optimizer_switch` change.
- `caching_sha2_password` authentication plugin for MySQL client compatibility. It is not loaded by default in the 12.3.3 image (`CREATE USER ... IDENTIFIED VIA caching_sha2_password` fails with ERROR 1524 `Plugin 'caching_sha2_password' is not loaded`); load it with `INSTALL SONAME 'auth_mysql_sha2'`. The library `auth_caching_sha2_password` does not exist.
- `SET SESSION AUTHORIZATION` to act as another user; `ssl_passphrase` for encrypted TLS keys.
- `UPDATE`/`DELETE` reading from a CTE; triggers on multiple events; `IS JSON`; JSON depth limit removed.
- Parallel apply for asynchronous replication between Galera clusters (`slave_parallel_threads`); Galera write-set apply retries (`wsrep_applier_retry_count`).
- `create_tmp_table_binlog_formats` makes temporary-table replication predictable; `binlog_row_event_fragment_threshold` fragments huge row events below `slave_max_allowed_packet`.
- `binlog_row_metadata=FULL` maps row events by column name (helps multi-primary schema drift).
- Audit plugin buffered logging (`server_audit_file_buffer_size`); HOST:PORT and TLS version in audit records.
- Segmented Aria page cache (`aria_pagecache_segments`), MDL scalability improvements.
- `mariadb-dump -L/--wildcards`; `CHECK TABLE` on sequences.

## Upgrading Into This Series

From 11.8:

- Remove `big_tables`, `large_page_size`, `storage_engine` from option files.
- Search schemas and stored code for unquoted `CONVERSION` and `TO_DATE`: `SELECT TABLE_SCHEMA, TABLE_NAME, COLUMN_NAME FROM information_schema.COLUMNS WHERE COLUMN_NAME IN ('conversion','to_date');` plus a grep of application SQL.
- Galera nodes: install the Galera package separately before upgrading; follow the Galera rolling-upgrade guide.
- Upgrade directly to 12.3.3 or later; on 12.3.2, re-check `SHOW REPLICA STATUS` `Using_Gtid` after the upgrade and re-run `CHANGE MASTER TO MASTER_USE_GTID=slave_pos` if it reset.
- Pin `binlog_format` and `innodb_autoinc_lock_mode` in option files to the values you run today (see the note above). Moving from `MIXED` to `ROW` increases binlog volume for bulk statements; moving to `autoinc_lock_mode=2` makes `AUTO_INCREMENT` values of concurrent multi-row inserts interleave and is unsafe with statement-based logging.
- InnoDB-based binlog is opt-in. Migrate only after all replicas run 12.3 or later; the three migration methods (restart with empty binlog, GTID-state carry-over, promote a replica) are in [replication](../replication-and-ha.md#innodb-based-binary-log-123-and-later).

## Managed Service Notes

On RDS 12.3: `binlog_storage_engine` is not available, `PATH` cannot be set globally (session only), `show_slave_auth_info` is not available, `rdsproxyadmin` is a reserved user, and `rdsrepladmin` cannot be dropped at any host.
