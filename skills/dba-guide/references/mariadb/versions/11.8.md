# MariaDB 11.8

Checked: 2026-11-27. Read this when the server reports `11.8.x`, when upgrading from 11.4, or when `ERROR 1020 (HY000): Record has changed since last read` starts appearing after an upgrade.

## Lifecycle

- LTS, first GA 2025-06-04 (Foundation table). Community support to 2028-06-04, Enterprise to 2030-10-22, Extended to 2033-10-22.
- Latest community release on the check date: 11.8.10. The official image tested was 11.8.9.
- Contains the features of the rolling releases 11.5, 11.6 and 11.7.
- Amazon RDS: standard support until June 2028. The RDS calendar lists the community release date as 2025-08-06 (differs from the Foundation GA date).

## Removed or Deprecated

- Removed: `wsrep_load_data_splitting` (remove from option files); the old column syntax `<type> <charset clause> COMPRESSED` (write `<type> COMPRESSED <charset clause>`).
- Deprecated: `binlog_optimize_thread_scheduling`, `alter_algorithm`, Spider `spider_table_crd_thread_count`, `spider_table_sts_thread_count`, `spider_casual_read`.

## Worth Adopting

- Vector search: `VECTOR(n)` columns, `VECTOR INDEX` (HNSW), `VEC_DISTANCE_EUCLIDEAN`, `VEC_DISTANCE_COSINE`, `VEC_FromText`. Memory for the index cache is bounded by `mhnsw_max_cache_size` (16 MiB default in the image). Size it before loading embeddings at scale.
- `max_tmp_session_space_usage` and `max_tmp_total_space_usage` cap disk used by temporary files and tables, protecting the data volume from a runaway query.
- PARSEC authentication plugin (11.6) and `unix_socket` with an `authentication_string` mapping (11.6). See [security](../security.md).
- `UUID_v7()` for time-ordered keys that insert at the end of the clustered index.
- Large transactions no longer freeze all other commits while binlogging (11.7, MDEV-32014); `binlog_large_commit_threshold` controls it.
- `slave_abort_blocking_timeout` aborts replica-side queries that block replication.
- `log_slow_always_query_time` logs every query above a time threshold regardless of sampling and row filters.
- `information_schema.USERS` (password expiry, `max_password_errors` state) and `INFORMATION_SCHEMA.SLAVE_STATUS`.
- Parallel `mariadb-dump --dir` and `mariadb-import --dir` for multi-database logical copies.
- `innodb_index_shrink` (from 11.8.9) to trade page density for less index latch contention on record-growing updates.

## Upgrading Into This Series

From 11.4:

- Repeatable Read now detects write conflicts. A transaction that read a snapshot and then updates or deletes rows changed by a concurrent committed transaction fails with `ERROR 1020 (HY000): Record has changed since last read` and is rolled back like a deadlock. Bulk `UPDATE`/`DELETE` under concurrency is affected most. Before upgrading, confirm the application retries transactions on 1020 as it does on 1213. Short-term rollback: `SET GLOBAL innodb_snapshot_isolation=OFF` (dynamic, also session scope) restores the 11.4 behavior while the retry logic is fixed. See [transactions](../transactions-and-locking.md#snapshot-isolation-and-error-1020).
- System-versioned tables: every row and index is rewritten for the extended `TIMESTAMP` range during the upgrade. Time it on a restored copy; with large history tables the upgrade can take hours. Downgrading with system-versioned tables is not trivial.
- Character set defaults: tables created without an explicit charset now get `utf8mb4` and `uca1400_ai_ci`. Older replicas (10.6 and earlier) may not know the collation; the character-set docs describe configuring the primary for older replicas. Pin `character_set_server`, `collation_server` (or `character_set_collations`) in option files if replicas are older.
- Remove `wsrep_load_data_splitting`.
- Vector indexes and new collations cannot be read by 11.4; keep the pre-upgrade backup for rollback.

## Managed Service Notes

RDS offers 11.8.3-11.8.9. From RDS 11.8.3, the RDS parameter `require_secure_transport` defaults to `1` (TLS required). RDS 11.8.9 adds post-quantum hybrid key exchange groups for TLS 1.3 (`SHOW STATUS LIKE 'Ssl_named_group'`).
