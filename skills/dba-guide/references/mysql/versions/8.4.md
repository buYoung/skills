# MySQL 8.4 LTS

Checked: 2026-11-27. Read this when the server reports `8.4.x`, when upgrading from 8.0 to 8.4, or when choosing between 8.4 and 9.7 for a new deployment.

## Lifecycle

- LTS. 8.4.0 GA 2024-04-30. Premier Support to April 2029, Extended Support to April 2032 (Oracle Lifetime Support Policy).
- Latest on 2026-11-27: 8.4.13 (the `mysql:8.4` image reports `version_with_update` 8.4.13.1).
- No features are added or removed within 8.4.x. In-place upgrade and downgrade within 8.4.x are supported, and Group Replication members can run mixed 8.4.x versions.
- Next step: 8.4 -> 9.7 LTS (direct). 8.4 cannot go directly to 26.x.

## Changed Defaults

Against 8.0. Values from the 8.4 What Is New page; "container" means confirmed on the `mysql:8.4` image (8.4.13, 14 logical CPUs, 8 GiB RAM).

| Variable | 8.0 | 8.4 | Decision impact |
|---|---|---|---|
| `innodb_adaptive_hash_index` | ON | OFF (container) | Re-test workloads with many repeated point lookups on hot secondary indexes; enable only if `SHOW ENGINE INNODB STATUS` hash searches/s were high and latch waits low. |
| `innodb_change_buffering` | `all` | `none` (container) | Write-heavy workloads on large secondary indexes that do not fit in memory may see more random reads. 9.5.0 switches back to `all`. |
| `innodb_io_capacity` / `_max` | 200 / 2000 min | 10000 / 20000 (container) | On slow disks the flusher is now aggressive; lower explicitly for HDD or throttled cloud volumes. |
| `innodb_log_buffer_size` | 16 MiB | 64 MiB (container) | |
| `innodb_flush_method` (Linux) | `fsync` | `O_DIRECT` if supported (container) | Page cache no longer double-buffers data files. |
| `innodb_use_fdatasync` | OFF | ON (container) | |
| `innodb_buffer_pool_instances` | 8 (1 if pool < 1 GiB) | 1 if pool <= 1 GiB, else computed from pool size and CPUs | |
| `innodb_parallel_read_threads`, `innodb_read_io_threads`, `innodb_purge_threads`, `innodb_page_cleaners` | fixed | CPU-derived (container: 4, 7, 1, 1) | Defaults move with host size; pin values when comparing hosts. |
| `innodb_doublewrite_files` / `_pages` | instances x 2 / write_io_threads | 2 / 128 (container) | |
| `temptable_max_ram` | 1 GiB | 3% of RAM, clamped to 1-4 GiB | Container shows 1073741824 on 8 GiB. |
| `temptable_max_mmap` / `temptable_use_mmap` | 1 GiB / ON | 0 / OFF (container) | Internal temp tables spill to InnoDB on disk instead of mmap files. |
| `innodb_numa_interleave` | OFF | ON | The variable did not exist on the arm64 image (error 1193); it is present only on NUMA-enabled builds (inference, not documented). |
| `group_replication_consistency` | EVENTUAL | BEFORE_ON_PRIMARY_FAILOVER (container) | New primary refuses reads until it has applied its backlog. |
| `group_replication_exit_state_action` | READ_ONLY | OFFLINE_MODE | An expelled member closes client connections. |
| `SOURCE_RETRY_COUNT` | 86400 (8.0 manual: 60 days at 60 s) | 10 | A replica now stops retrying after about 10 minutes (10 x `SOURCE_CONNECT_RETRY` 60 s). |
| `restrict_fk_on_non_standard_key` | n/a | ON (container) | FKs referencing non-unique or partial keys are rejected. |
| `mysql_native_password` | loaded | DISABLED (container) | Accounts on it cannot log in until you enable it. |

## Removed or Deprecated

Removed in 8.4.0 (from What Is New, Features Removed). Setting a removed variable or option makes the server refuse to start.

| Removed | Use instead |
|---|---|
| `CHANGE MASTER TO`, `RESET MASTER`, `SHOW MASTER STATUS`, `PURGE MASTER LOGS`, `SHOW MASTER LOGS`, `START/STOP/RESET SLAVE`, `SHOW SLAVE STATUS`, `SHOW SLAVE HOSTS` | `CHANGE REPLICATION SOURCE TO`, `RESET BINARY LOGS AND GTIDS`, `SHOW BINARY LOG STATUS`, `PURGE BINARY LOGS`, `SHOW BINARY LOGS`, `START/STOP/RESET REPLICA`, `SHOW REPLICA STATUS`, `SHOW REPLICAS`. Container: 8.4 returns error 1064 for `SHOW MASTER STATUS`, `SHOW MASTER LOGS` and `RESET MASTER` (also on 9.7 and 26.x); 8.0.46 returns 1064 for `SHOW BINARY LOG STATUS` and `RESET BINARY LOGS AND GTIDS`. |
| `default_authentication_plugin` | `authentication_policy` (syntax changed; default `*,,`) |
| `expire_logs_days` | `binlog_expire_logs_seconds` (default 2592000 = 30 days) |
| `binlog_transaction_dependency_tracking` | none; the source always uses writesets for dependency tracking |
| `group_replication_recovery_complete_at` | none |
| `--skip-host-cache` | `--host-cache-size=0` |
| `FLUSH HOSTS` | `TRUNCATE TABLE performance_schema.host_cache` (container: `FLUSH HOSTS` is error 1064 on 8.4+ and a deprecation warning on 8.0.46; the `TRUNCATE` works on all five images) |
| `mysql_upgrade` | none; the server upgrades itself at startup |
| `mysqlpump` (+ `lz4_decompress`, `zlib_decompress`) | `mysqldump` or MySQL Shell dump utilities |
| `mysql_ssl_rsa_setup` | the server generates certificates (`auto_generate_certs`) |
| `keyring_file`, `keyring_encrypted_file` plugins (and `keyring_file_data`) | `component_keyring_file`, `component_keyring_encrypted_file` |
| `SET_USER_ID` privilege | `SET_ANY_DEFINER`, `ALLOW_NONEXISTENT_DEFINER` |
| `AUTO_INCREMENT` on `FLOAT`/`DOUBLE` columns | integer types; the upgrade fails until such tables are fixed |
| `--character-set-client-handshake`, `--old-style-user-limits` | none |
| `--ssl`, `--skip-ssl`, `--admin-ssl` options and the `have_ssl`, `have_openssl` variables (8.4.0 notes) | `--tls-version`, `--admin-tls-version` |

Deprecated in 8.4 (still works, plan to remove): `mysql_native_password`; `%` and `_` as wildcards in database-level grants (deprecated 8.2.0; expect them to become literals); non-unique or partial foreign key references; `INFORMATION_SCHEMA.PROCESSLIST`; `--master-retry-count`; `temptable_use_mmap`.

## Worth Adopting

- New privileges: `FLUSH_PRIVILEGES` (narrower than `RELOAD`), `OPTIMIZE_LOCAL_TABLE`, `TRANSACTION_GTID_TAG`, `SET_ANY_DEFINER`, `ALLOW_NONEXISTENT_DEFINER`. The upgrade grants them automatically to accounts that held the old equivalent.
- Tagged GTIDs: `SET gtid_next = 'AUTOMATIC:batch01'` marks transactions as `UUID:TAG:N`, for example to separate maintenance writes from application writes. Requires `TRANSACTION_GTID_TAG`.
- `START REPLICA ... SQL_AFTER_GTIDS` works with the multithreaded applier.
- Automatic histogram updates: `ANALYZE TABLE t UPDATE HISTOGRAM ON c WITH 64 BUCKETS AUTO UPDATE`. Not available on Aurora MySQL 8.4.7+ (treated as `MANUAL UPDATE`).
- Clone between any two 8.4.x patch releases.
- Sanitized relay log recovery: incomplete transactions at the end of the relay log are removed at startup when `relay_log_recovery=OFF`.
- `mysqldump --output-as-version=BEFORE_8_2_0|BEFORE_8_0_23` to produce dumps loadable by older replicas.
- `tls_certificates_enforced_validation` to refuse invalid certificates at startup and on `ALTER INSTANCE RELOAD TLS`.
- `mysql --system-command=OFF` and (8.4.6+) `--commands=OFF` to restrict client-side commands when running untrusted scripts.

## Upgrading Into This Series

From 8.0 (direct). Blockers and checks, in order:

1. Run the upgrade checker with `--target-version=8.4.x`. It reports removed variables, new reserved words, and invalid objects. `QUALIFY` and `TABLESAMPLE` are reserved in 8.4. `MANUAL` and `PARALLEL` are reserved in 8.4.0-8.4.10 and nonreserved from 8.4.11 (8.4 keywords page; containers: `CREATE TABLE manual (...)` fails with 1064 on 8.4.10 and succeeds on 8.4.13). Upgrading to 8.4.10 or older, quote them; from 8.4.11 they work unquoted again.
2. Accounts on `mysql_native_password`:
   ```sql
   SELECT user, host FROM mysql.user WHERE plugin = 'mysql_native_password';
   ```
   Convert them before the upgrade (`ALTER USER 'u'@'h' IDENTIFIED WITH caching_sha2_password BY '...'`; this needs the password), or start 8.4 with `mysql_native_password=ON` in `[mysqld]` as a temporary bridge (container: with `--mysql-native-password=ON` the plugin is ACTIVE, and an account created `IDENTIFIED WITH mysql_native_password` can log in; without it `CREATE USER ... IDENTIFIED WITH mysql_native_password` fails with ERROR 1524). Clients older than `caching_sha2_password` support, or connecting without TLS and without RSA key exchange, fail to authenticate; test each driver.
3. Option files and `mysqld-auto.cnf`: delete every removed variable above. Replace `expire_logs_days` with `binlog_expire_logs_seconds` and `default_authentication_plugin` with `authentication_policy`.
4. Scripts and tools: replace every `MASTER`/`SLAVE` statement. Monitoring that runs `SHOW SLAVE STATUS` returns a syntax error on 8.4.
5. `FLOAT`/`DOUBLE` columns with `AUTO_INCREMENT`:
   ```sql
   SELECT table_schema, table_name, column_name FROM information_schema.columns
    WHERE extra LIKE '%auto_increment%' AND data_type IN ('float','double');
   ```
   The upgrade fails while any exist.
6. Foreign keys that reference non-unique or partial keys: the upgrade writes warnings listing them. New ones are rejected while `restrict_fk_on_non_standard_key=ON`. Add a unique key on the referenced columns, or set the variable OFF as a temporary measure.
7. Re-check performance-relevant defaults (adaptive hash index, change buffering, `innodb_io_capacity`, flush method). Pin the 8.0 values in the option file for the first cutover if you want an unchanged baseline, then revert to the new defaults one at a time.
8. Group Replication: decide whether the new `group_replication_consistency` and `exit_state_action` defaults suit the application.

## Managed Service Notes

- RDS for MySQL 8.4: community release 2024-04-30, RDS release 2024-11-21, standard support to 2029-07-31, Extended Support to 2032-07-31. RDS 8.4 stored procedures use `source` names (`mysql.rds_set_external_source`, `mysql.rds_next_source_log`); the 8.0 `master` names do not exist there.
- RDS for MySQL 8.4 defaults to `caching_sha2_password` but keeps `mysql_native_password` working, unlike community 8.4; RDS 9.7 does not support it, and accounts that use it block the RDS 8.4 to 9.7 upgrade. See [managed services](../managed-services.md#restrictions).
- Aurora MySQL 8.4 (announced 2026-05-21, first minor 8.4.7, latest 8.4.12 on 2026-11-20). Aurora keeps `mysql_native_password` enabled and the setting cannot be changed. Fast insert is not available. Automatic histogram updates are disabled from 8.4.7.
