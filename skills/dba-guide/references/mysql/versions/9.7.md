# MySQL 9.7 LTS

Checked: 2026-11-27. Read this when the server reports `9.7.x` or any 9.x Innovation release, when upgrading from 8.4, or when a server must later move to the 26.x calendar-versioned releases.

## Lifecycle

- LTS. 9.7.0 GA 2026-04-21. Premier Support to April 2031, Extended Support to April 2034.
- Latest on 2026-11-27: 9.7.4 (2026-10-20) and its update 9.7.4.1 (2026-11-24).
- 9.7 is the last sequentially numbered series and the only one that can upgrade directly into the calendar-versioned releases (26.7, 26.10).
- The 9.7 release notes include the Innovation releases 9.0.0 (2024-07-01) through 9.6.x. A change listed below as made "in 9.x" is part of 9.7.

## Changed Defaults

Against 8.4. "Container" means confirmed on the `mysql:9.7` image (9.7.4) and differing from the `mysql:8.4` image (8.4.13) on the same host.

| Variable | 8.4 | 9.7 | Changed in | Decision impact |
|---|---|---|---|---|
| `gtid_mode` / `enforce_gtid_consistency` | OFF / OFF | ON / ON (container) | 9.5.0 | New servers write GTIDs, and statements that GTID consistency forbids now fail. Set `gtid_mode` explicitly in every option file so a rebuilt server never starts in a different mode from its topology. |
| `SOURCE_SSL` (`CHANGE REPLICATION SOURCE TO`) | 0 | 1 | 9.5.0 | Replication connections are encrypted by default; the source must accept TLS. |
| `group_replication_ssl_mode` / `group_replication_recovery_use_ssl` | not stated | REQUIRED / ON | 9.5.0 | |
| `explain_format` | TRADITIONAL | TREE (container) | 9.5.0 | Plain `EXPLAIN` prints the tree format. Tools that parse the tabular output must ask for `FORMAT=TRADITIONAL`. |
| `explain_json_format_version` | 1 | 2 (container) | 9.5.0 | `EXPLAIN FORMAT=JSON` has a different structure; update JSON parsers. |
| `innodb_change_buffering` | `none` | `all` (container) | 9.5.0 | |
| `innodb_change_buffer_max_size` | 25 | 5 (container) | 9.4.0 | |
| `back_log` | 151 | 10000 (container) | 9.4.0 | The OS listen backlog (`net.core.somaxconn`) still caps the effective value. |
| `binlog_transaction_dependency_history_size` | 25000 (maximum 1000000) | 10000000 (maximum 100000000) in the 9.7.4, 26.7.0 and 26.10.0 containers; the 9.5.0 notes give a default of 1000000 and a maximum of 10000000 | 9.5.0 | The 9.7 variable reference gives 10000000 and 100000000, matching the containers; only the 9.5.0 notes differ. |
| `caching_sha2_password_digest_rounds` | 5000 | 10000 (container) | 9.5.0 | New password hashes cost more CPU per authentication. |

| `activate_mandatory_roles` | n/a | ON (container) | 9.5.0 | Mandatory roles become active at login in addition to default roles. With `activate_all_roles_on_login=ON` this variable is ignored and all granted and mandatory roles are activated (9.5.0 notes). |
| `replica_parallel_workers` | minimum 0 | minimum 1 | 9.3.0 | Single-threaded apply is `replica_parallel_workers=1`. |

| `container_aware` | n/a (error 1193 on 8.4.13) | OFF (9.7 manual; container) | 9.x; the notes checked do not name the release | With OFF the server logs that it ignores container CPU and memory limits when it derives defaults. |

## Removed or Deprecated

Removed between 8.4 and 9.7:

| Removed | In | Replacement or action |
|---|---|---|
| `mysql_native_password` server plugin; `--mysql-native-password`, `--mysql-native-password-proxy-users`; `default_authentication_plugin` | 9.0.0 | Convert accounts to `caching_sha2_password`. The client-side plugin still exists. Container: `CREATE USER ... IDENTIFIED WITH mysql_native_password` fails with ERROR 1524 "Plugin 'mysql_native_password' is not loaded" on 9.7.4, 26.7.0 and 26.10.0, and a 9.7.4 server started with `--mysql-native-password=ON` aborts with "unknown variable 'mysql-native-password=ON'". |
| `innodb_log_file_size`, `innodb_log_files_in_group` | 9.3.0 | `innodb_redo_log_capacity` |
| `innodb_undo_tablespaces` | 9.3.0 | `CREATE UNDO TABLESPACE` / `DROP UNDO TABLESPACE` |
| Version Tokens plugin | 9.3.0 | none |
| `temptable_use_mmap` | 9.4.0 | `temptable_max_mmap=0` disables mmap use |
| `replica_parallel_type` | 9.5.0 | none (LOGICAL_CLOCK behavior is built in) |
| `group_replication_allow_local_lower_version_join` | 9.5.0 | none |
| `semisync_master`, `semisync_slave` plugins | 9.5.0 | `semisync_source`, `semisync_replica` |
| `sha2_cache_cleaner` audit plugin | 9.2.0 | none |
| `MD5()`, `SHA1()` in the core server | 9.6.0 | install the `classic_hashing` component (functions deprecated since 9.4.0) |

Deprecated in 9.x and still present in 9.7: `FLUSH PRIVILEGES`, the `FLUSH_PRIVILEGES` privilege, `mysqladmin flush-privileges` and `reload` (9.2.0); the Connection Control plugins, replaced by `component_connection_control` (9.2.0); the plugin API, `--early-plugin-load`, and all keyring plugins, replaced by keyring components (9.4.0); the Enterprise Firewall plugin (9.4.0); `keyring_okv` (9.5.0); `SCRAM-SHA-1` for SASL LDAP (9.5.0). Since 9.0.0, a transaction that changes both transactional and non-transactional tables raises a deprecation warning.

## Worth Adopting

- `EXPLAIN ANALYZE FORMAT=JSON INTO @v SELECT ...` (9.0.0) stores the analysed plan in a variable for scripted comparison. Requires `explain_json_format_version=2`.
- `VECTOR` column type (9.0.0, InnoDB only, cannot be a key).
- Hypergraph optimizer in Community Edition (9.7.0): test one query with `SET SESSION optimizer_switch='hypergraph_optimizer=on'`; do not enable it globally without a regression run.
- Telemetry component in Community Edition (9.7.0).
- JSON duality views (`CREATE JSON DUALITY VIEW`, 9.4.0); DML through them is in Community Edition from 9.7.0.
- `server_memory` (9.4.0) caps the memory the server assumes when it computes memory-based defaults.
- `caching_sha2_password` proxy users (9.3.0) and `component_connection_control` (9.2.0).
- `mysqldump --users`, `--add-drop-user`, `--include-user`, `--exclude-user` (9.3.0) dump accounts as `CREATE USER` and `GRANT`.

## Upgrading Into This Series

From 8.4 (direct) or from a 9.x Innovation release (direct). From 8.0, upgrade to 8.4 first.

1. Run the upgrade checker with `--target-version=9.7.4` from Shell 9.7 or later.
2. `mysql_native_password` is gone, and no server setting brings it back. Every account still on it cannot log in after the upgrade:
   ```sql
   SELECT user, host FROM mysql.user WHERE plugin = 'mysql_native_password';
   ```
   Convert each listed account and test each client driver before the switch.
3. Remove from option files and `mysqld-auto.cnf`: `innodb_log_file_size`, `innodb_log_files_in_group`, `innodb_undo_tablespaces`, `temptable_use_mmap`, `replica_parallel_type`, `group_replication_allow_local_lower_version_join`, `mysql_native_password`, `default_authentication_plugin`, and `plugin-load` entries for `semisync_master`/`semisync_slave`. Size the redo log with `innodb_redo_log_capacity`.
4. Spatial indexes: 9.2.0 fixed a spatial index corruption bug in an incompatible way. Drop spatial indexes before the upgrade and recreate them after, or recreate them right after the upgrade before the tables are used.
5. Tables whose constraints, defaults, partitioning, or generated columns call functions: since 9.3.0 the upgrade checks them and, with the default `--check-table-functions=ABORT`, stops if one fails to open. Run the checker and fix them first.
6. Inline `REFERENCES` clauses in column definitions create enforced foreign keys since 9.0.0 (earlier versions parsed and ignored them). Re-run schema scripts in a test schema.
7. GTID default: if the 8.4 topology runs `gtid_mode=OFF` and the option file does not set it, a 9.7 server starts with `ON`. Set `gtid_mode` and `enforce_gtid_consistency` explicitly before the upgrade.
8. Replication TLS default: `SOURCE_SSL` defaults to 1 since 9.5.0, and a channel with `SOURCE_SSL=1` does not fall back to an unencrypted connection (9.7 `CHANGE REPLICATION SOURCE TO` page). Confirm the source accepts TLS for replication users. After the upgrade, check what each existing channel uses with `SELECT CHANNEL_NAME, SSL_ALLOWED FROM performance_schema.replication_connection_configuration;` and set `SOURCE_SSL` explicitly where it matters.
9. SQL behavior changes in the 9.x notes: `db.tbl.col` references to derived tables are rejected (9.1.0); `CREATE VIEW IF NOT EXISTS` combined with `OR REPLACE` is a syntax error (9.1.0); `ROLLUP` over an empty set returns a grouping row (9.1.0); `BINLOG` cannot be an unquoted label in stored programs (9.2.0); `RANGE` window frames with a non-deterministic `ORDER BY` are rejected (9.4.0); collation derivation rules changed and `COERCIBILITY()` results can differ (9.4.0); invalid temporal values over the binary protocol are rejected in non-strict mode (9.5.0); casting a double to an integer always rounds (9.0.0).
10. `performance_schema.data_locks` and `data_lock_waits` may show an incomplete list of a transaction's locks since 9.1.0. Lock-monitoring scripts must not assume a full per-transaction snapshot.
11. `MD5()` and `SHA1()` moved out of the core server into the `classic_hashing` component in 9.6.0. Without it they fail with error 1305 (`FUNCTION db.MD5 does not exist`; containers 9.7.1 and 9.7.4). Search application SQL, views, routines, generated columns, defaults and `CHECK` constraints for `MD5(` and `SHA1(`. Either install the component right after the upgrade with `INSTALL COMPONENT 'file://component_classic_hashing';` (URN from the 9.7 manual's Legacy Hashing Component page; on the 9.7.4 container both functions work after it) or replace the calls with `SHA2()`. Objects that call them can also trip `--check-table-functions=ABORT` in step 5.
12. `EXTERNAL` is reserved in 9.7 but not in 8.4: `CREATE TABLE external (...)` succeeds on 8.4.13 and fails with 1064 on 9.7.1 and 9.7.4 (containers). Quote or rename such identifiers. `CUBE`, `QUALIFY` and `TABLESAMPLE` already fail unquoted on 8.4.10 and 8.4.13. `MANUAL` and `PARALLEL` fail on 9.7.1 and work from 9.7.2 (9.7.2 notes; container 9.7.4).
