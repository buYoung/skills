# MySQL 8.0

Checked: 2026-11-27. Read this when the server reports `8.0.x`, when planning the 8.0 -> 8.4 upgrade, or when an RDS for MySQL 8.0 or Aurora MySQL version 3 instance is involved.

## Lifecycle

- GA April 2018. Premier Support ended April 2025, Extended Support April 2026. Since 2026-04-21 Oracle covers 8.0 only under Sustaining Support (no new fixes). 8.0.46 is the final release.
- Oracle's advice: upgrade to 8.4 LTS or 9.7 LTS. 9.7 cannot be reached directly; go through 8.4.
- RDS for MySQL 8.0: standard support ended 2026-07-31; RDS Extended Support runs to 2029-07-31 with RDS-built `8.0.46-RDS.YYYYMMDD` minors. Aurora MySQL version 3 (8.0-compatible): standard support to 2028-04-30. See [managed-services.md](../managed-services.md#version-availability-and-extended-support).

## Changed Defaults

Defaults that differ from later series. Sources: container output for 8.0.46, 8.4.13, 9.7.4 and 26.10.0 (2026-11-27); the "changed in" versions come from the release notes.

|---|---|---|---|
| `innodb_adaptive_hash_index` | ON | OFF | OFF |
| `innodb_change_buffering` | `all` | `none` | `all` (changed in 9.5.0) |
| `innodb_change_buffer_max_size` | 25 | 25 | 5 (changed in 9.4.0) |
| `innodb_io_capacity` / `_max` | 200 / 2000 | 10000 / 20000 | 10000 / 20000 |
| `innodb_log_buffer_size` | 16 MiB | 64 MiB | 64 MiB |
| `innodb_use_fdatasync` | OFF | ON | ON |
| `innodb_flush_method` on Linux | `fsync` | `O_DIRECT` if supported | `O_DIRECT` |
| `innodb_purge_threads` | 4 | 1 if <= 16 logical CPUs, else 4 | same as 8.4 |
| `temptable_use_mmap` | ON | OFF, deprecated | removed in 9.4.0 |
| `back_log` | 151 | 151 | 10000 (changed in 9.4.0) |
| `gtid_mode` / `enforce_gtid_consistency` | OFF / OFF | OFF / OFF | ON / ON (changed in 9.5.0) |
| `explain_format` | TRADITIONAL | TRADITIONAL | TREE (changed in 9.5.0) |

## Removed or Deprecated

Deprecated in 8.0 and removed in 8.4. They work on 8.0 but break an 8.4 upgrade or the scripts that use them: `master`/`slave` replication statements, `expire_logs_days`, `default_authentication_plugin`, `binlog_transaction_dependency_tracking`, `--skip-host-cache`, `FLUSH HOSTS`, `mysql_upgrade`, `mysqlpump`, the `keyring_file` and `keyring_encrypted_file` plugins, and `AUTO_INCREMENT` on `FLOAT`/`DOUBLE`. `SET_USER_ID` works without a warning on 8.0; it was deprecated in 8.2.0 and removed in 8.4.0, where granting it is a syntax error (use `SET_ANY_DEFINER` and `ALLOW_NONEXISTENT_DEFINER`). Replacements: [8.4](8.4.md#removed-or-deprecated).

Deprecated in 8.0, still in 8.4, removed later: `mysql_native_password` (removed 9.0.0), `innodb_log_file_size` and `innodb_log_files_in_group` (deprecated 8.0.30, removed 9.3.0), `innodb_undo_tablespaces` (deprecated 8.0.14, removed 9.3.0), `temptable_use_mmap` (deprecated 8.0.26, removed 9.4.0), `replica_parallel_type` (deprecated 8.0.29, removed 9.5.0), `INFORMATION_SCHEMA.PROCESSLIST` (deprecated 8.0.35).

## Worth Adopting

While a server must stay on 8.0, use the 8.0 features that make the later upgrade smaller. Each exists only from the 8.0 minor named; check `VERSION()`.

- `innodb_redo_log_capacity` (8.0.30+) instead of `innodb_log_file_size` x `innodb_log_files_in_group`. It is dynamic and is the only redo sizing variable after 9.3.0.
- `SHOW REPLICA STATUS`, `START REPLICA`, `CHANGE REPLICATION SOURCE TO` and the `replica_*`/`source_*` variable names (8.0.22-8.0.26). Convert scripts now; the old statements are syntax errors in 8.4.
- `mysqldump --source-data` instead of `--master-data` (the 8.0.46 `mysqldump --help` lists both and marks `--master-data` deprecated; the 8.0 minor that introduced `--source-data` is not confirmed, so check `mysqldump --help` on older minors).
- `binlog_expire_logs_seconds` instead of `expire_logs_days`.
- `caching_sha2_password` for every account, so the default-disabled native plugin in 8.4 locks nobody out.
- The clone plugin for rebuilding replicas (8.0.17+).

## Upgrading Into This Series

Upgrades into 8.0 come from 5.7, which this reference does not cover. Read https://dev.mysql.com/doc/refman/8.0/en/upgrading-from-previous-series.html and run the MySQL Shell upgrade checker against the 5.7 server.

Upgrading out of 8.0: see [8.4](8.4.md#upgrading-into-this-series).

## Managed Service Notes

- RDS for MySQL 8.0 is available only under RDS Extended Support, which is charged from 2026-08-01 (rates on the RDS pricing page). RDS offers the 8.0 -> 8.4 major upgrade. Disabling Extended Support enrollment on an 8.0 instance upgrades it automatically to the next major version.
- On RDS for MySQL 8.0.36 and higher the master user gets `rds_superuser_role` plus a fixed static privilege list; on older 8.0 minors there is no role.
- Aurora MySQL version 3 engine versions look like `8.0.mysql_aurora.3.xx.y`. LTS minors: 3.04 (standard support ended 2026-10-31) and 3.10 (to 2028-04-30). Latest: 3.14, compatible with MySQL 8.0.46, released 2026-10-26.
