# MySQL 26.10 Innovation (and 26.7)

Checked: 2026-11-27. Read this when the server reports `26.x`, when deciding whether to run Innovation releases, or when upgrading from 9.7 LTS into the calendar-versioned releases.

## Lifecycle

- 26.10 is an Innovation release. 26.10.0 GA 2026-10-20; update 26.10.0.1 (Critical Security Patch Update) 2026-11-24. Supported until the next Innovation release; that date is not announced.
- 26.7 was the first calendar-versioned release (26.7.0 GA 2026-07-28). As an Innovation release its support ended when 26.10.0 shipped on 2026-10-20. 26.7 -> 26.10 is a direct upgrade (same lineage).
- Both belong to the compatibility lineage anchored by 9.7.0. They can upgrade to later releases in that lineage and to the LTS release that closes it. They cannot be downgraded in place (Innovation downgrades require a logical dump and load).
- Run Innovation releases only where you can upgrade every quarter and have automated tests; behavior can change in any release.
- RDS for MySQL offers 26.10 only in the Database Preview environment (not for production). Aurora MySQL offers no 26.x version.

## Changed Defaults

Against 9.7 (from release notes; "container" = confirmed on `mysql:26.7`/`mysql:26.10` images).

| Variable | 9.7 | 26.x | Changed in | Note |
|---|---|---|---|---|
| `group_replication_communication_stack` | XCOM | MYSQL | 26.7.0 | The variable itself is deprecated in 26.7. Groups created with defaults use the MySQL communication stack and need the recovery user to have `GROUP_REPLICATION_STREAM` and `CONNECTION_ADMIN` (Group Replication connection security page; without `CONNECTION_ADMIN` a member placed in offline mode is expelled). |
| `thread_pool_max_unused_threads` | 2 (9.7.0-9.7.1), 32 (9.7.2+, 9.7.2 notes) | 32 | 9.7.2 | Thread pool is in Community Edition from 26.7.0 (26.7.0 notes); the 9.7 manual still lists it as Enterprise. See the container note below the table. |
| `innodb_autoinc_preallocate` | n/a (error 1193 on 9.7.4) | 50 (container) | 26.7.0 | InnoDB persists AUTO_INCREMENT counters in batches; a crash can skip up to the preallocated values. A clean shutdown leaves no gap. `0` disables. |
| `optimizer_switch`, `optimizer_trace` value parsing | prefixes accepted | exact values only; invalid value -> `ER_WRONG_VALUE_FOR_VAR` | 26.10.0 | Scripts with `index_merge=of` style abbreviations fail. |
| `EXPLAIN FORMAT=TREE` | no note | emits Note 1003 | 26.10.0 | Container: `EXPLAIN` shows "1 warning". |

Container note on the thread pool: the `mysql:9.7` Community image (9.7.4) ships `thread_pool.so`. Started with `--plugin-load-add=thread_pool.so`, it shows `thread_pool` ACTIVE with license GPL and `thread_pool_max_unused_threads=32`, as 26.10.0 does. Without that option the variable does not exist (error 1193). The 8.0 and 8.4 images do not ship the plugin.

Defaults that 26.10.0 shares with 9.7.4 (both containers): `gtid_mode=ON`, `explain_format=TREE`, `explain_json_format_version=2`, `innodb_change_buffering=all`, `back_log=10000`, `caching_sha2_password_digest_rounds=10000`, `restrict_fk_on_non_standard_key=ON`, `container_aware=OFF`.

## Removed or Deprecated

26.7.0:

- Enterprise Linux 7 is no longer supported.
- Undo truncation marker files (`undo_space_number_trunc.log`) are no longer created; old ones are still read.
- Deprecated: `group_replication_communication_stack`, `group_replication_ip_allowlist`.
- Keywords: the 26.7.0 notes list `CUBE`, `EXTERNAL`, `QUALIFY`, `TABLESAMPLE` as now reserved and `MANUAL`, `PARALLEL` as no longer reserved. The same fix shipped in 8.4.11 and 9.7.2. On 9.7 the four words already fail unquoted (containers 9.7.1 and 9.7.4), so a schema that works on 9.7 is not affected.
- `NULLIF()` on a `YEAR` expression keeps the `YEAR` type (aggregates over it may return DECIMAL instead of DOUBLE); `POW(x, NULL)` returns NULL instead of 1.

26.10.0:

- OpenSSL older than 1.1.1 is unsupported.
- `PSI_THREAD_VERSION` 4-6 deprecated for plugins.

Not removed: the X Plugin is loaded on 26.10.0 (container: `mysqlx` is `ACTIVE` in `information_schema.PLUGINS` on every image, `mysqlx_port=33060`, "X Plugin ready for connections" in the log). `SELECT @@mysqlx` fails on every version because no variable named `mysqlx` exists, so it cannot be used to test for the plugin. `mysql_native_password` is absent, as in every release since 9.0.0.

The "Features Removed" sections of the 26.7 and 26.10 manuals list only `group_replication_allow_local_lower_version_join` and `replica_parallel_type`, which the 9.5.0 notes say were removed in 9.5.0. Treat those manual sections as carried over from 9.7, and use the release notes as the authority.

## Worth Adopting

26.7.0:

- Change Stream Applier (CSA): per-channel alternative to the multithreaded applier. `CHANGE REPLICATION SOURCE TO ... APPLIER_VERSION = 2, APPLIER_WORKER_COUNT = 16` (stop the SQL thread first). Requires row-based replication with `GTID_MODE=ON`, `GTID_ONLY=1`, `REQUIRE_ROW_FORMAT=1`; not supported with file-position channels, `SOURCE_DELAY`, `sql_replica_skip_counter`, `IGNORE_SERVER_IDS`, or `UNTIL` conditions other than `SQL_BEFORE_GTIDS`/`SQL_AFTER_GTIDS`. `APPLIER_VERSION = 1` (the multithreaded applier) stays the default for new channels.
- Post-quantum TLS 1.3 key exchange and signatures with OpenSSL 3.5+: `tls_kex`, `force_pqc`, `use_pqc_sign` and per-channel equivalents (`admin_`, `replication_`, `group_replication_`, `mysqlx_`). Status: `Tls_key_exchange_algorithm`, `Tls_sign_algorithm`. The 26.10 container logs a warning per channel while `force_pqc` is OFF.
- Thread pool plugin in Community Edition.
- Crash-safe undo tablespace creation and truncation recorded in the tablespace header.
- Clone across series only from one LTS to the next LTS.
- `mysqldump --extended-insert-multiline`.

26.10.0:

- Health Monitor in Community Edition: disk, memory, CPU and process metrics plus disk-usage forecasts through Performance Schema (full metric set on Linux, basic on macOS, not on Windows).
- MySQL REST Service component (`INSTALL COMPONENT 'file://component_mysql_rest_service'`, HTTP port 33443 by default, admin needs `MYSQL_REST_SERVICE_ADMIN`). Do not install it on a database server without reviewing its network exposure.
- `authentication_webauthn` server plugin in Community Edition (FIDO multifactor or passwordless login).
- Four-part version: `VERSION_WITH_UPDATE()`, `@@version_with_update` (container: 26.10.0.1).
- JSON duality view `CHECK`/`NO CHECK` and `UPDATE`/`NO UPDATE` annotations. Upgrade replicas before a source replicates DDL using them.
- Partition names in TREE/ANALYZE EXPLAIN output and a `partitions` array in JSON v2.
- Error-log warnings when the InnoDB history list exceeds `innodb_max_purge_lag` or purge lag starts delaying DML.
- `EXCHANGE PARTITION` enforces CHECK constraints in both directions even `WITHOUT VALIDATION` (error 3819).

## Upgrading Into This Series

From 9.7.x LTS (the only sequential release that can enter), or from 26.7.x.

1. 8.4 and older, and 9.0-9.6 Innovation releases, are rejected at startup. Upgrade them to 9.7 first.
2. Run the upgrade checker from Shell 26.10.
3. Schemas and SQL that only ran on 8.4 can still use `EXTERNAL` unquoted (accepted on 8.4.13). They reach 26.x through 9.7, where it is rejected; see [9.7](9.7.md#upgrading-into-this-series).
4. Fix scripts that set `optimizer_switch` or `optimizer_trace` with abbreviated values.
5. Applications that must not see AUTO_INCREMENT gaps after a crash: set `innodb_autoinc_preallocate=0`. (No application should depend on gap-free AUTO_INCREMENT; rollbacks already create gaps.)
6. Group Replication: decide the communication stack explicitly (`group_replication_communication_stack`) before members on different versions join, because the default changed to MYSQL. With MYSQL, grant the recovery user `GROUP_REPLICATION_STREAM` and `CONNECTION_ADMIN` on every member first.
7. Keep a logical backup taken before the upgrade. There is no in-place downgrade from 26.x.
