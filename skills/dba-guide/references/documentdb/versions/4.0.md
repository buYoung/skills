# Amazon DocumentDB 4.0

Checked: 2026-11-27. Read this when a cluster reports `EngineVersion` `4.0.0` or a patch version `2.0.x`, when you upgrade from 3.6, or when you plan to leave 4.0.

## Lifecycle

| Event | Date |
| --- | --- |
| Release | 9 Nov 2020 |
| End of standard support | Not announced (N/A on the [lifecycle page](https://docs.aws.amazon.com/documentdb/latest/devguide/docdb-version-support-dates.html)) |

- 4.0 has no minor versions. The engine version is always `4.0.0`, and fixes arrive as `2.0.x` patches. The latest patch in the release notes is 2.0.14287 (18 Aug 2026).
- A required patch, 2.0.14278 (27 Apr 2026), fixes a rare hang in point-in-time restore and major version upgrade. Apply it before you rely on PITR or start an MVU.

## Changed Defaults

Compared with 3.6, from the [release notes](https://docs.aws.amazon.com/documentdb/latest/devguide/release-notes.html) and the [compatibility page](https://docs.aws.amazon.com/documentdb/latest/devguide/compatibility.html#mongodb-40):

- Working memory scales with the instance memory size.
- The cluster volume shrinks when you drop collections, indexes, or databases. On 3.6 it never shrinks.
- Numeric comparisons inside subdocuments behave the same as at the top level, as in MongoDB.
- `$setOnInsert` is rejected when the path uses the positional `$`, as in MongoDB 4.0.

Change stream retention up to 7 days (previously 24 hours) and cluster- and database-level change streams (`client.watch()`, `db.watch()`) shipped for 3.6 on 30 Oct 2020 and for 4.0 at its GA, so they are not differences between the two. `startAtOperationTime` reached 3.6 in optional patch 1.0.208692 (27 Apr 2026). The compatibility page still presents all three as 4.0 features (release notes).

## Worth Adopting

| Feature | Why it changes a decision |
| --- | --- |
| Multi-document ACID transactions | You can keep normalized designs that need atomic multi-document updates. Limits (1-minute execution, 32 MB log) are in [compatibility.md](../compatibility.md#sessions-transactions-and-retryable-writes) |
| Global clusters | Cross-Region disaster recovery; 3.6 has none. Switchover and managed failover were added on 22 Aug 2024 |
| `$expr`, `$jsonSchema` validation, the `$convert` family, `$switch`, set operators, the `$trim` family, the `$collStats` stage (added by patches from 2023 to 2025) | Logic that previously had to run in the client can run in the database |
| Index use in `$lookup`; covered queries for one projected field (plus `_id`); `hint()` with `findAndModify` | Joins no longer need a collection scan |
| Uncorrelated `$lookup` subqueries (patch 2.0.10392) | |
| DML auditing with audit filtering (`setAuditConfig`, patch 2.0.10593 or later) | You get an audit trail of reads and writes without logging every operation |
| `tls1.2+`/`tls1.3+` values for the `tls` parameter (patch 2.0.10980 or later) | You can enforce TLS 1.2 or later without upgrading to 5.0 |
| TLS CA rotation without reboot (patch 2.0.10179 or later) | Certificate rotation no longer costs downtime |
| Dual-stack IPv4/IPv6 (patch 2.0.11747 or later) | |
| `AvailableMVCCIds` and `LongestActiveGCRuntime` metrics; `MVCCIDStats`/`gcRuntimeStats` in `collStats` (patch 2.0.11747 or later) | You can alarm before MVCC IDs run out and the cluster turns read-only. On 3.6 and 4.0, alarm below 1.3 billion |
| Graviton2 `db.r6g` and `db.t4g` instances | Lower instance cost. `db.r8g` and NVMe-backed `db.r6gd` need 5.0 or later |

## Still missing compared with 5.0 and later

Text indexes, partial indexes, vector search, document compression, I/O-Optimized storage, serverless, IAM authentication, client-side field level encryption, `reIndex`, plan cache filters, change streams on replicas, `$dateAdd`/`$dateSubtract`, `$regexMatch`/`$regexFind`, longer names, and `db.r8g` instances. On 4.0 a collection name is limited to 57 characters, `<db>.<col>` to 120, and the combined `<col>$<index>` name to 63 ([naming constraints](https://docs.aws.amazon.com/documentdb/latest/devguide/limits.html#limits-naming_constraints)).

## Upgrading Into This Series

From 3.6 the only paths are DMS and `mongodump`/`mongorestore`, because 4.0 is not an in-place MVU target. Running an MVU from 3.6 straight to 5.0 or 8.0 is usually better: it is a single downtime event, and the cluster keeps its endpoints.

Behavior changes from 3.6 ([compatibility page](https://docs.aws.amazon.com/documentdb/latest/devguide/compatibility.html#mongodb-40)):

- A nested projection such as `{a: {b: {c: 1}}}` now applies at every level.
- `{x: {$gt: MaxKey}}` returns nothing, and `{x: {$lt: MaxKey}}` returns everything.
- Numeric comparisons inside subdocuments are consistent across int, long, and double.

Checks:

1. Transactions need drivers compatible with MongoDB 4.0 or later. Keep `retryWrites=false`, because 4.0 rejects retryable writes with code 301.
2. Move every instance off `db.r4`.
3. DMS does not copy indexes. Copy them with the Amazon DocumentDB Index Tool, or recreate them before the full load ([DMS upgrade page](https://docs.aws.amazon.com/documentdb/latest/devguide/docdb-migration.versions.html)).

## Leaving This Series

- In-place MVU can go to any 5.0 or 8.0 minor. Direct 4.0 to 8.0 has been available since 31 Aug 2026. DMS also works.
- Global clusters cannot use in-place MVU. Detach the secondaries, run the MVU, then add them back.
- After the MVU, optionally run `reIndex` on 5.0 or later. It costs I/O.
- Review [5.0](5.0.md#upgrading-into-this-series) for query-result changes. They apply even when you go directly to 8.0.

## Managed Service Notes

- Engine patches on 4.0 cause a longer outage than on 5.0 and 8.0, and the outage covers reads too, because rolling, read-available patching exists only on 5.0 and later.
- Performance Insights is available on 4.0 ([PI page](https://docs.aws.amazon.com/documentdb/latest/devguide/performance-insights.html)). The open question about its future is covered in [architecture-and-operations.md](../architecture-and-operations.md#monitoring).
