# Amazon DocumentDB 3.6

Checked: 2026-11-27. Read this when a cluster reports `EngineVersion` `3.6.0` or a patch version `1.0.x`, or when you plan to move one off 3.6.

## Lifecycle

| Event | Date |
| --- | --- |
| Release | 9 Jan 2019 |
| End of standard support | 30 Mar 2026 |
| Enrolled in Extended Support | 31 Mar 2026 (automatic) |
| Extended Support year-1 pricing | 31 Mar 2026 according to the [support-dates page](https://docs.aws.amazon.com/documentdb/latest/devguide/docdb-version-support-dates.html); 1 Jul 2026 according to the [Extended Support page](https://docs.aws.amazon.com/documentdb/latest/devguide/extended-support.html) (conflict) |
| Extended Support year-3 pricing | 31 Mar 2028 |
| End of Extended Support | 30 Mar 2029. After this date AWS upgrades the cluster itself |

- Every 3.6 cluster is now billed the Extended Support premium. To stop it, upgrade the cluster to a version in standard support. Enrollment ends on the day the upgrade completes.
- You can still create a new 3.6 cluster if the account already has one. The new cluster is enrolled in Extended Support too.
- 3.6 has no minor versions and is never designated LTS. Changes arrive only as engine patches (`1.0.x`). The latest patch in the release notes is 1.0.208702 (18 Aug 2026).

## Removed or Deprecated

The whole series is past standard support. Treat 3.6 as a source for upgrades, not as a target.

| Change stream `startAtOperationTime` | Added in an optional patch 1.0.208692 (27 Apr 2026). Earlier patches lack it |

## Behavior specific to 3.6

- Nested projection. A projection such as `{a: {b: {c: 1}}}` is applied to `a` only, while MongoDB 3.6 applies it at each level. The dotted form `"a.b.c": 1` behaves the same on both. Rewrite projections to the dotted form before you rely on them.
- Numeric comparison inside subdocuments. Numbers of different types inside subdocuments are not compared across types: `{a: {b: NumberLong(1)}}` does not equal `{a: {b: 1}}`. 4.0 and later compare them consistently. A cluster upgraded in place from 3.6 keeps this 3.6 behavior even after the MVU, per the [MVU page](https://docs.aws.amazon.com/documentdb/latest/devguide/docdb-mvu.html#mvu-36-to-50-differences).
- Storage high-water mark. On 3.6 the cluster volume reuses freed space but never shrinks, and you are billed for the highest allocation ever reached. A snapshot restore does not reset the high-water mark. Only a logical dump and restore into a new cluster does. 4.0 and later shrink the volume when you drop collections or indexes.
- Connection limits per instance are about half of those on 4.0 and later. For example, `db.r5.large` allows 1,700 connections on 3.6 and 3,400 on 4.0 and later ([quotas](https://docs.aws.amazon.com/documentdb/latest/devguide/limits.html#limits.instance)).
- Patching downtime. 3.6 does not keep reads available while the cluster is patched. Engine patches take longer and affect both reads and writes ([maintenance](https://docs.aws.amazon.com/documentdb/latest/devguide/db-instance-maintain.html#read-availability-during-patching)).
- Point-in-time restore cannot target a 4.0 cluster.
- The Ruby driver is not supported with `db.watch()` and `client.watch()` on 3.6.

## Upgrading Out of This Series

No covered series precedes 3.6; the steps here lead out of it.

| Target | Method | Notes |
| --- | --- | --- |
| 8.0 (any published minor) | In-place MVU, direct since 31 Aug 2026 | Use this when the application tolerates the 8.0 changes; it is a single downtime event |
| 5.0 (any published minor, including 5.0.0 LTS) | In-place MVU | Use this if you need LTS, elastic clusters later, or want to skip the 8.0 behavior changes for now |
| 4.0 | DMS or `mongodump`/`mongorestore` | Not an MVU target |

Blockers and checks:

1. Move off `db.r4.*` instances. 4.0 and later do not support them.
2. Scale burstable primaries up, as described in [index.md](index.md#generic-procedure).
3. A global cluster cannot exist on 3.6, so the global-cluster MVU restriction does not apply here.
4. Test every projection that uses nested object syntax, and every comparison of mixed numeric types inside subdocuments. After an in-place MVU the 3.6 comparison behavior stays. To get the 4.0+ behavior, migrate the data into a new cluster with DMS or dump/restore instead.
5. After the MVU, rebuild indexes with `reIndex` so they pick up the index maintenance and garbage-collection improvements of 5.0. This is optional and costs I/O.
6. Moving to 5.0 or later also changes several query results, listed in [5.0](5.0.md#upgrading-into-this-series) and [8.0](8.0.md#upgrading-into-this-series). Review both sets of changes when you go directly from 3.6 to 8.0.

## Managed Service Notes

Only Extended Support patches (critical and high CVEs, critical bugs) will arrive from now on. Budget for the premium, and expect AWS to upgrade any cluster still on 3.6 after 30 Mar 2029.
