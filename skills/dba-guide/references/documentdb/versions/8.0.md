# Amazon DocumentDB 8.0

Checked: 2026-11-27. Read this when a cluster reports `EngineVersion` `8.0.x` or a patch version `4.0.x`, when you choose a target version, or when you upgrade from 5.0, 4.0, or 3.6.

## Lifecycle

| Item | Value |
| --- | --- |
| GA | 14 Nov 2025 on the [lifecycle page](https://docs.aws.amazon.com/documentdb/latest/devguide/docdb-version-support-dates.html). The release notes entry is dated 11 Nov 2025 (patch 4.0.4448) |
| End of standard support | Not announced (N/A) |
| LTS | None designated. For LTS, use 5.0.0 with patch 3.0.17983 or later |
| Minor versions | 8.0.0, 8.0.1 (from 13 Jul 2026), 8.0.2 (28 Sep 2026, patch 4.0.12042), 8.0.3 (11 Nov 2026, patch 4.0.13572) |
| MongoDB API | MongoDB 8.0 drivers. Applications built on API 6.0 and 7.0 are also supported. Drivers must be compatible with MongoDB 5.0 or later |

When you create a cluster with the SDK, CLI, or CloudFormation and omit `engineVersion`, you get the newest 8.0 minor in the Region. Pin `--engine-version` in infrastructure code.

## Changed Defaults

| Item | 5.0 | 8.0 |
| --- | --- | --- |
| `planner_version` default | 1.0 (2.0 selectable) | 3.0 |
| `default_collection_compression` | `disabled` (valid: `enabled`, `disabled`) | `zstd` (valid: `zstd`, `lz4`, `disabled`; `enabled` is rejected) |
| TLS | `enabled` accepts TLS 1.0 to 1.3 on 5.0.0 | TLS 1.2 or later only. TLS 1.0 and 1.1 removed |
| Collation on new collections and indexes after an MVU | n/a | On by default |
| New text indexes | v1 | v2 (additional tokens). Existing text indexes keep their version |
| Max storage | 128 TiB | 256 TiB (from 22 Jul 2026) |
| Zstd compression threshold | n/a | 128 bytes (LZ4 threshold: 2,032 bytes) |

Source: [compatibility page](https://docs.aws.amazon.com/documentdb/latest/devguide/compatibility.html#mongodb-80), [cluster parameters reference](https://docs.aws.amazon.com/documentdb/latest/devguide/cluster_parameter_groups-list_of_parameters.html), [MVU page](https://docs.aws.amazon.com/documentdb/latest/devguide/docdb-mvu.html#mvu-50-to-80-differences), [compression](https://docs.aws.amazon.com/documentdb/latest/devguide/doc-compression.html).

## Removed or Deprecated

- TLS 1.0 and 1.1 are no longer accepted.
- `enabled` is no longer a valid value for `default_collection_compression`. A copied 5.0 parameter group that sets it must be changed.
- Elastic clusters are not available on 8.0. A design that needs elastic sharding stays on the elastic (5.0-compatible) cluster type.
- Planner v3 rejects the `planHint` comment used to force a `$lookup` algorithm. That hint works only on planner v1.

## Upgrading Into This Series

Paths: in-place MVU from 5.0.0 or 5.0.1 to 8.0.0 through 8.0.3; from 5.0.2 to 8.0.2 or 8.0.3 only; and directly from 3.6 or 4.0 to any 8.0 minor. DMS can be used from 5.0. Global and elastic clusters cannot use MVU.

Blockers (from the [MVU page](https://docs.aws.amazon.com/documentdb/latest/devguide/docdb-mvu.html)):

1. Partial indexes whose `partialFilterExpression` uses `$type` with `binData`, `bool`, `date`, `double`, `decimal`, `array`, or a numeric code make the upgrade fail. List them with:

   ```
   db.getCollectionNames().forEach(function (c) {
     db.getCollection(c).getIndexes().forEach(function (ix) {
       if (ix.partialFilterExpression &&
           JSON.stringify(ix.partialFilterExpression).indexOf('"$type"') >= 0) {
         print(c + "  " + ix.name + "  " + JSON.stringify(ix.partialFilterExpression));
       }
     });
   });
   ```

   This flags every `$type` partial index, so check each hit against the list above. Drop the affected indexes before the upgrade and recreate them after it. While such an index is gone, queries that depend on it fall back to other plans, so schedule this inside the maintenance window.
2. Burstable primary: scale it to `db.r5.large` or `db.r6g.large` first. Serverless writer: set max DCU to at least 3.
3. Every client must negotiate TLS 1.2 or later.
4. A copied parameter group must not set `default_collection_compression=enabled`. Create the target group in family `docdb8.0`.

Behavior changes to test:

- Planner v3 becomes the default. Aggregation edge cases change ([planner v3 page](https://docs.aws.amazon.com/documentdb/latest/devguide/query-planner-v3.html)):
  - On an empty input, v1 emitted `"field": 0`, while v3 emits nothing.
  - `$skip` now always skips.
  - `$lookup` against a collection that does not exist returns empty matches instead of an error.
  - Multiple `$search` stages in one pipeline are rejected.
- `planHint` comments stop working under v3. Remove them, or use plan cache filters (index filters).
- After the MVU, new collections get Zstd compression and collation. Existing collections keep their compression settings. To use Zstd on an existing collection, run `collMod` with `algorithm: "zstd"`. Only documents inserted or updated afterward are recompressed.
- No index rebuild is needed when you come from 5.0. Coming from 3.6 or 4.0, run `reIndex` as described in [index.md](index.md#generic-procedure).
- Retryable writes are available only from 8.0.2, and only with planner 2.0 or later. If the parameter group pins `planner_version` to 1.0, retryable writes do not work.
- If you need to keep planner v1 for compatibility, set `planner_version` to 1.0 in the custom group. You then lose views, collation, `$merge`, and the other v3-only features. The parameter reference describes 1.0 and 2.0 as "Supported in Amazon DocumentDB 5.0". The planner v3 page implies that 8.0 accepts other values: it says to revert to v3 "if you changed your default query planner in 8.0" and tells global clusters to use the same value (1.0, 2.0 or 3.0) in both Regions. Check the values your Region accepts with `aws docdb describe-engine-default-cluster-parameters --db-parameter-group-family docdb8.0 --query "EngineDefaults.Parameters[?ParameterName=='planner_version']"`.

After the upgrade, wait for the index metadata refresh event before you reboot, fail over, or scale (see [index.md](index.md#generic-procedure)).

## Managed Service Notes

- Global clusters work on 8.0. The release notes from August 2024 say switchover and managed failover are supported "on 4.0 and 5.0 only", and no later note extends them to 8.0. The disaster-recovery page does not restrict them by version. Before you rely on switchover on 8.0, run `aws docdb switchover-global-cluster` on a test 8.0 global cluster.
- No elastic clusters and no LTS on 8.0 as of 2026-11-27.
