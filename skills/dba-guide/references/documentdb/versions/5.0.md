# Amazon DocumentDB 5.0

Checked: 2026-11-27. Read this when a cluster reports `EngineVersion` `5.0.x` or a patch version `3.0.x`, when you choose between 5.0 LTS and 8.0, or when you upgrade into 5.0 from 3.6 or 4.0.

## Lifecycle

| Item | Value |
| --- | --- |
| Release | 1 Mar 2023 (engine patch 3.0.775) |
| End of standard support | Not announced (N/A on the [lifecycle page](https://docs.aws.amazon.com/documentdb/latest/devguide/docdb-version-support-dates.html)) |
| LTS | Minor version 5.0.0 with patch 3.0.17983 or later. LTS receives only critical stability and security patches, with no new features |
| Minor versions | 5.0.0 (LTS), 5.0.1 (8 Jun 2026), 5.0.2 (28 Sep 2026, release notes only; the lifecycle calendar does not list it) |

LTS decision: stay on 5.0.0 when upgrade windows are scarce and you already have every feature you need. Move to 5.0.1 or 5.0.2 (or 8.0) when you need their features, such as SCRAM-SHA-256, `$rand`/`$pow`, hidden indexes, or `cursor.min()`/`max()`. Every minor upgrade is one-way. AWS notes that no LTS has been designated for 8.0.

## Changed Defaults

Compared with 4.0 ([compatibility page](https://docs.aws.amazon.com/documentdb/latest/devguide/compatibility.html#mongodb-50)):

| Item | 4.0 | 5.0 |
| --- | --- | --- |
| Role discovery command | `isMaster` | `hello` |
| Delay field in `replSetGetConfig` | `slaveDelay` | `SecondaryDelaySecs` |
| `backup` built-in role | no `serverStatus` | includes `serverStatus` |
| Default query planner | v1 | v1. Planner v2 can be selected from patch 3.0.15902 on |
| `default_collection_compression` | n/a | `disabled`; set it to `enabled` for LZ4 |
| Minimum TLS with `tls=enabled` | TLS 1.0 to 1.3 accepted | 5.0.0: TLS 1.0 to 1.3. 5.0.1 and later: TLS 1.2 or later only |
| Max storage | 64 TiB (since 2022) | 128 TiB |
| Collection / index name length | 57 / 63 characters | 255 / 255 characters (5.0 and later) |
| Read availability during patching | none | Readers are patched in a rolling fashion. Reads stay available if the read preference can fall back |

## Removed or Deprecated

- 5.0.1 and later accept only TLS 1.2 or later. Clients limited to TLS 1.0 or 1.1 fail to connect after a minor upgrade from 5.0.0.

## Upgrading Into This Series

From 3.6 or 4.0, use in-place MVU to any published 5.0 minor, or DMS. Query-result changes compared with 4.0 ([compatibility page](https://docs.aws.amazon.com/documentdb/latest/devguide/compatibility.html#mongodb-50)):

1. A nested `$elemMatch` inside `$elemMatch` matches only the first array nesting level. Results can shrink. Example: `{a: {$elemMatch: {b: {$elemMatch: {$lt: 6, $gt: 4}}}}}` no longer matches `{a: [[{b: [5]}]]}`.
2. A `find` with a `$` positional projection returns only the matched field, instead of every field.
3. A query that sets options both inside `$regex` and in `$options` now fails with "Cannot set options in both $regex and $options".
4. `$indexOfCP` returns `-1` (previously `0`) when the start is greater than the end or beyond the byte length.
5. Projecting a nested `_id` field, such as `{"_id.nestedField": 1}`, now returns only that field.
6. Drivers must be compatible with MongoDB 5.0 or later.
7. Driver code that reads `isMaster` or `slaveDelay` must read `hello` or `SecondaryDelaySecs`.

Checks:

- Run the 4.0 test suite against a clone that has been upgraded to 5.0. Diff the results of the queries that use the shapes listed above.
- After an in-place MVU from 3.6 or 4.0, optionally run `reIndex` to pick up 5.0 index maintenance. `reIndex` does not support text, geospatial, vector, or partial indexes.
- A bug kept storage from being reclaimed after an MVU to 5.0. The 17 Sep 2024 release notes fix it in 5.0 patch 3.0.10696 and in 4.0 patch 2.0.10898. If the source is 4.0, apply 2.0.10898 or later before the MVU; after the MVU, make sure the 5.0 cluster is on 3.0.10696 or later.
- If you choose 5.0.1 or later, confirm that every client negotiates TLS 1.2 or later.

## Managed Service Notes

- Elastic clusters use the 5.0-compatible wire protocol. This makes 5.0 the only series whose instance-based behavior is close to elastic clusters. Elastic clusters still lack transactions, change streams, unique indexes, and other features; see [compatibility.md](../compatibility.md#elastic-clusters).
- IAM authentication is documented only for instance-based 5.0 on the IAM page. The features table also marks 8.0 as supported (conflict, see [compatibility.md](../compatibility.md#documentation-conflicts)).
