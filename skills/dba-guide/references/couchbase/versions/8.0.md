# Couchbase Server 8.0

Checked: 2026-11-27. Read this when a cluster runs 8.0.x, when you plan an upgrade from 7.2 or 7.6 to 8.0, or when a script, default, or metric behaves differently after the upgrade.

## Lifecycle

- GA October 2025. Full Maintenance and End of Life: October 2028 (lifecycle page).
- Maintenance releases so far: 8.0.1 (March 2026), 8.0.2 (June 2026), 8.0.3 (September 2026), 8.0.4 (November 2026).
- Run 8.0.3 or later if any bucket was created before 5.0 and never edited. MB-72097 could switch such a bucket to Magma during the upgrade. It is fixed in 8.0.2 and listed again in 8.0.3, and the 8.0.2 notes link a `fix_undefined_storage_mode scan` script.
- Capella offers 8.0 for new clusters, and new free-tier clusters use 8.0.

## Changed Defaults

| Setting | 7.6 behavior | 8.0 behavior | Evidence |
|---|---|---|---|
| Storage engine for a new bucket with no `storageBackend` (EE) | Couchstore, 1024 vBuckets, `valueOnly` | Magma, 128 vBuckets, `fullEviction` | Upgrade page; container: `bucket-create` with no backend gave `"storageBackend":"magma","numVBuckets":128,"evictionPolicy":"fullEviction"` on 8.0.4 and `couchstore`/1024/`valueOnly` on 7.6.13 |
| `storageBackend=magma` with no `numVBuckets` | 1024 vBuckets | 128 vBuckets | Upgrade page |
| Magma minimum bucket quota | 1 GiB per node | 100 MiB per node with 128 vBuckets; still 1 GiB with 1024 | Storage Engines page |
| Warmup after a bucket restart | Blocking: fully available after loading up to the low watermark | `warmupBehavior=background`: available once metadata loads, then the cache fills in the background | Release notes MB-9418 |
| `ro_admin` role | Can read security settings, users, and groups | Cannot. Security reads move to the new `ro_security_admin`, which upgrade grants to existing `ro_admin` users | Roles page; 8.0.1 MB-70597, MB-70629 |
| Node-to-node authentication when N2N encryption is on | Basic auth | Mutual TLS | MB-50939 |
| Audit log file | `audit.log` is a real file that is renamed on rotation | `audit.log` is a symlink to the file being written | MB-62295 |
| Incremental backup removal | Allowed even when later incrementals depend on it | Blocked unless `--disable-safe-remove-check` | MB-60337 |
| Writes with a CAS too far in the future | Accepted before 7.6.13. 7.6.13 also lists the fix. | Rejected beyond `hlc_max_future_threshold` (65 minutes; 8.0.4 bucket JSON shows `"hlcMaxFutureThreshold":3900`, the 7.6.13 JSON has no such field) | MB-61385 in 8.0 and 7.6.13 notes |
| Subdoc get on a locked document | Returns `LOCKED` | Returns `SUCCESS` with CAS `0xffffffffffffffff` | MB-66015 |
| Bucket priority (high/low) | Affects scheduling | No effect. Removed from the UI, still accepted by REST and CLI | MB-67280 |
| `deferBuild` in `GET /settings/indexes` | Field absent in the 7.6.13 container (the 7.6.2+ default can be changed through the indexer setting `indexer.settings.defer_build`) | Field present, `false` | Container output; CREATE INDEX page |

## Removed or Deprecated

- Memcached buckets are removed. The upgrade refuses to proceed while one exists. Replace them with Ephemeral buckets first.
- `cbepctl` no longer sets `access_scanner_enabled`, `exp_pager_stime`, `warmup_min_items_threshold`, `warmup_min_memory_threshold`, the secondary warmup thresholds, `mem_high_wat`, or `mem_low_wat`. Use the bucket REST parameters `accessScannerEnabled`, `expiryPagerSleepTime`, `warmupBehavior`, `memoryLowWatermark` (50–89, default 75), and `memoryHighWatermark` (51–90, default 85).
- `GET /pools/default/buckets/<bucket>/stats` and the per-destination XDCR stats endpoint are deprecated. Use `GET /pools/default/stats/range/<metric>[/<function>]` or `POST /pools/default/stats/range`.
- Metric `kv_vb_ht_memory_bytes` is deprecated in favor of `kv_vb_ht_memory_overhead`. Both are emitted in 8.0.
- The "Cache Miss Ratio" UI metric is renamed "Get Miss Ratio". It measures gets for keys that do not exist, not disk fetches.
- `mcstat` no longer takes several stat groups in one call (`mcstat ... vbucket-details 1` replaces the quoted form) and ignores `--json=pretty`. Pipe to `jq` instead.
- Platforms dropped: Amazon Linux 2, macOS 12, SLES 12, Ubuntu 20.04, Windows 10, Windows Server 2019.
- On x86-64, CPUs without AVX2 are no longer supported: the server exits with an error at start. AVX2 was deprecated in 7.6.3.
- Views remain deprecated (since 7.0) and do not run on Magma.

## Worth Adopting

- Magma with 128 vBuckets for small or medium buckets that do not fit in memory. It has a 100 MiB floor and a 1% memory-to-data ratio. Prefer 1024 vBuckets for multi-terabyte buckets, heavy durable-transaction workloads, or any bucket that receives XDCR from a pre-8.0 cluster. See [configuration-and-sizing.md](../configuration-and-sizing.md).
- Change the ejection policy without a bucket restart (`evictionPolicy=...&noRestart=true`, then a swap rebalance or graceful failover plus recovery per node). On Ephemeral buckets the change applies immediately.
- `durabilityImpossibleFallback=fallbackToActiveAck` per bucket. It keeps durable writes and transactions succeeding while a single-replica bucket lacks a majority, for example during a graceful-failover upgrade. It weakens durability to an asynchronous write, so turn it off right afterwards. See [transactions-and-durability.md](../transactions-and-durability.md).
- Filesystem usage limit for the Data Service path (off by default). It stops writes before the disk fills.
- Native encryption at rest (EE) for bucket, log, audit, and configuration data, with KMIP or AWS KMS keys. Bucket setting `encryptionAtRestKeyId` defaults to `-1` (unencrypted). In the 8.0.4 container, `/pools/default` reported configuration data as `"encrypted"` with no setup, while logs and audit were unencrypted.
- Add or remove non-Data services on an existing node (`index`, `n1ql`, `fts`, `cbas`, `eventing`, `backup`), with an automatic rebalance.
- Auto-failover for nodes holding unreplicated Ephemeral buckets (`allowFailoverEphemeralNoReplicas`, off by default) and failover on data-disk non-responsiveness (`failoverOnDataDiskNonResponsiveness`, off by default). Both are fields in `GET /settings/autoFailover` (container).
- Security: Hybrid client-certificate mode, client certificates combined with node-to-node encryption, local user lock and unlock, forced password change, and last-activity tracking for local users (EE).
- Query: Auto Update Statistics (EE, opt-in). Negative hints `NO_INDEX`, `NO_INDEX_FTS`, `NO_USE_NL`, `NO_USE_HASH` (the 7.6.13 container already followed `NO_INDEX`; see [indexes-and-queries.md](../indexes-and-queries.md)). Hints on `DELETE`, `UPDATE`, and `MERGE`. Auto-reprepare of prepared statements when index metadata changes. Completed-request logging qualifiers `statement` and `plan`.
- Hyperscale and Composite vector indexes in GSI (`CREATE VECTOR INDEX`, `APPROX_VECTOR_DISTANCE`).
- XDCR: conflict logging for active-active, a view of incoming replications, and `xdcrDiffer` bundled with the server (present in the 8.0.4 container, absent in 7.6.13). 8.0.3 adds a `forwardLocalOnly` replication setting.
- Backup Service retention periods and prune tasks. `cbbackupmgr restore --auto-resolve-conflicts` for scope and collection ID clashes.

## Upgrading Into This Series

From 7.6.x or 7.2.x the upgrade is direct (any 7.2.x or 7.6.x → any 8.0.x). Check these before the first node moves:

1. Memcached buckets: none may exist. `curl -s -u ... :8091/pools/default/buckets | jq '.[] | select(.bucketType=="memcached") | .name'` must return nothing.
2. Bucket-creation scripts: any script that omits `storageBackend` now creates Magma/128 buckets. Views fail on them. XDCR from a pre-8.0 cluster into them is impossible, because pre-8.0 sources need matching vBucket counts and do not support 128. Set `storageBackend=couchstore` or `storageBackend=magma&numVBuckets=1024` explicitly where needed. Community Edition behaves differently; see the Community note in [configuration-and-sizing.md](../configuration-and-sizing.md).
3. AVX2 on every x86-64 node.
4. Client-certificate authentication combined with node-to-node encryption: disable client-cert auth before the upgrade and re-enable it once every node, in particular every Index Service node, runs 8.0 (upgrade page; MB-52097). Otherwise the rebalance that adds the first upgraded Index node fails. The upgrade page gives `couchbase-cli ssl-manage ... --set-client-auth-state disabled` for this, but `ssl-manage -h` in the 7.6.13 and 8.0.4 images has no `--set-client-auth-state`. It offers `--set-client-auth <path>` (a file with the client auth configuration) instead. Clusters with pre-7.6 out-of-the-box CA certificates must regenerate them before enabling client-cert auth with N2N encryption (MB-47905).
5. RBAC: after upgrade, or after restoring users from a pre-8.0 backup, check users and groups that held `security_admin_local`, `security_admin_external`, or `ro_admin`. 8.0.1 MB-70629 says groups were not converted correctly and must be fixed by hand. The new role IDs are `user_admin_local`, `user_admin_external`, and `ro_security_admin`; see [security.md](../security.md).
6. Magma buckets coming from before 7.6.7 (or 7.2.7): follow MB-67762 before upgrading (integer overflow after roughly 500 billion to 2 trillion mutations per bucket).
7. Pre-5.0 buckets: target 8.0.3 or later (MB-72097).
8. Index shard assignment changed (MB-63192): plasma shards are shared more aggressively. Rehearse index build and rebalance times. The behavior is behind a feature flag.
9. XDCR: do not change `filterExpression`, `collectionsExplicitMapping`, or `collectionsMigrationMode` until every node runs 8.0 (MB-66140).
10. Scripts that read `cbepctl` warmup or watermark settings, or the deprecated stats endpoints, must move to the bucket REST parameters and `/pools/default/stats/range`.
11. For `cbbackupmgr` 8.0.0 restoring into 7.6 or earlier with `--auto-create-buckets`, use 8.0.1 or later (MB-70235).
12. Rollback window: before the last node is upgraded you can still downgrade online. Add a 7.6 arbiter node to hold the cluster unfinalized while you test.

## Managed Service Notes

- MB-63192 notes that for Capella upgrades to 8.0 all shards may already exist, so vector indexes may need additional shards depending on resources.
- Capella runs maintenance upgrades in a window it schedules; see [managed-services.md](../managed-services.md).
