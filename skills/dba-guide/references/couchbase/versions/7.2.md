# Couchbase Server 7.2

Checked: 2026-11-27. Read this when a cluster still runs 7.2.x (End of Life) and you need its upgrade path, or when a behavior seen on 7.2 differs from this reference.

## Lifecycle

- GA June 2023. Full Maintenance and End of Life: July 2026. On 2026-11-27 the series is past End of Life, with no fixes or security updates.
- The latest maintenance release listed in the 7.2 release notes is 7.2.8 (August 2025). If a cluster reports a later 7.2 build, read its release notes before relying on this file.
- 7.2.4 (January 2024) moved to Erlang 25. Clusters older than 7.1 cannot upgrade directly to 7.2.4 or later. 7.2.3 is the intermediate stop for 6.x and 7.0 clusters.

## Changed Defaults

- TLS 1.0 and 1.1 are deprecated in 7.2 (removed in 7.6).
- Node certificates are validated for a Subject Alternative Name matching the node name when uploaded and when a node joins. Upgrades from earlier versions can fail if the SAN is missing.
- 7.2.4 upgraded OpenSSL to 3.1.4, which changes the available ciphers. Test old clients.
- 7.2.4: after a lock timeout, a document's CAS reverts to its original value instead of the all-ones locked value (MB-59746).
- From 7.2.8 and 7.6.7, on Linux with cgroups v1, the installer sets `memory.swappiness=0` for the `couchbase-server` slice. On cgroups v2 set kernel swappiness to 0 yourself (MB-57755).

## Removed or Deprecated

- Platforms no longer supported in 7.2: SLES 12 before SP2, macOS 10.15, RHEL 7, CentOS 7, Oracle Linux 7, Ubuntu 18. Deprecated in 7.2: SLES 12, macOS 11, Debian 10.
- `/prometheus_sd_config.yaml` is deprecated in favor of `/prometheus_sd_config` (7.2.1+).

## Worth Adopting

These features first appear in 7.2 and still apply on 7.6 and 8.0:

- Magma change history per collection (bucket-level `historyRetention*` defaults). It feeds the Kafka connector.
- Magma block size at bucket creation (`magmaSeqTreeDataBlockSize`; the whole cluster must run 7.2+).
- Prometheus service discovery endpoint `/prometheus_sd_config`, and failover and rebalance metrics: `cm_auto_failover_count`, `cm_auto_failover_enabled`, `cm_auto_failover_max_count` in 7.2; `cm_failover_total`, `cm_graceful_failover_total`, `cm_is_balanced`, `cm_rebalance_in_progress`, `cm_rebalance_total` in 7.2.6.
- Audit log pruning (`pruneAge` on `/settings/audit`, 7.2.4+).
- Alert when memcached connections exceed 90% of the limit (7.2.4).
- Standalone tools package with `cbbackupmgr`, `cbimport`, `cbexport`, and `cbq`, and `network=external` host option for those tools.
- Search (FTS) replica partition catch-up tracking on rebalance (`enableReplicaCatchupOnRebalance`, listed under What's new in 7.2; off by default, adds rebalance overhead, only when `disableFileTransferRebalance` is `false`).

## Upgrading Into This Series

Upgrading into 7.2 is only relevant as an intermediate hop:

- From 6.x or 7.0: upgrade to 7.2.3 (not later), then go to 8.0.x (or 7.6.x).
- From 7.1: the 7.6 upgrade table allows 7.1 → 7.6.x directly. The 8.0 upgrade table routes 7.1 through 7.2.3 → 8.0.

Leaving 7.2:

- 7.2.x → 8.0.x is a supported direct path. Read [8.0](8.0.md) "Upgrading Into This Series". Watch the default storage-engine change: a 7.2 cluster cannot replicate by XDCR into an 8.0 Magma bucket that has 128 vBuckets.
- 7.2.x → 7.6.0 or 7.6.1 with Index nodes requires swap rebalance (MB-62547). Prefer the newest 7.6.x or go straight to 8.0, since 7.6 reaches End of Life in March 2027.
- Magma buckets on releases before 7.2.7: follow MB-67762 before upgrading (mutations can become invisible after roughly 500 billion to 2 trillion mutations per bucket). The 7.2 banner says "prior to 7.2.7", while the fix entry appears under 7.2.8. Use 7.2.8 or later as the safe source version.
- A backup taken on 7.2 and restored to 7.6+ may need `--map-data bucket.scope=bucket.scope` because of the `_system` scope.
