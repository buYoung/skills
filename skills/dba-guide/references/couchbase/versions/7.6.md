# Couchbase Server 7.6

Checked: 2026-11-27. Read this when a cluster runs 7.6.x, when you upgrade from 7.2 to 7.6, or when you plan the move from 7.6 to 8.0 before 7.6 reaches End of Life.

## Lifecycle

- GA March 2024. Full Maintenance and End of Life: March 2027 (lifecycle page). The 7.6 release notes give the End of Life date as March 31, 2027.
- Latest maintenance release on the check date: 7.6.13 (November 2026). Earlier ones: 7.6.12 (July 2026), 7.6.11 (April 2026), 7.6.10 (February 2026), 7.6.9 (January 2026), 7.6.8 (November 2025), 7.6.7 (August 2025), 7.6.6 (May 2025), 7.6.5 (January 2025), 7.6.4 (December 2024), 7.6.3 (September 2024), 7.6.2 (July 2024), 7.6.1 (April 2024), 7.6.0 (March 2024).
- Avoid 7.6.0 and 7.6.1 for clusters with Index Service nodes upgraded from 7.1 or 7.2 except by swap rebalance (MB-62547: offline or failover/delta upgrades corrupted indexes). Avoid 7.6.8 if you use Eventing basic accessors (release notes advisory, fixed in 7.6.9).
- Capella still offers 7.6 for new clusters, as the "previous" version.

## Changed Defaults

| Setting | 7.2 behavior | 7.6 behavior | Evidence |
|---|---|---|---|
| Minimum TLS version | `tlsv1`/`tlsv1.1` allowed but deprecated | TLS 1.0 and 1.1 removed. Upgrade raises `tlsMinVersion` to `tlsv1.2`. | 7.6 What's New; container `"tlsMinVersion":"tlsv1.2"` |
| Default TLS cipher list | Includes some CBC-SHA suites | Four CBC-SHA suites removed (LUCKY13) | 7.6 What's New |
| Password hash for new users | SHA1-based | Argon2id. Existing hashes stay until migration is enabled (`allowHashMigrationDuringAuth`, false by default in the container) | 7.6 What's New; container `"passwordHashAlg":"argon2id"` |
| `_system` scope | Absent | Created in every user and sample bucket, with `_mobile` and `_query` collections that cannot be dropped | Scopes and Collections page |
| Auto-failover minimum timeout via REST | 5 s | 1 s (the UI still requires 5 s; below 5 s the UI cannot edit cluster settings, MB-60062) | 7.6 What's New; Automatic Failover page |
| Query statistics for CBO | Gathered only by `UPDATE STATISTICS` | Also gathered automatically when an index is created or built | 7.6 What's New |
| ORDER BY and GROUP BY over quota | Fail | Spill to disk | 7.6 What's New |
| `sendStats=false` on Community Edition | Allowed | Not allowed (EE still allows it) | 7.6 What's New |

## Removed or Deprecated

- Removed: TLS 1.0/1.1, the `cbbackup` and `cbrestore` utilities (use `cbbackupmgr`), and password-less buckets (SQL++ requires authentication).
- Removed platforms: CentOS 7, Debian 10, macOS 11, RHEL 7. Deprecated in 7.6: Amazon Linux 2, Windows Server 2019, Ubuntu 20.04, SLES 12, macOS 12. All five are removed in 8.0.
- Deprecated in 7.6.3: x86 CPUs without AVX2 (required in 8.0). Deprecated in 7.6.4: Windows 10.
- `/prometheus_sd_config.yaml` is deprecated in favor of `/prometheus_sd_config`. The change arrived in 7.2.1; the 7.6 What's New repeats it.
- Linux package repositories: install `couchbase-release` 1.0-13 before upgrading to 7.6.0 or later.

## Worth Adopting

- Bucket storage-engine migration (Couchstore ↔ Magma) while online. Change `storageBackend`, then swap rebalance, or graceful failover plus full recovery, each node. See [configuration-and-sizing.md](../configuration-and-sizing.md).
- Arbiter nodes (nodes with no services). They give faster failover when the orchestrator node fails, quorum for two-server-group layouts, and a way to hold an upgrade unfinalized.
- Bucket `rank` (0–1000) to rebalance critical buckets first.
- Replica minimum per cluster (`minReplicasCount`, 0 in the container).
- File-based index rebalance (move index files instead of rebuilding).
- Users and groups in backups (`cbbackupmgr config --enable-users`, `restore --enable-users [--overwrite-users]`). Encrypted backups are GA.
- Audit `pruneAge` for rotated audit logs. It is documented as new in 7.6 What's New, and the 7.2 notes list it for 7.2.4.
- Certificate expiry alerts (`certExpirationDays`). PKCS#12 node certificates. SAML for the Web Console. LDAP regex mapping.
- Query: sequential scans without any index (RBAC role `query_use_sequential_scans`). Read from replica vBuckets when actives are unavailable (`use_replica`, `queryUseReplica`). Recursive CTEs (`WITH RECURSIVE`). Sequences. `EXPLAIN FUNCTION`. `system:indexes` shows replica counts. `queryPreparedLimit`. Completed-request streaming to disk (`completed-stream-size`, 7.6.4+). Auto-reprepare (7.6.10+, opt-in via `n1ql-feat-ctrl` bit 0x800000).
- Collections: `maxTTL` can be changed after creation, and `maxTTL=-1` exempts a collection from the bucket's TTL.
- KV range scan and subdoc operations on multiple xattrs.
- Search Service vector search (Linux only in 7.6.0).
- XDCR connection pre-check and binary-document filtering. Since 7.6.6: `enableCrossClusterVersioning` (one-way; see [replication-and-xdcr.md](../replication-and-xdcr.md)).

## Upgrading Into This Series

From 7.2.x the upgrade is direct. Check:

1. If Index Service nodes exist and the target is 7.6.0 or 7.6.1, use swap rebalance only. Better, target the latest 7.6.x.
2. Clients must support TLS 1.2. Test client TLS libraries against the new OpenSSL cipher set (OpenSSL 3.1.4 arrived in 7.2.4 and 7.6).
3. .NET SDK must be 3.5.1 or later.
4. Linux repo package `couchbase-release` must be 1.0-13.
5. Restores of pre-7.6 backups into 7.6 can collide with the `_system` scope's IDs. Map the scope to itself with `--map-data bucket.scope=bucket.scope` when you see `scope ... exists with a different name/id`.
6. Magma buckets: if coming from before 7.2.7, follow MB-67762 (the 7.2 banner) and upgrade to 7.6.7 or later.
7. Flushing a bucket on 7.6 deletes scope-level UDFs, sequences, and CBO statistics stored in `_system._query` (MB-64966). Recreate them and rerun `UPDATE STATISTICS` after any flush.
8. After the upgrade, decide whether to enable password hash migration. It requires every node on 7.6.

Planning 7.6 → 8.0: see [8.0](8.0.md). Do it before March 31, 2027.

## Managed Service Notes

- Capella cluster backups can be copied to other regions (AWS and Azure) only on 7.6.6 or later. Cross-cluster restore of cluster backups requires 7.6.6 or later on both clusters. See [managed-services.md](../managed-services.md).
- Auto-reprepare must be enabled by Capella Support on Capella (7.6.10 note).
