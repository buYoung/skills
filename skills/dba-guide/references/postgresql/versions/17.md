# PostgreSQL 17

Checked: 2026-11-27 against https://www.postgresql.org/docs/release/17.0/ and https://www.postgresql.org/support/versioning/.

Read this when the server reports `server_version_num` 170000 to 179999, or when upgrading into 17.

## Lifecycle

- First release 17.0 on 2024-09-26; current minor 17.12; community support until 2029-11-08.
- Amazon RDS: end of standard support 2030-02-28; Extended Support until 2033-02-28. Latest RDS minor: 17.12 (RDS release 2026-11-26).
- Aurora PostgreSQL: available since 2025-05-01 (from 17.4); end of standard support 2030-02-28; Extended Support until 2033-02-28; Aurora LTS minor 17.7 (supported until 2030-02-28).

## Changed Defaults

| Setting or behavior | Before 17 | 17 | Action |
| --- | --- | --- | --- |
| `vacuum_buffer_usage_limit` | 256kB | 2MB | Vacuum's ring buffer is larger; usually leave it. |
| Vacuum memory | silently capped at 1GB | no cap; uses `maintenance_work_mem`/`autovacuum_work_mem` fully with a compact dead-tuple store | Large `maintenance_work_mem` values now take effect; size them against RAM and `autovacuum_max_workers`. |
| Maintenance `search_path` | caller's | safe `search_path` during `ANALYZE`, `CLUSTER`, `CREATE INDEX`, `REFRESH MATERIALIZED VIEW`, `REINDEX`, `VACUUM` | Functions used in expression indexes or materialized views that reference non-default schemas must set `search_path` in their definition, or those operations fail. |
| `pg_walfile_name()` on a segment boundary | previous segment | current segment | Adjust archive tooling that depends on boundary behavior. |

## Removed or Deprecated

- `old_snapshot_threshold` removed ("snapshot too old" feature gone). Remove it from config before upgrading or the server refuses to start with an unrecognized parameter.
- `db_user_namespace` removed; `adminpack` extension removed; `trace_recovery_messages` removed.
- `pg_stat_bgwriter` loses checkpoint columns and `buffers_backend`, `buffers_backend_fsync`; checkpoint data moves to the new `pg_stat_checkpointer`. Container: 14 still shows `checkpoints_timed` in `pg_stat_bgwriter`; 17 shows only `buffers_clean`, `maxwritten_clean`, `buffers_alloc`.
- `pg_stat_statements.blk_read_time`/`blk_write_time` renamed `shared_blk_read_time`/`shared_blk_write_time`.
- `pg_stat_progress_vacuum` columns renamed (`max_dead_tuple_bytes`, `num_dead_item_ids`, new `dead_tuple_bytes`).
- `SET SESSION AUTHORIZATION` uses the session user's superuser status at the time of the command.

## Worth Adopting

- Incremental backup: `summarize_wal = on`, then `pg_basebackup --incremental=<previous backup_manifest>`; reconstruct with `pg_combinebackup`. See [backup-and-recovery.md](../backup-and-recovery.md).
- Failover slots: `pg_create_logical_replication_slot(..., failover => true)` or `CREATE SUBSCRIPTION ... WITH (failover = true)`, `sync_replication_slots = on` on the standby, `synchronized_standby_slots` on the primary. Lets logical subscribers continue after a physical failover. See [replication-and-ha.md](../replication-and-ha.md).
- pg_upgrade preserves logical slots and subscriptions, but only when the old cluster is 17 or later. Upgrades from 17 onward no longer need slot re-creation and table resync.
- `pg_createsubscriber` converts a physical standby into a logical replica, avoiding the initial table copy.
- `transaction_timeout` caps total transaction duration.
- `MAINTAIN` privilege and `pg_maintain` role: delegate `VACUUM`, `ANALYZE`, `REINDEX`, `REFRESH MATERIALIZED VIEW`, `CLUSTER`, `LOCK TABLE` without ownership.
- `allow_alter_system = off` blocks `ALTER SYSTEM` where configuration is managed externally.
- `MERGE ... RETURNING` with `merge_action()`, `WHEN NOT MATCHED BY SOURCE`, `MERGE` on updatable views. Container confirms `merge_action()` on 17.
- `JSON_TABLE()` and SQL/JSON constructors.
- `COPY ... (ON_ERROR ignore)` skips bad rows; `LOG_VERBOSITY`.
- `EXPLAIN (SERIALIZE)`, `EXPLAIN (MEMORY)` (container: rejected on 14, accepted on 17).
- `pg_wait_events` view with descriptions; `pg_replication_slots.inactive_since` and `invalidation_reason`; `pg_stat_progress_vacuum.indexes_total`/`indexes_processed`.
- B-tree `IN (...)` lookups and streaming reads speed up common access paths without configuration.
- Builtin collation provider (`C`, `C.UTF-8`) that does not depend on the OS C library, which removes the glibc-collation-change reindex risk for databases that can use code-point ordering.
- Client option `sslnegotiation=direct` saves a round trip.

## Upgrading Into This Series

From 16 (or older):

- Remove `old_snapshot_threshold`, `db_user_namespace`, `trace_recovery_messages` from configuration; drop `adminpack`.
- Add `SET search_path = ...` to functions used by expression indexes and materialized views: `SELECT DISTINCT p.oid::regprocedure FROM pg_depend d JOIN pg_proc p ON p.oid = d.refobjid WHERE d.refclassid = 'pg_proc'::regclass AND d.classid IN ('pg_class'::regclass, 'pg_rewrite'::regclass) AND p.proconfig IS NULL AND p.pronamespace NOT IN ('pg_catalog'::regnamespace, 'information_schema'::regnamespace);` is a starting point (it also lists functions used by plain views; review results by hand), and the rehearsal copy is the real test: run `REINDEX` and `REFRESH MATERIALIZED VIEW` there.
- Update monitoring for `pg_stat_bgwriter` and `pg_stat_statements` column changes.
- Logical replication from 14, 15, or 16: pg_upgrade drops slots and subscription positions. Either drop and re-create subscriptions after the upgrade (with a full table resync), or use the logical replication upgrade method instead.

## Managed Service Notes

- RDS and Aurora: on source version 17 and later, logical replication slots can be kept through a major upgrade (RDS: slots on non-replica instances only). Consume all pending changes first, or the upgrade fails. Aurora also requires `rds.logical_replication = 1` in the target cluster parameter group.
- RDS: upgrading directly to 17 with `rdkit` 4.6.0 or lower requires first moving to 14.14+, 15.9+, or 16.5+.
