# PostgreSQL 19

Checked: 2026-11-27 against https://www.postgresql.org/docs/release/19.0/ and https://www.postgresql.org/support/versioning/.

Read this when the server reports `server_version_num` 190000 or higher, or when planning an upgrade into 19.

## Lifecycle

- First release 19.0 on 2026-11-19; community support until 2031-11-19.
- Not available on Amazon RDS or Aurora on 2026-11-27. RDS adds a major within 30 days of `<major>.1`; Aurora within 8 months of `<major>.1`. 19.1 had not been released on the check date.
- Treat 19.0 as a first release: wait for at least one minor release on critical systems unless a 19 feature is required, and rehearse on a copy.

## Changed Defaults

| Setting or behavior | 18 | 19 | Action |
| --- | --- | --- | --- |
| `jit` | `on` | `off` | Analytical workloads that relied on JIT must set `jit = on` explicitly. Container: `SHOW jit` returns `off` on 19.0, `on` on 18.7. |
| `default_toast_compression` | `pglz` | `lz4` | Applies to newly written TOAST values only; existing data is not recompressed. Builds without lz4 support cannot use it. Container shows `lz4`. |
| `max_locks_per_transaction` | 64 | 128 | Lock table sizing changed: a value carried over from an older `postgresql.conf` must be doubled to keep the same capacity. Check this after every upgrade that copies the old config. |
| `io_workers` | `3` (exists) | removed | Replaced by `io_min_workers` (2), `io_max_workers` (8), `io_worker_idle_timeout` (60s), `io_worker_launch_interval` (100ms). A config file that still sets `io_workers` produces an unrecognized-parameter error on start; remove it. Container: `SHOW io_workers` fails on 19.0. |
| `log_lock_waits` | `off` | `on` | Expect lock-wait messages after `deadlock_timeout` (1s). Container `boot_val` is `on` in 19, `off` in 18; started without `-c` overrides, the setting is `on` (source `default`) on 19.0 and `off` on 13 to 18. |
| `log_autovacuum_min_duration` | covers vacuum and analyze | covers autovacuum vacuum only | Set the new `log_autoanalyze_min_duration` (default 10min) for auto-analyze logging. |
| `wal_compression = on` | always `pglz` | best available method | Set an explicit method (`lz4`, `zstd`, `pglz`) if you need determinism. |
| `standard_conforming_strings` | settable | always `on` | Dumps produced by older pg_dump with this setting `off` do not load. Re-dump with the 19 pg_dump. `escape_string_warning` is removed. |
| Parallel vacuum cost limit | each worker had its own budget | leader and workers share `vacuum_cost_limit` | Parallel `VACUUM` with cost delay can run slower than in 18; raise the limit deliberately if needed. |
| Wraparound warnings | at 40 million XIDs remaining | at 100 million remaining | Warnings appear earlier; act on them. |
| Autovacuum table order | `pg_class` order | scored priority (new `*_score_weight` settings, default 1) | Set all five weights to 0 to restore pre-19 ordering. |

## Removed or Deprecated

- RADIUS authentication removed. Migrate `radius` lines in `pg_hba.conf` before upgrading.
- MD5 passwords: deprecated since 18; 19 also warns after each successful MD5 authentication (disable with `md5_password_warnings = off`). New `password_expiration_warning_threshold` (default 7 days) warns users of `VALID UNTIL` expiry.
- `MULE_INTERNAL` encoding removed; dump and restore such databases with another encoding.
- Default opclass for `inet`/`cidr` GiST indexes is now the core GiST opclass, not `btree_gist`; pg_upgrade refuses clusters that have `btree_gist` `inet`/`cidr` indexes. Drop or rebuild them with the core opclass (`inet_ops`) first.
- Carriage returns and line feeds are no longer allowed in database, role, and tablespace names; pg_upgrade refuses such clusters.
- Wait event renames: type `BUFFERPIN` to `BUFFER`, event `BufferPin` to `BufferCleanup`; `BufferContent` replaced by `BufferShared`, `BufferShareExclusive`, `BufferExclusive`. Update monitoring queries and dashboards.
- `pg_stat_subscription_stats.sync_error_count` renamed `sync_table_error_count`.
- `json_array()` over zero rows returns `[]`, not `NULL`.
- `READ ONLY` and `DEFERRABLE` now propagate to postgres_fdw remote sessions, so read-only transactions can no longer modify remote rows.
- Full text search and pg_trgm classify characters with the database's locale provider; after pg_upgrade of ICU or builtin-provider databases, reindex FTS and pg_trgm indexes and recompute stored `tsvector` values. Reindex indexes using `fuzzystrmatch` functions too.
- `VACUUM FULL` and `CLUSTER` remain for compatibility; `REPACK` is the replacement.

## Worth Adopting

- `REPACK` and `REPACK (CONCURRENTLY)`: rewrite a bloated table to return space to the OS. Without `CONCURRENTLY` it holds `ACCESS EXCLUSIVE` for the whole run. With `CONCURRENTLY`, most of the work runs under `SHARE UPDATE EXCLUSIVE` and `ACCESS EXCLUSIVE` is held only for the final swap. Restrictions: the table needs a primary key or index-based replica identity, cannot be partitioned, unlogged, a catalog, or non-heap; it cannot run inside a transaction block; it uses a replication slot counted against `max_repack_replication_slots` (default 5); the command fails if more than about 104 million rows are updated or deleted concurrently. It is not MVCC-safe: transactions whose snapshot predates the repack see the table as empty after it commits. Needs free disk equal to table plus indexes. Progress in `pg_stat_progress_repack`. See [vacuum-and-maintenance.md](../vacuum-and-maintenance.md).
- Logical decoding without restart: with `wal_level = replica`, creating the first logical slot raises the effective level to logical; `SHOW effective_wal_level` reports it. Dropping or invalidating the last logical slot lowers it again, which invalidates logical slots on standbys.
- Logical replication of sequences (`CREATE PUBLICATION ... FOR ALL SEQUENCES`, `ALTER SUBSCRIPTION ... REFRESH SEQUENCES`), `EXCEPT` for `ALL TABLES` publications, and `retain_dead_tuples` for conflict detection. These remove the last manual step (sequence resync) in logical-replication upgrades.
- `WAIT FOR LSN '<lsn>' [WITH (MODE 'standby_replay', TIMEOUT '100ms', NO_THROW)]` on a standby gives read-your-writes against async replicas. Run it as a top-level command before the first snapshot-taking statement. See [replication-and-ha.md](../replication-and-ha.md).
- Parallel index vacuuming by autovacuum: `autovacuum_max_parallel_workers` (default 0) and the per-table `autovacuum_parallel_workers` storage parameter.
- New views: `pg_stat_lock` (per lock type), `pg_stat_recovery`, `pg_stat_autovacuum_scores`, `pg_stat_progress_repack`; `started_by` and `mode` columns in `pg_stat_progress_vacuum`; `stats_reset` per table and index; `wal_fpi_bytes` in `pg_stat_wal`. See [monitoring.md](../monitoring.md).
- `EXPLAIN (ANALYZE, IO)` reports asynchronous I/O; `EXPLAIN` shows Memoize estimates.
- `pg_plan_advice` and `pg_stash_advice` contrib modules for controlling planner decisions per query. Treat as a targeted fix for a regressed plan, not a default.
- `INSERT ... ON CONFLICT DO SELECT ... RETURNING` returns (and optionally locks) the conflicting row.
- `pg_stat_statements` adds `generic_plan_calls` and `custom_plan_calls` (container confirms the columns).
- `log_min_messages` accepts per-process-type levels (`type:level`).
- Server-side SNI with `pg_hosts.conf`.
- Query scans may now set visibility-map bits, so a following `VACUUM` scans fewer pages. Container: `VACUUM (VERBOSE)` on the freshly loaded test table scanned 2 of 1607 pages on 19.0 against 1607 of 1607 on 18.7 (interpretation: consistent with this change).

## Upgrading Into This Series

Checks to run on the 18 (or older) source before pg_upgrade:

```sql
-- btree_gist indexes on inet/cidr block pg_upgrade into 19
SELECT i.indexrelid::regclass AS index_name, i.indrelid::regclass AS table_name
FROM pg_index i
JOIN pg_opclass oc ON oc.oid = ANY (i.indclass::oid[])
JOIN pg_type t ON t.oid = oc.opcintype
WHERE oc.opcname LIKE 'gist_%_ops' AND t.typname IN ('inet', 'cidr');

-- names with CR or LF block pg_upgrade into 19
SELECT 'database' AS kind, datname AS name FROM pg_database WHERE datname ~ '[\r\n]'
UNION ALL SELECT 'role', rolname FROM pg_roles WHERE rolname ~ '[\r\n]'
UNION ALL SELECT 'tablespace', spcname FROM pg_tablespace WHERE spcname ~ '[\r\n]';

-- RADIUS rules must go
SELECT line_number, auth_method FROM pg_hba_file_rules WHERE auth_method = 'radius';

-- MULE_INTERNAL databases need dump/restore
SELECT datname FROM pg_database WHERE pg_encoding_to_char(encoding) = 'MULE_INTERNAL';
```

The first query's opclass-name filter is a heuristic; `pg_upgrade --check` on the rehearsal copy is the authoritative test. Container: on 18.7 the query returned an index built with `gist_inet_ops`, and 19.0 `pg_upgrade --check` against that cluster failed at `Checking for uses of gist_inet_ops/gist_cidr_ops` ("Replace them with indexes that use the built-in GiST inet_ops operator class", index list in `pg_upgrade_output.d/.../gist_inet_ops.txt`). After `DROP INDEX` and `CREATE INDEX ... USING gist (ip inet_ops)` the check passed. On 19.0, `USING gist (ip)` on an `inet` column picks `inet_ops`.

Then:

- Remove `io_workers` from `postgresql.conf` and `postgresql.auto.conf`; set `io_min_workers`/`io_max_workers` if you had tuned it.
- Double any explicit `max_locks_per_transaction` value.
- Decide on `jit`: leave it off for OLTP; enable it for long analytical queries after measuring.
- Re-dump with the 19 `pg_dump` if you use dump/restore and the source had `standard_conforming_strings = off`.
- After the upgrade, reindex full-text, pg_trgm, and fuzzystrmatch indexes in ICU or builtin-provider databases.
- Update monitoring for renamed wait events and columns.
