# PostgreSQL 16

Checked: 2026-11-27 against https://www.postgresql.org/docs/release/16.0/ and https://www.postgresql.org/support/versioning/.

Read this when the server reports `server_version_num` 160000 to 169999, or when upgrading into 16.

## Lifecycle

- First release 16.0 on 2023-09-14; current minor 16.16; community support until 2028-11-09.
- Amazon RDS: end of standard support 2029-02-28; Extended Support until 2032-02-29.
- Aurora PostgreSQL: available since 2024-01-31; end of standard support 2029-02-28; Extended Support until 2032-02-28 (the Aurora calendar shows 28 February, the RDS calendar 29 February 2032); Aurora LTS minor 16.8. Aurora PostgreSQL Limitless Database minors are 16-based (16.4-limitless to 16.11-limitless on the check date).

## Changed Defaults

| Setting or behavior | Before 16 | 16 | Action |
| --- | --- | --- | --- |
| Role membership inheritance | decided by the member role's `INHERIT` attribute at use time | set per grant (`GRANT ... WITH INHERIT TRUE|FALSE`, `WITH SET`, `WITH ADMIN`) | Inspect `pg_auth_members.inherit_option` and `set_option` (columns exist from 16; container shows them on 16.16 and later, absent on 14 and 15). |
| `CREATEROLE` | could alter almost any non-superuser role | can only manage roles it has `ADMIN OPTION` on; can grant `CREATEDB`, `REPLICATION`, `BYPASSRLS` only if it has them | Re-test delegated user-management accounts. |
| `REINDEX DATABASE`, `reindexdb` | included system catalogs | skip system catalogs | Use `REINDEX SYSTEM` for catalogs. |
| Logical replication apply | ran as the subscription owner | runs as the table owner; subscription owner needs `SET ROLE` on table owners (or `run_as_owner = true`) | Check subscription owners' role grants before upgrading subscribers. |

## Removed or Deprecated

- `vacuum_defer_cleanup_age` removed (use `hot_standby_feedback` or replication slots).
- `promote_trigger_file` removed; promote with `pg_ctl promote` or `SELECT pg_promote();`.
- `force_parallel_mode` renamed `debug_parallel_query`.
- Read-only `lc_collate`, `lc_ctype` settings removed; read `pg_database.datcollate`/`datctype`.
- Views can no longer be created manually with `ON SELECT` rules.
- `NULLS NOT DISTINCT` not allowed for primary keys.
- `aclitem` internal format changed: community `pg_upgrade` 16 and later (when the old cluster is 15 or older) and the RDS and Aurora prechecks refuse the upgrade while user tables have `aclitem` columns (`pg_upgrade` source `check.c`, tag REL_16_0; the 16.0 release notes do not list it).

## Worth Adopting

- `pg_stat_io` for I/O by backend type, object, and context. See [monitoring.md](../monitoring.md).
- Logical decoding on standbys (create logical slots on a hot standby; use `pg_log_standby_snapshot()` on the primary to speed up slot creation).
- Parallel apply of large transactions (`streaming = parallel`, `max_parallel_apply_workers_per_subscription`); binary initial sync; `origin = none` to avoid replication loops in bidirectional setups.
- `REPLICA IDENTITY FULL` apply can use B-tree indexes on the subscriber.
- `pg_hba.conf`/`pg_ident.conf`: regular expressions (leading `/`), `include` files, rule and map numbers in `pg_hba_file_rules`.
- `reserved_connections` with `pg_use_reserved_connections` keep admin slots free for non-superuser operators.
- `pg_create_subscription` predefined role; `password_required = false` subscriptions.
- `EXPLAIN (GENERIC_PLAN)` shows the generic plan of a parameterized statement without values (container: works on 16.16 and later, error "there is no parameter $1" on 14 and 15).
- `last_seq_scan`, `last_idx_scan`, `n_tup_newpage_upd` in table and index stats: use them to find unused indexes and HOT-update failures.
- `vacuum_buffer_usage_limit` and `VACUUM (BUFFER_USAGE_LIMIT ...)`.
- Opportunistic page freezing during normal vacuum.
- `scram_iterations`; Kerberos credential delegation.

## Upgrading Into This Series

From 15 (or older):

- Remove `vacuum_defer_cleanup_age` and `promote_trigger_file` from configuration; replace trigger-file promotion in HA scripts.
- Rename `force_parallel_mode` in configs.
- Find `aclitem` columns in user tables before any upgrade from 15 or older; `pg_upgrade --check` reports them in `tables_using_aclitem.txt`.
- Review roles that rely on `CREATEROLE` or on `NOINHERIT` behavior; after the upgrade, verify `pg_auth_members` options.
- Subscribers: grant the subscription owner `SET ROLE` on table owners, or create subscriptions with `run_as_owner = true`.
