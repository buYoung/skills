# PostgreSQL 18

Checked: 2026-11-27 against https://www.postgresql.org/docs/release/18.0/ and https://www.postgresql.org/support/versioning/.

Read this when the server reports `server_version_num` 180000 to 189999, or when upgrading into 18.

## Lifecycle

- First release 18.0 on 2025-09-25; current minor 18.7; community support until 2030-11-14.
- Amazon RDS: available since 2025-11-14 (from 18.1); end of standard support 2031-02-28; Extended Support until 2034-02-28. Latest RDS minor on the check date: 18.7 (RDS release 2026-11-26).
- Aurora PostgreSQL: available since 2026-06-11 (from 18.3); end of standard support 2031-02-28; Extended Support until 2034-02-28; no Aurora LTS minor designated yet. Latest Aurora minor listed: 18.6.

## Changed Defaults

| Setting or behavior | Before 18 | 18 | Action |
| --- | --- | --- | --- |
| `initdb` data checksums | off unless `--data-checksums` | on; `--no-data-checksums` disables | pg_upgrade requires matching checksum settings. When upgrading a non-checksum cluster, run `initdb --no-data-checksums` for the new cluster, or enable checksums on the old one first. Container: `data_checksums` is `on` on 18 and 19 images, `off` on 14 to 17. |
| `effective_io_concurrency`, `maintenance_io_concurrency` | 1 and 10 (container, 14 to 17) | 16 | Re-evaluate explicit overrides; the asynchronous I/O subsystem uses them. |
| `io_method` (new) | — | `worker` (default, container); `sync` reproduces pre-18 behavior; `io_uring` on Linux builds with liburing (the official 18.7 and 19.0 images list `sync`, `worker`, `io_uring`) | Leave `worker` unless you have measured otherwise. |
| `io_workers` (new) | — | 3 | Fixed worker count on 18; replaced by auto-scaling settings in 19. |
| `EXPLAIN ANALYZE` | `BUFFERS` only on request | `BUFFERS` included automatically | Container confirms buffer lines in plain `EXPLAIN (ANALYZE)` on 18 and 19, not on 17. |
| `EXPLAIN` row counts | integers | fractional (`rows=77680.50`) | Update plan-parsing tools. |
| `CREATE SUBSCRIPTION ... streaming` | `off` | `parallel` | Large transactions are applied by parallel workers by default. |
| Generated columns | stored only | virtual by default; `STORED` keyword for stored | `GENERATED ALWAYS AS (expr)` without `STORED` is virtual on 18; the same DDL is a syntax error on 17. Container confirms. |
| `VACUUM`/`ANALYZE` on an inheritance parent | parent only | parent and children; `VACUUM ONLY parent` / `ANALYZE ONLY parent` restores the old behavior (`VACUUM (ONLY) parent` is a syntax error, container 18.7) | Scheduled scripts that vacuum parents now do more work. |
| `log_connections` | boolean | list of connection stages (boolean still accepted) | `SHOW log_connections` returns an empty string when off (container). Context is `superuser-backend`: `SET log_connections` in a session fails with `cannot be set after connection start`; set it in the configuration and reload, or at connection start. Container 18.7 and 19.0 accept `receipt,authentication,authorization,setup_durations`, `on`, and `all`. |
| `pg_stat_io` | — | adds `read_bytes`, `write_bytes`, `extend_bytes`, WAL rows; removes `op_bytes` | Container: 79 rows on 18, 35 on 17. |
| `pg_stat_wal` | had `wal_write`, `wal_sync`, `wal_write_time`, `wal_sync_time` | removed; WAL I/O timing moves to `pg_stat_io` (`track_wal_io_timing`) | Fix dashboards. |
| `pg_stat_checkpointer` | — | adds `num_done`, `slru_written` | `num_timed`/`num_requested` count skipped checkpoints too. |
| `AFTER` triggers | ran as the role active at execution (e.g. at `COMMIT`) | run as the role active when the event was queued | Matters for code that switches roles inside a transaction. |
| `RESTRICT` foreign key violations | SQLSTATE `23503` | `23001` (`restrict_violation`) | Update error handling that matches on SQLSTATE. |

## Removed or Deprecated

- MD5 password authentication deprecated. `CREATE ROLE`/`ALTER ROLE` with MD5 passwords emit a warning (container shows `WARNING:  setting an MD5-encrypted password` on 18 and 19, none on 17). Disable with `md5_password_warnings = off` only as a temporary measure.
- `COPY FROM` CSV no longer treats `\.` as end-of-file; older psql clients using `\copy` against 18 can misbehave.
- Unlogged partitioned tables disallowed.
- `pg_backend_memory_contexts.parent` removed; `level` is one-based.
- Primary/foreign key pairs must use deterministic collations or the same nondeterministic collation; pg_dump restore and pg_upgrade fail otherwise.
- Full text search uses the cluster's default collation provider; reindex FTS and pg_trgm indexes after pg_upgrade in ICU or builtin clusters.

## Worth Adopting

- pg_upgrade keeps optimizer statistics (not extended statistics). Post-upgrade use `vacuumdb --all --analyze-in-stages --missing-stats-only` then `vacuumdb --all --analyze-only`. `--no-statistics` disables the transfer.
- `pg_upgrade --swap`: fastest mode for many relations; the old cluster becomes unusable once pg_upgrade says so. `--jobs` now parallelizes the checks.
- B-tree skip scan: a multicolumn index can serve queries that do not constrain the leading column. Re-check whether redundant single-column indexes are still needed (measure first).
- `uuidv7()` for time-ordered UUID keys; `uuidv4()` alias.
- `OLD`/`NEW` in `RETURNING` for `INSERT`, `UPDATE`, `DELETE`, `MERGE` (container confirms `RETURNING old.total, new.total`).
- Temporal constraints: `PRIMARY KEY`/`UNIQUE ... WITHOUT OVERLAPS`, foreign keys with `PERIOD`.
- `NOT ENFORCED` for `CHECK` and foreign key constraints; `NOT NULL` constraints stored in `pg_constraint` with names and `NOT VALID`.
- `idle_replication_slot_timeout` invalidates idle slots automatically (default 0 = off). Set it to cap WAL retention by abandoned slots.
- `autovacuum_worker_slots` (default 16) lets you change `autovacuum_max_workers` without restart, up to that limit. `autovacuum_vacuum_max_threshold` (default 100,000,000) caps the dead-tuple trigger on very large tables.
- Eager freezing: normal vacuums freeze some all-visible pages (`vacuum_max_eager_freeze_failure_rate`, default 0.03), reducing later aggressive vacuums. `VACUUM VERBOSE` reports "eagerly scanned" pages.
- `vacuum_truncate` as a server setting; `track_cost_delay_timing` adds vacuum delay time to progress views.
- `log_lock_failures` logs `NOWAIT` lock failures.
- OAuth authentication method (`oauth` in `pg_hba.conf`, `oauth_validator_libraries`).
- `pg_dump`/`pg_restore` `--statistics`, `--statistics-only`, `--no-statistics`, `--no-data`, `--no-schema`, `--no-policies`, `--sequence-data`.
- `pg_verifybackup` verifies tar-format backups; `pg_combinebackup --link`.
- `pg_get_acl()`, predefined role `pg_signal_autovacuum_worker`.
- psql pipeline commands (`\startpipeline` ... `\endpipeline`).

## Upgrading Into This Series

From 17 (or older):

- Decide the checksum setting for the new cluster before `initdb`.
- Remove MD5 passwords: `SELECT rolname FROM pg_authid WHERE rolpassword LIKE 'md5%';` then reset those passwords with `password_encryption = 'scram-sha-256'` and switch `pg_hba.conf` lines from `md5` to `scram-sha-256` (an `md5` line already accepts SCRAM passwords).
- Find PK/FK collation mismatches and nondeterministic collations on keys before pg_dump or pg_upgrade.
- Check application code for SQLSTATE `23503` matching on `RESTRICT` foreign keys.
- Update monitoring for removed `pg_stat_wal` columns and `pg_stat_io.op_bytes`.
- Logical replication: from a 17 source, pg_upgrade carries slots and subscriptions; from 14 to 16 it does not (see [17](17.md)).

## Managed Service Notes

- RDS removes the `plrust` extension starting with RDS PostgreSQL 18, and `postgis_topology` is unavailable on RDS 18.1 and 18.2; drop them before upgrading.
- RDS Multi-AZ DB clusters on source versions earlier than 17.8 or 18.2 must have flow control disabled for a major upgrade.
- AWS upgrade guides still say optimizer statistics are not transferred during a major version upgrade and tell you to run `ANALYZE` afterwards. This conflicts with community pg_upgrade behavior into 18; follow the AWS instruction on RDS and Aurora (the managed upgrade path may differ), and run `ANALYZE` regardless.
