# Redis 8.0

Checked: 2026-11-27. Read when the server reports `redis_version:8.0.x`, when moving from Redis Stack or separately loaded modules, or when ACLs break after an upgrade to 8.

## Lifecycle

- Standard release. GA 8.0.0 on 2025-05-02. End of support 2026-12-01, four days after this check. Plan the move to 8.2 (Extended, supported to 2030-09-01) or to 8.10/8.12 now.
- Official image `redis:8.0` reported 8.0.6 on 2026-11-27.
- License: RSALv2, SSPLv1, or AGPLv3, at the user's choice. Product renamed to Redis Open Source.

## Changed Defaults

- Bundled data types: JSON, time series, Bloom, Cuckoo, count-min sketch, top-k, t-digest, the Query Engine (search and vector search), and vector sets (beta) ship in the binary distributions. The official image loads them: `MODULE LIST` shows `vectorset`, `search`, `bf`, `timeseries`, `ReJSON` on 8.0.6. A build from source needs the steps in the README to include them.
- New config file `redis-full.conf` loads all components and holds their parameters.
- I/O threading reimplemented. `io-threads` (default 1) now drives both reads and writes; `io-threads-do-reads` no longer has any effect.
- New replication mechanism (performance and robustness); new `replica-full-sync-buffer-limit` caps replication data accumulated on the replica during full sync.
- `cluster-compatibility-sample-ratio` (default 0) and `INFO` `cluster_incompatible_ops` detect commands that would fail after moving to Cluster.
- `GETRANGE` with an out-of-range negative end index returns an empty bulk string.

## Removed or Deprecated

- Redis Stack and the standalone RediSearch, RedisJSON, RedisTimeSeries, RedisBloom modules are deprecated for Redis 8; the functionality is part of Redis.
- `io-threads-do-reads` is ineffective.

## Worth Adopting

- `HGETEX`, `HSETEX`, `HGETDEL`: read or write hash fields and set or clear their TTL in one command (observed working on 8.0.6).
- `INFO keysizes`: per-type histograms of key sizes (`db0_distrib_strings_sizes`, `db0_distrib_hashes_items`, ...). Cheap first look for big keys.
- `INFO threads`: per-I/O-thread client and event counts.
- Vector sets (`VADD`, `VSIM`, ...): beta in 8.0; API may change.
- TLS works together with I/O threads from 8.0.
- Replication offset stored in AOF, to tell which AOF is newer during recovery.

## Upgrading Into This Series

From 7.4 or 7.2:

- ACL categories (listed under "Major changes" in the GA notes; breaking for ACL rules in practice): commands of the bundled data types are now members of the standard categories (`@read`, `@write`, ...) and of new categories `@search`, `@json`, `@timeseries`, `@bloom`, `@cuckoo`, `@cms`, `@topk`, `@tdigest`. A user defined as `+@all -@write` can no longer run `JSON.SET`. Rehearse with production `ACL LIST` and watch `ACL LOG` and `acl_access_denied_cmd`.
- Search (breaking for Stack users): `BM25` replaces `TF-IDF` as default scorer; stricter `LIMIT`, `FT.CURSOR READ`, `FT.ALIASADD` parsing; invalid input returns errors instead of empty results; reducer defaults revisited.
- Supported paths: from earlier Redis with or without the four modules, and from Redis Stack 7.2 or 7.4, by replication or persistence.
- License: moving from 7.2 (BSD) to 8.0 adds AGPLv3 obligations only if you modify the code and offer it over a network (per the Redis licensing FAQ). Moving from 7.4 changes nothing for users already on RSALv2/SSPLv1.
- `io-threads-do-reads` in old config files is silently ineffective; remove it and size `io-threads` instead.

Check after the switch: `MODULE LIST`, `ACL LOG`, `INFO errorstats`, `INFO threads` when `io-threads` > 1.

## Managed Service Notes

ElastiCache and MemoryDB do not run Redis Open Source 8. Their own JSON, vector search, Bloom, and search features come from AWS or Valkey implementations with their own command coverage. See [managed services](../managed-services.md).
