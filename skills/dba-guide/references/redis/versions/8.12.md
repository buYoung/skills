# Redis 8.12

Checked: 2026-11-27. Read when the server reports `redis_version:8.12.x`, or when adopting `BLESS`, set member TTLs, Roaring bitmaps, or CPU time in the slow log.

## Lifecycle

- Standard release. GA 8.12.0 on 2026-11-22. End of support TBD.
- Official image `redis:8.12` reported 8.12.0 on 2026-11-27; `MODULE LIST` shows `bf`, `timeseries`, `ReJSON` at `81200`, `search` at `81201`, `vectorset` at `1`.
- License: RSALv2, SSPLv1, or AGPLv3.
- Five days old at the check date. Rehearse before production and watch for the first patch releases.

## Changed Defaults

New parameters and their defaults on the 8.12.0 image:

| Parameter | Default | Effect |
|---|---|---|
| `bitmap-default-roaring` | `no` | create new bitmaps as Roaring-compressed |
| `stream-stats` | `no` | per-database stream histograms in `INFO STREAMS` |
| `off-cpu-tracking` | `yes` | CPU time field in `SLOWLOG GET` |
| `json-legacy-rdb-depth-limit` | `no` | cap JSON nesting at 128 when loading RDB/`RESTORE` |
| `json-auto-create-deep-paths` | `no` | `JSON.SET` creates missing parents; load-time only; keep equal on all shards and AOF replays |
| `tls-groups` | empty | TLS named groups (OpenSSL default when empty) |

- Client memory (`tot-mem`, `mem_clients_normal`, `maxmemory-clients`) now counts watched key names and Pub/Sub channel and pattern names; `maxmemory-clients` can evict clients earlier than on 8.10.
- Supported x86 systems use the processor monotonic clock by default.
- `SORT`/`SORT_RO` no longer convert listpack sorted sets to the large encoding.

## Worth Adopting

- `BLESS SET <key> NO-EVICT`, `BLESS CLEAR <key> NO-EVICT`, `BLESS GET <key>`, `BLESS SCAN <cursor> NO-EVICT [COUNT n]`: exempt keys from eviction under any policy. If protected keys prevent reaching `maxmemory`, writes keep succeeding until `used_memory` would exceed 1.25 x `maxmemory`, then fail with OOM. Count in `blessed_keys`. On 8.12.0 `BLESS SET` replies `1`, `BLESS GET` replies `NO-EVICT`, and `blessed_keys:1` follows.
- Set member expiration: `SEXPIRE`, `SPEXPIRE`, `SEXPIREAT`, `SPEXPIREAT`, `STTL`, `SPTTL`, `SEXPIRETIME`, `SPEXPIRETIME`, and a command to clear it. The GA notes name that command `SETPERSIST`; the 8.12.0 image answers `ERR unknown command 'SETPERSIST'` and has `SPERSIST` instead (`SPERSIST s MEMBERS 1 a` returns `1`). Syntax on 8.12.0: `SEXPIRE key seconds [NX|XX|GT|LT] MEMBERS nummembers member ...`, `STTL key MEMBERS nummembers member ...`; `SEXPIRE s 100 MEMBERS 1 a` returns `1`, `STTL s MEMBERS 2 a b` returns `100` and `-1`.
- `ZMOVE`, `BZMOVE`, `ZMOVEMEMBER`: atomic moves between sorted sets, replacing Lua for queue and leaderboard handoffs. `ZMOVE source destination MIN|MAX|BYSCORE min max [COUNT n]` keeps scores and replies with each moved member and its score (`ZMOVE z1 z2 MIN COUNT 1` returned `a`, `1` on 8.12.0).
- Roaring bitmaps and `BITRANGEINTARRAY`.
- New B+ tree encoding for large sorted sets with lower memory (GA notes). `OBJECT ENCODING` reports `btree` for a 200-member sorted set on 8.12.0 (`skiplist` on 8.10.3).
- `SLOWLOG GET` eighth field: CPU time of the command in microseconds; compare with duration to separate slow commands from CPU-starved ones. On 8.12.0 `DEBUG SLEEP 0.2` logged duration `200557` and CPU time `73`; a CPU-bound `EVAL` logged `101931` and `101370`.
- `CLUSTER MIGRATION STATUS` progress for snapshot and incremental phases.
- `INFO keysizes` includes streams.

## Upgrading Into This Series

From 8.10:

- Search: the module requires Redis 8.9.241 or newer to load; `FT.CREATE` rejects `RERANK` on in-RAM HNSW; `COLLECT` needs `@` field prefixes; numeric arguments parse strictly; disk indexes reject `DIALECT 4` and `WITHOUTCOUNT`.
- Probabilistic: `CMS.MERGE` requires equal cell sizes; rejected `CMS.INCRBY` updates no longer saturate counters.
- Security: TLS session resumption across listeners or after `tls-auth-clients`/`tls-expected-peer-name` changes fixed (#16127). Upgrade if you rely on client certificate checks.
- Data-loss fixes: keys lost during atomic slot migration when the destination rejected a command (#16176), data loss after a replica migrated to another shard (#15680), loss when a legacy AOF was upgraded before loading completed (#15916), double replay after an AOF write error (#16175). If you run atomic slot migration or AOF on 8.10, prefer 8.12, or check whether your 8.10 patch carries these fixes.
- Cluster: `cluster-bus-port-protected-mode` defaults to `yes` on 8.12.0 (`no` on the 8.2 to 8.10 images). With `cluster-enabled yes` and `tls-cluster no`, 8.12.0 refuses to start: `*** FATAL CONFIG FILE ERROR (Redis 8.12.0) *** cluster-bus-port-protected-mode is enabled but tls-cluster is disabled, ...`. Before upgrading cluster nodes, set `tls-cluster yes`, or set `cluster-bus-port-protected-mode no` when a firewall already restricts the bus port.
- `notify-keyspace-events` containing `A` lost the `n`, `o`, `c` flags through `CONFIG GET`/`CONFIG REWRITE` before this fix (#16142); re-check the value after a restart on older versions.
