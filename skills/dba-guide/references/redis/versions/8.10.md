# Redis 8.10

Checked: 2026-11-27. Read when the server reports `redis_version:8.10.x`, or when adopting the `BACKUP` command, `preload-file` restores, compact hashes, or replication stream compression.

## Lifecycle

- Standard release. GA 8.10.0 on 2026-07-29. End of support: TBD on the version management page. Inference, not stated in the documentation: the standard-release rule (6 months after the next minor) points to about 2027-05 after 8.12's GA; not a published date.
- Official image `redis:8.10` reported 8.10.3 on 2026-11-27.
- License: RSALv2, SSPLv1, or AGPLv3.
- Run 8.10.1 or later: 8.10.1 (August 2026) is a security release fixing CVE-2026-62356 (count-min sketch RDB loading), a TLS client-certificate bypass through a Common Name with an embedded NUL byte, a use-after-free in the TLS pending-data list, RDB `SLOT_INFO` memory corruption, several vector set issues, and a blocked-client use-after-free.

## Changed Defaults

- New startup-only `backupdirname` (default `backupdir`, under `dir`) and `backup-sealed-ttl` (default 0: sealed backups stay until `BACKUP CLEANUP`).
- New startup-only `preload-file` (`aof:<manifest>` or `rdb:<file>`): load this file instead of the normal `appenddirname`/`dump.rdb` at start; startup aborts if it cannot be loaded.
- Replication stream compression between primary and replicas (#15366): `repl-compression` (default `0` on the 8.12 image) and `repl-compression-max-latency` (default `100`). Per the 8.12.0 `redis.conf`, `repl-compression` is the zstd level for the replica's connection to the primary, 0–22 with 0 meaning off; it requires `io-threads` > 1, and the settings are commented out because compression is disabled unless Redis is built with `BUILD_COMPRESSION=yes`. `repl-compression-max-latency` is the maximum latency in ms before compressed data is flushed to the socket. Check `CONFIG GET repl-compression` on your build before planning on it.
- Compact hash parameters: `hash-min-template-entries`, `hash-max-template-entries`, `hash-rdb-load-min-template-entries`, `hash-rdb-load-max-template-entries`, `hash-rdb-load-template-disassembly-threshold`, all `0` on the 8.12 image. With these defaults, 1000 hashes written by `HSET` with the same three fields stayed `listpack` and no template was created (`hash_templates:0`, `hash_template_keys:0`, `used_memory_hash_templates:80` on 8.12.0); the `HIMPORT` path was not tested.
- Search: `search-on-timeout` gains `RETURN_STRICT`, and the release notes add `search-global-timeout`, a cap on the per-query `TIMEOUT` argument. The 8.10.3 image also reports an underscore-prefixed `search-_max-foreground-timeout-limit 60000` in `CONFIG GET` (image observation; not in the notes).

## Worth Adopting

- `BACKUP START`, `BACKUP LIST`, `BACKUP SEAL`, `BACKUP STATUS`, `BACKUP ABORT`, `BACKUP CLEANUP`: online backup producing BASE + INCR + manifest in multi-part AOF format, with or without AOF persistence enabled. Lets a control plane stagger the fork across cluster nodes. See [persistence](../persistence-and-recovery.md#backup-command-810).
- Compact hashes and `HIMPORT`: field names stored once per shared schema. Watch `hash_templates`, `hash_template_keys`, `used_memory_hash_templates`. `MEMORY USAGE` includes the key's share of its template.
- `SUNIONCARD`, `SDIFFCARD`: cardinality without materializing a result.
- `LMOVEM`, `BLMOVEM`: move several list elements in one call.
- `XREAD`/`XREADGROUP ... MAXCOUNT`/`MAXSIZE`: bound reply size for fan-in reads.
- `SLOWLOG GET` adds a seventh field: total argument count before truncation (`42` for a 42-argument `SADD` on 8.10.3; 8.8.4 returns six fields).
- `redis-cli --cluster reshard` and `rebalance` use server-side atomic slot migration.
- `redis-cli --latency-percentiles 50,99,99.9`.
- TLS peer certificate-based authentication for server-to-server links.

## Upgrading Into This Series

From 8.8:

- Security: ACL bypass in `SORT`, `GEORADIUS`, `GEORADIUSBYMEMBER`, `XREAD`, `XREADGROUP` fixed (#15478); CRLF injection through error replies fixed (8.10-RC2). Upgrade if untrusted users have restricted ACLs.
- `SET` now rejects `NX`/`XX` combined with `IF*` options (#15291).
- `MEMORY USAGE` over-reporting fixed (#15462); expect lower numbers than 8.8 for the same keys.
- Backups: `BACKUP` is new; existing RDB copy and AOF-directory procedures keep working.
