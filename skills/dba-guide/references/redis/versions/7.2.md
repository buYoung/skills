# Redis 7.2

Checked: 2026-11-27. Read when the server reports `redis_version:7.2.x`, when choosing between staying on the last BSD-licensed line and moving to Redis 8 or Valkey, or when upgrading from 6.2 (this file carries the 7.0 changes too).

## Lifecycle

- Extended release. GA 7.2.0 on 2023-08-15. End of support 2029-12-01.
- Official image `redis:7.2` reported 7.2.17 on 2026-11-27.
- License: BSD-3-Clause; this is the last Redis line under it. Valkey forked from this lineage. See [licensing](../licensing.md).

## Changed Defaults

Defaults observed on the 7.2.17 image (`CONFIG GET`), identical on every 7.4 and 8.x image checked:

| Parameter | Value |
|---|---|
| `maxmemory` / `maxmemory-policy` | `0` / `noeviction` |
| `save` | `3600 1 300 100 60 10000` |
| `appendonly` / `appendfsync` | `no` / `everysec` |
| `aof-use-rdb-preamble` | `yes` |
| `repl-diskless-sync` | `yes` (default since 7.0) |
| `repl-backlog-size` | `1048576` |
| `slowlog-log-slower-than` | `10000` (microseconds) |
| `latency-monitor-threshold` | `0` (off) |
| `lazyfree-lazy-user-del`, `lazyfree-lazy-eviction` | `no` |
| `io-threads` | `1` |
| `enable-debug-command` | `no` (since 7.0) |
| `busy-reply-threshold` (alias `lua-time-limit`) | `5000` |
| `protected-mode` | `no` in the container run; the shipped `redis.conf` sets `yes`. The image entrypoint does not set it (no `protected` line in `docker-entrypoint.sh` on 6.2, 7.2, or 8.12), and 8.12.0 reports `no` also when started with a config file that omits it, so the image's built-in default is `no`: the docker-library build template patches the `protected-mode` default in `src/config.c` to 0 before compiling (`Dockerfile.template`, current master) |

7.0 changes that reach a 6.2 user here: `acl-pubsub-default` became `resetchannels` (new users get no channel access), `repl-diskless-sync` became `yes`, `MODULE` and `DEBUG` are blocked by default (`enable-module-command`, `enable-debug-command`), and setting `bind` explicitly no longer disables protected mode.

## Removed or Deprecated

- 7.0: `STRALGO` removed (use `LCS`); EVAL script verbatim replication removed (effects replication only); gopher protocol removed; Lua `print()` removed; admin and snapshot commands rejected inside `MULTI`.
- 7.2: `QUIT` deprecated; ACL rules are stored as written, so `ACL LIST` and `ACL SAVE` output can differ from 7.0 for the same user.
- Config names using `ziplist` remain as aliases for the `listpack` names (7.0).

## Worth Adopting

- Multi-part AOF (7.0): base file plus incremental files plus manifest in `appenddirname`. Rewrites no longer double-write or buffer in memory. Changes how you back up AOF; see [persistence](../persistence-and-recovery.md).
- ACL v2 (7.0): selectors `( ... )`, read/write key permissions `%R~`, `%W~`, subcommand rules `-config|set`.
- Redis Functions (7.0): libraries persisted in RDB/AOF and replicated, instead of client-cached `EVAL` scripts.
- Sharded Pub/Sub (7.0): `SPUBLISH`, `SSUBSCRIBE` scoped to a slot in Cluster.
- `WAITAOF` (7.2): block until N local and replica AOFs have fsynced prior writes.
- `CLIENT NO-TOUCH` (7.2): run admin reads without changing LRU/LFU.
- Listpack encoding for small sets (7.2), in addition to intset; memory drop for small sets and lists.
- `CLIENT SETINFO` (7.2): clients report library name and version (`lib-name`, `lib-ver` in `CLIENT LIST`).
- `latency-tracking` and `INFO latencystats` (7.0, on by default): per-command percentiles without extra tooling.

## Upgrading Into This Series

From 6.2:

- RDB format: 7.0 writes RDB version 10 and 7.2 writes version 11 (`REDIS0011` header on 7.2.17; 6.2.24 writes `REDIS0009`), neither loadable by older servers. Take a 6.2-format backup before the switch; rollback is by restore, not by replication from 7.2.
- AOF layout: on first start with `appendonly yes`, 7.x converts a single `appendonly.aof` into the multi-part layout under `appenddirname`. Update backup scripts that copy one file.
- ACL: new users no longer get Pub/Sub access by default. Users created by automation after the upgrade fail `SUBSCRIBE`/`PUBLISH` with `NOPERM` unless the rule adds `&pattern` or `allchannels`, or you set `acl-pubsub-default allchannels`.
- Errors and replies: ACL error texts were unified; `XREADGROUP` and `XCLAIM` create consumers even when nothing is read; `PUBLISH` reply order changed for RESP3 clients subscribed to the same channel; time is frozen during command and script execution. Re-run client test suites.
- Encodings: ziplists in old RDBs convert to listpacks on load; expect slightly longer loading.

Check after the switch: `INFO server`, `ACL LOG` for unexpected denials, `INFO errorstats`, `ls <dir>/appendonlydir` when AOF is enabled.

## Managed Service Notes

- ElastiCache and MemoryDB do not offer a "Redis OSS 7.2" engine. Their newest Redis OSS engine is 7.1, compatible with Redis OSS 7.0; 7.2 behavior arrives there as "Valkey 7.2" (Valkey 7.2 includes Redis OSS changes up to 7.2.4). See [managed services](../managed-services.md).
