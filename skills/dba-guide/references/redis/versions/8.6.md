# Redis 8.6

Checked: 2026-11-27. Read when the server reports `redis_version:8.6.x` or `8.4.x` (both out of support; upgrade to 8.8 or later), or when upgrading from 8.2 to 8.8 or later, since such an upgrade crosses the 8.4 and 8.6 changes. The 8.4 series has no file of its own; its changes are under [Changes First Shipped in 8.4](#changes-first-shipped-in-84).

## Lifecycle

- Standard release. GA 8.6.0 on 2026-02-10. End of support 2026-11-25 (ended two days before this check). This is the most recent series past end of support.
- Official image `redis:8.6` reported 8.6.8 on 2026-11-27.
- License: RSALv2, SSPLv1, or AGPLv3.

## Changed Defaults

- New eviction policies `allkeys-lrm` and `volatile-lrm` (least recently modified). Default `maxmemory-policy` stays `noeviction`.
- Diskless replication no longer compresses the RDB stream; `repl-diskless-load` accepts a new `flushdb` value.
- Personally identifiable data is hidden from ACL logs and server logs.
- AArch64 uses the hardware clock by default.
- Changed: `cluster-slot-stats-enabled` (present since 8.2 as `yes`/`no`) takes a list of `cpu`, `net`, `mem` from 8.6 (#14719). `yes` means all three, and `mem` can only be turned on at startup: on the 8.6.8 to 8.12.0 images, a runtime `CONFIG SET cluster-slot-stats-enabled yes` fails with `memory tracking cannot be enabled at runtime`, while `"cpu net"` works. Scripts that set `yes` at runtime on 8.2 or 8.4 break after the upgrade.
- New, off by default: `key-memory-histograms`, `tls-auth-clients-user`, `stream-idmp-duration` and `stream-idmp-maxsize` (defaults 100 and 100 on the 8.12 image).

## Worth Adopting

- `HOTKEYS START METRICS 2 CPU NET COUNT 10`, `HOTKEYS GET`, `HOTKEYS STOP`, `HOTKEYS RESET`: server-side hot key tracking by CPU time and network bytes, one session at a time. Some cluster clients cannot send it; connect to a single node.
- LRM eviction: keeps read-hot but unchanged data at risk and protects recently written data. Use when "stale since last write" is the right eviction signal.
- TLS certificate-based client authentication: `tls-auth-clients-user` maps the client certificate to an ACL user; failures counted in `acl_access_denied_tls_cert`.
- `XADD ... IDMP` / `IDMPAUTO`: idempotent stream production (at-most-once add).
- `key-memory-histograms yes`: memory-size histograms per type (`db0_distrib_hashes_sizes`, ...).
- Memory reduction for hashtable-encoded hashes and skiplist-encoded sorted sets.

## Upgrading Into This Series

From 8.4, or from 8.2 after applying [the 8.4 upgrade notes](#upgrading-from-82-into-84):

- Known limitation in 8.6.0: do not use `XADD` with `IDMP`/`IDMPAUTO` when `appendonly yes` and `aof-use-rdb-preamble no`; the notes say a later patch removes it. Run the newest 8.6 patch, or better, move on.
- Search cursors may miss results during atomic slot migration (known limitation).
- Log redaction changes what incident tooling can grep from logs and `ACL LOG`.

## Changes First Shipped in 8.4

### 8.4 Lifecycle


- Standard release. GA 8.4.0 on 2025-11-18. End of support 2026-08-10 (ended).
- Official image `redis:8.4` reported 8.4.8 on 2026-11-27.
- License: RSALv2, SSPLv1, or AGPLv3.

### 8.4 Changed Defaults


- New `lookahead` parameter (default 16): depth of command prefetching in the parsing pipeline.
- New `aof-load-corrupt-tail-max-size` (default 0 on the 8.12 image, which keeps repair off): lets the server repair a corrupted AOF tail up to this size at startup. Different from `aof-load-truncated`, which only handles a truncated last command.
- Search: `search-default-scorer` is `BM25STD`; `search-on-oom` controls queries under memory pressure; `search-io-threads` for cluster coordination.

### 8.4 Worth Adopting


- Atomic slot migration: `CLUSTER MIGRATION IMPORT <start> <end> [...]` on the destination primary, `CLUSTER MIGRATION STATUS [ID <id> | ALL]`, `CLUSTER MIGRATION CANCEL ID <id> | ALL`. Slots and their keys move as one operation with a short write pause at handoff, replacing the per-key `MIGRATE` loop and its `ASK` redirections. See [replication and cluster](../replication-and-cluster.md#resharding).
- Compare-and-set on strings: `SET key value IFEQ <old>` (and the other `IF*` forms), `DELEX` (delete if the value matches a condition), `DIGEST` (hash of a value, for comparing without transferring it). `SET k1 v2 IFEQ v1` returns `OK` on 8.4.8; it is a syntax error on 8.2.
- `MSETEX`: set several keys and their expiration atomically.
- `XREADGROUP ... CLAIM <min-idle-time>`: read new entries and reclaim idle pending ones in one call.
- `FT.HYBRID`: hybrid text and vector queries with RRF or linear fusion.

### Upgrading from 8.2 into 8.4


From 8.2:

- Search and time series multi-shard commands (`FT.SEARCH`, `FT.AGGREGATE`, `FT.CURSOR`, `FT.HYBRID`, `TS.MGET`, `TS.MRANGE`, `TS.MREVRANGE`, `TS.QUERYINDEX`) may return partial or duplicate results while an atomic slot migration is running (known limitation in the 8.4 notes). Schedule migrations outside reporting windows.
- `SET` with `IF*` options was not checked for mutual exclusion with `NX`/`XX` until a fix in 8.10 (#15291); do not combine them.
- Go on to 8.8 or later; 8.4 no longer receives fixes.
