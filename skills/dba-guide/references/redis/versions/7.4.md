# Redis 7.4

Checked: 2026-11-27. Read when the server reports `redis_version:7.4.x`, when adopting hash field expiration, or when the license change from BSD matters.

## Lifecycle

- Extended release. GA 7.4.0 on 2024-07-29. End of support 2029-12-01.
- Official image `redis:7.4` reported 7.4.12 on 2026-11-27.
- License: RSALv2 or SSPLv1 (the 7.4 RC1 notes say "License changed - see LICENSE.txt"). No OSI-approved option in this series. Product name at the time: Redis Community Edition.

## Changed Defaults

- Lua: scripts loaded through `EVAL` are now evicted by LRU when too many accumulate (`evicted_scripts` in `INFO stats`). Clients that rely on `EVALSHA` of a script sent once by `EVAL` must handle `NOSCRIPT` and resend, or move to `SCRIPT LOAD` or Functions.
- Lua VM memory is allocated through jemalloc and counted in used memory, so `used_memory` rises for script-heavy instances after the upgrade without any data change.
- `ACL LOAD` no longer disconnects all clients.
- New: `hide-user-data-from-log` (default `no`) to keep user data out of the log.
- New: `max-new-connections-per-cycle` and `max-new-tls-connections-per-cycle` limit accepts per event-loop cycle (defaults 10 and 1 on the 8.12 image).

## Worth Adopting

- Hash field expiration: `HEXPIRE`, `HPEXPIRE`, `HEXPIREAT`, `HPEXPIREAT`, `HPERSIST`, `HEXPIRETIME`, `HPEXPIRETIME`, `HTTL`, `HPTTL`. Replaces "one key per field to get a TTL" designs. A small hash with field TTLs reports encoding `listpackex` (observed on 7.4.12). `INFO keyspace` reports `subexpiry`; `INFO stats` reports `expired_subkeys`. The RDB format changed for this feature.
- `HSCAN ... NOVALUES` to list field names only.
- `CLIENT KILL MAXAGE <seconds>` to drop long-lived connections in bulk.
- `redis-cli --keystats` (combines `--bigkeys` and `--memkeys` with distributions).
- Limit on total request size of a `MULTI ... EXEC` transaction.
- New metrics: `pubsub_clients`, `watching_clients`, `total_watched_keys`, `client_query_buffer_limit_disconnections`, `client_output_buffer_limit_disconnections`, `allocator_muzzy`, `mem_overhead_db_hashtable_rehashing`.

## Upgrading Into This Series

From 7.2:

- License: confirm the RSALv2/SSPLv1 terms are acceptable before upgrading; RSALv2 forbids offering the software to others as a managed service. If not acceptable, stay on 7.2, move to 8.x and elect AGPLv3, or move to Valkey. See [licensing](../licensing.md).
- RDB: the release notes list RDB format changes for hash field expiration. 7.4.12 writes RDB format 12 (`REDIS0012`) for every file, and 7.2.17 refuses to start on any of them, including one holding only a plain string: `Can't handle RDB format version 12`, then `Fatal error loading the DB, check server logs. Exiting.` Rollback to 7.2 is by a 7.2-format backup, not by copying a 7.4 RDB back.
- Lua script eviction: watch `evicted_scripts` and `NOSCRIPT` errors after the switch.
- `used_memory` increase from Lua accounting: re-check headroom against `maxmemory`.

## Managed Service Notes

No ElastiCache or MemoryDB engine is labeled Redis OSS 7.4. Hash field expiration reaches ElastiCache through Valkey 9.0. See [managed services](../managed-services.md).
