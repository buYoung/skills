# Rust 1.99

## Deprecations and Removals

- The legacy integral modules are fully deprecated: `std::i32::MAX` and similar constants warn under `deprecated`; use the associated constants such as `i32::MAX`.
- `no_mangle_generic_items` is a hard error: a generic function marked `#[no_mangle]` (`#[unsafe(no_mangle)]` in edition 2024) no longer compiles, and `#[allow(no_mangle_generic_items)]` only reports a removed lint.

## Migration Instructions

- Cargo disables incremental compilation by default when the `CI` environment variable is set. A CI job that depends on incremental reuse of a cached `target/` sets `CARGO_INCREMENTAL=1`; other CI builds become non-incremental without a configuration change.
- Macros from another crate whose expansion ends in a `;` in expression position now trigger `semicolon_in_expressions_from_non_local_macros` (warn). Report it to the crate that provides the macro instead of silencing it locally; the same-crate case has been deny-by-default since [1.91](1.91.md).
- Workspace members on edition 2024 or later can override an inherited dependency's `default-features`: `serde = { workspace = true, default-features = false }` now turns the defaults off even when `[workspace.dependencies]` enables them. Earlier editions ignore the override with a warning. Feature unification still enables the defaults when another package in the same build requests them.

## Behavior Changes Requiring Attention

- The `Box::leak` documentation now recommends against later deallocating leaked memory; the announcement recommends `Box::into_raw` or `Box::into_non_null` for memory that will be freed again, and applies the guidance to the other standard leak functions.
- The safety invariants of `Pin::new_unchecked` changed slightly; re-read its documentation where unsafe code builds pins by hand. References to extern statics are no longer promoted.
- The Rust Reference no longer recommends matching a union together with another value in one pattern, as in a hand-written tagged union: the compiler could read the union before checking the rest of the pattern, which can cause undefined behavior.
- An exhausted `RangeInclusive` iterator can return different `start()` and `end()` values and behave differently as a slice index. These values were not guaranteed.
- Cargo adds a built-in `debug` profile. It currently has the same settings as `dev` and prepares for changing `dev` away from debugging defaults.
- 1.99.1 fixes three regressions: missing `wcslen` link errors on UEFI and some embedded targets, x86_64 FFI functions returning `bool` with bits 1-7 of the return register unspecified, and `rust-lld` failing to load `libLLVM` on macOS when invoked without the rustup proxy. The first two appeared in 1.99.0. The `rust-lld` failure affects `aarch64-apple-darwin` toolchains from 1.98.0, when LLVM started being linked dynamically there, so 1.98.x is affected too. Prefer 1.99.1 over 1.99.0.

## Replacement APIs Worth Adopting

- C-variadic functions can be defined in Rust with the `"C"` and `"C-unwind"` ABIs (`unsafe extern "C" fn sum(mut args: ...) -> i32`); `...` has type `core::ffi::VaList`. [1.91](1.91.md) allowed only declarations.
- `Layout::for_value_raw`, `mem::size_of_val_raw`, `mem::align_of_val_raw`; `Box::into_non_null`, `Box::from_non_null`; `Vec::into_parts`, `Vec::from_parts`; `String::from_utf8_lossy_owned`; `VecDeque::retain_back`; `IntoIterator` for `Box<[T; N]>`; `std::fs::set_times`; `LocalKey<Cell<T>>::update`.
- The input of a custom attribute or derive macro may contain outlined modules (`mod foo;`), so `#[my_macro] mod foo;` is accepted. Targets: `riscv64-unknown-linux-musl` Tier 2 with host tools.
