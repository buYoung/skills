# Rust 1.81

## Deprecations and Removals

- `std::panic::PanicInfo` is renamed to `std::panic::PanicHookInfo`. The old name remains an alias and emits a deprecation warning from 1.82.0; rename uses in panic hooks.
- The `wasm32-wasi` target is deprecated in favor of `wasm32-wasip1` (same target, renamed since 1.78); the compiler warns on use, and the target is removed in [1.84](1.84.md).

## Migration Instructions

- The stable and unstable sort implementations changed and may now panic when an `Ord` or `PartialOrd` implementation is not a total order. Audit hand-written comparisons that previously produced a silently wrong order.
- A panic that reaches an `extern "C"` function (or any other non-unwinding ABI) now aborts the process. Where unwinding across FFI is intended, declare the function `extern "C-unwind"`; otherwise catch panics with `std::panic::catch_unwind` inside the boundary and return an error code.

```rust
use std::panic::{catch_unwind, AssertUnwindSafe};

fn double_checked(input: i32) -> i32 {
    assert!(input >= 0, "negative input");
    input * 2
}

// Before 1.81 a panic here unwound into the C caller (unsound). Since 1.81 the process aborts
// instead, so convert panics into an error code at the boundary.
#[unsafe(no_mangle)]
pub extern "C" fn double_checked_c(input: i32, out: *mut i32) -> i32 {
    if out.is_null() {
        return -1;
    }
    match catch_unwind(AssertUnwindSafe(|| double_checked(input))) {
        Ok(value) => {
            // SAFETY: `out` is non-null and the caller promises it is writable.
            unsafe { out.write(value) };
            0
        }
        Err(_) => -2,
    }
}

// When the foreign side is built to unwind (C++ exceptions, Rust panics through a C shim), declare
// the unwinding ABI so the panic can cross legally.
unsafe extern "C-unwind" {
    fn callback_that_may_throw(value: i32);
}
```

## Behavior Changes Requiring Attention

- Windows `Command` argument escaping for batch files was fixed for CVE-2024-43402; code that pre-escaped arguments should be re-tested.

## Replacement APIs Worth Adopting

- `#[expect(lint, reason = "...")]` replaces blanket `#[allow]` where a lint is known to fire; it warns when the lint stops firing. Lint attributes accept `reason = "..."`. Clippy adds `allow_attributes` and `allow_attributes_without_reason` (restriction group) to enforce this.
- `core::error::Error` makes the `Error` trait available in `no_std` crates.
- `std::fs::exists`, `Duration::abs_diff`, `AtomicBool::fetch_not`, `core::hint::assert_unchecked`.
