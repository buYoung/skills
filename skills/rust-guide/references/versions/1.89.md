# Rust 1.89

Released 2025-08-07.

## Deprecations and Removals

- The warn-by-default `elided_named_lifetimes` lint is superseded by `mismatched_lifetime_syntaxes`; rename it in `[lints]` tables and attributes. The new lint asks for consistent elision between inputs and outputs, for example `&[u8]` in and `Iter<'_, u8>` out.
- This is the last release with `x86_64-apple-darwin` at Tier 1; the demotion to Tier 2 with host tools takes effect in [1.90](1.90.md).
- The deprecated `std::intrinsics::copy`, `copy_nonoverlapping`, and `write_bytes` are now real intrinsics without debug-assertion checks and can no longer be coerced to function pointers; `std::intrinsics::drop_in_place` is removed. Use the `std::ptr` functions.

```rust
// Warns since 1.89 with "hiding a lifetime that's elided elsewhere is confusing":
// pub fn items(scores: &[u8]) -> std::slice::Iter<u8> { scores.iter() }

// Fixed: the path type names the elided lifetime with `'_`, matching the `&[u8]` input.
pub fn items(scores: &[u8]) -> std::slice::Iter<'_, u8> {
    scores.iter()
}
```

## Migration Instructions

- `dangerous_implicit_autorefs` is deny-by-default; fix every remaining implicit autoref through a raw-pointer dereference.
- `missing_fragment_specifier` is a hard error in every edition: `macro_rules!` matchers with an unused metavariable lacking a fragment specifier (`$name` without `:expr` or similar) must be removed or completed.
- `i128` and `u128` are removed from `improper_ctypes_definitions`; they are C-compatible with `__int128` where the platform provides it. Delete `#[allow(improper_ctypes_definitions)]` added for them.
- `extern "C"` on `wasm32-unknown-unknown` now follows the standard C ABI; regenerate JavaScript glue or bindings that relied on the old layout.

## Behavior Changes Requiring Attention

- `cargo test --doc --target <triple>` runs doctests cross-compiled for the target; an `ignore-<target>` doctest attribute skips one target.

## Replacement APIs Worth Adopting

- `_` for const generic arguments in expressions (not in signatures or const items); `#[repr(u128)]` and `#[repr(i128)]`.
- `File::lock`, `lock_shared`, `try_lock`, `try_lock_shared`, `unlock`; `Result::flatten`; `NonZero<char>`; `OsString::leak`, `PathBuf::leak`.
