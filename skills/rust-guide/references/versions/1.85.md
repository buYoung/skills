# Rust 1.85 and Edition 2024

Edition 2024 ships with this release: `edition = "2024"` requires Rust 1.85.0 or later, so a library that adopts it raises its MSRV to at least 1.85.

## Deprecations and Behavior Changes in the Release

- `std::env::home_dir()` on Windows now ignores a non-standard `HOME` variable; the long-standing deprecation is lifted in [1.87](1.87.md).
- In edition 2024 only: `std::env::set_var`, `std::env::remove_var`, and `CommandExt::before_exec` are `unsafe fn`; `Future` and `IntoFuture` join the prelude; `Box<[T]>::into_iter()` yields values; `resolver = "3"` is the default.
- Async closures (`async |args| { ... }`) and the `AsyncFn`, `AsyncFnMut`, `AsyncFnOnce` traits are stable in every edition and replace `impl Fn(..) -> impl Future` workarounds.

## Edition 2024 Migration: Collect Inputs

- Toolchain at or above 1.85.0 everywhere the crate builds: developer machines, CI, and the MSRV job.
- Workspace layout: each member declares its own `edition`; a virtual workspace must set `resolver` in `[workspace]` because members' `edition = "2024"` does not change the workspace resolver.
- Inventory of edition-sensitive code: `extern` blocks; `#[no_mangle]`, `#[export_name]`, `#[link_section]`; `unsafe fn` bodies; `static mut`; `std::env::set_var`/`remove_var`; `CommandExt::before_exec`; public functions returning `impl Trait`; `macro_rules!` using `$x:expr`; identifiers named `gen`; `.into_iter()` on `Box<[T]>`; user traits with methods named `poll` or `into_future`; `if let` whose scrutinee holds a lock guard or other temporary with a destructor; blocks whose tail expression borrows a temporary; macro inputs containing `#"` or `##`; generic code that relied on `!` falling back to `()`; doctests asserting `std::panic::Location` lines or `std::any::type_name` paths; `#[doc = include_str!(...)]` files with nested `include!`; editor rustfmt configuration.
- A clean working tree: `cargo fix` refuses to run with uncommitted changes unless `--allow-dirty` is passed.

## Procedure

Apply the migration per package:

1. `cargo update` so the migration runs against current dependencies.
2. `cargo fix --edition` while still on the old edition. Run it for every target and feature combination the crate compiles (`--all-targets`, `--all-features` or each meaningful feature set), because `cargo fix` rewrites only code it compiles. Read every warning it leaves; those are the changes it cannot make.
3. Set `edition = "2024"` in `Cargo.toml`. In a virtual workspace also set `resolver = "3"` in `[workspace]`.
4. `cargo build` and `cargo test`. Fix remaining errors and warnings by hand using the table below.
5. `cargo fmt`. Commit a `rustfmt.toml` with `style_edition = "2024"` so editors that call `rustfmt` directly format the same way as `cargo fmt`.

Migrate one package at a time in a large workspace; edition is per package and mixed editions compile together.

## Change Table

`Auto` means `cargo fix --edition` rewrites the code; `Manual` means it only warns or cannot detect the case.

| Change | Migration lint | Auto | Manual attention |
|---|---|---|---|
| `impl Trait` in return position captures all in-scope lifetimes | `impl_trait_overcaptures` | Auto inserts `use<..>` | Argument-position `impl Trait` cannot be named in `use<..>`; the fix changes the signature. Decide per public API whether to keep the old capture set via `use<..>` or accept the new one; callers can observe the difference. Remove old `Captures`/outlives tricks by hand. |
| `if let` scrutinee temporaries drop before `else` | `if_let_rescope` | Auto rewrites to `match` to preserve old timing | Review each rewrite: the new drop order is usually what lock-holding code wants. Revert the `match` where the earlier drop is desirable. |
| Tail-expression temporaries drop before block locals | `tail_expr_drop_order` | Manual | Borrow errors such as `let n = { &String::from("x") }.len();`. Bind the temporary in a `let` first. |
| Match ergonomics restrictions on `mut`, `ref`, `&` in default-binding-mode patterns | `rust_2024_incompatible_pat` | Auto | None beyond review. |
| `extern` blocks must be `unsafe extern` | `missing_unsafe_on_extern` | Auto inserts `unsafe` | Verify every declared signature; the tool cannot. Mark items `safe` only when calling them is sound with any arguments. |
| `#[no_mangle]`, `#[export_name]`, `#[link_section]` become `#[unsafe(...)]` | `unsafe_attr_outside_unsafe` | Auto | Check symbol-name collisions and document the justification. |
| Unsafe operations inside `unsafe fn` need an `unsafe {}` block | `unsafe_op_in_unsafe_fn` (warn in 2024) | Auto inserts blocks | Attach a `// SAFETY:` comment per block instead of one per function. |
| References to `static mut` denied | `static_mut_refs` (deny in 2024) | Manual | Replace with atomics, `Mutex`/`RwLock`, `OnceLock`/`LazyLock`, or `&raw const`/`&raw mut` when a pointer is unavoidable; code in [replacing static mut](../practices/unsafe-and-ffi.md#replacing-static-mut). |
| Never-type fallback becomes `!` instead of `()` | `never_type_fallback_flowing_into_unsafe` (deny) | Manual | Write the intended type explicitly where `?`, `panic!`, or diverging closures left inference to fallback. |
| `expr` fragment also matches `const {}` and `_` | `edition_2024_expr_fragment_specifier` | Auto rewrites to `expr_2021` | Most macros want plain `expr`; revert unless a rule ordering depends on the old exclusion. |
| `gen` reserved | `keyword_idents_2024` | Auto rewrites to `r#gen` | Rename in public APIs deliberately; `r#gen` is legal but awkward for callers. |
| `#"..."#` and `##` reserved | `rust_2024_guarded_string_incompatible_syntax` | Auto inserts spaces | Only macro inputs are affected. |
| Prelude adds `Future` and `IntoFuture` | `rust_2024_prelude_collisions` | Auto qualifies ambiguous calls | User traits with `poll` or `into_future` methods. |
| `Box<[T]>::into_iter()` yields `T` instead of `&T` | `boxed_slice_into_iter` | Auto rewrites to `.iter()` | `for x in boxed_slice` already yielded `T` since 1.80 in every edition. |
| `set_var`, `remove_var`, `before_exec` become `unsafe` | `deprecated_safe_2024` | Auto wraps in `unsafe {}` with a TODO comment | Audit that no other thread can read the environment concurrently; prefer `Command::env` or a configuration struct. |
| Cargo `resolver = "3"` (MSRV-aware resolution) | none | Implied by `edition = "2024"` for the root package | Virtual workspaces set it explicitly. CI should also test with newest compatible dependencies so MSRV-capped resolution does not hide breakage. |
| Cargo removes `[project]`, `default_features`, `crate_type`, `proc_macro`, `[dev_dependencies]`, `[build_dependencies]` | none | Auto rewrites `Cargo.toml` | None. |
| Cargo rejects `default-features = false` on a `workspace = true` dependency whose workspace entry keeps defaults | none | Auto removes the ineffective override | Move `default-features = false` to `[workspace.dependencies]` if members need to opt in. |
| Rustdoc compiles doctests together | none | none | Add `standalone_crate` to doctests that break under combined compilation (line numbers, `type_name`; global attributes are auto-detected). |
| Nested `include!` in `#[doc = include_str!]` resolves relative to the Markdown file | none | Manual | Fix the paths the errors point at. |
| Rustfmt style edition 2024 | none | `cargo fmt` reformats | Commit `style_edition` so editor formatting matches. |

Edition 2024 also unlocks `let` chains (`if let Some(a) = x && a > 0 && let Ok(b) = y`) from Rust 1.88.0, which are edition-2024-only; `if let` guards in `match` arms (1.95.0) are listed in the release notes without an edition restriction. Neither requires migration work.

## Verify

- `cargo build --all-targets` and `cargo test` on the MSRV toolchain and on current stable; `cargo clippy --all-targets`.
- `cargo doc` and `cargo test --doc`: combined doctests are the most common post-migration surprise.
- For a library: run downstream consumers or a public-API diff to catch capture-rule changes in `impl Trait` returns and any `r#gen` renames.
- For `unsafe`-heavy crates: `cargo miri test` on the migrated code when available; the automatic `unsafe` insertions audited nothing.
- Check that `Cargo.lock` still resolves the intended versions after `resolver = "3"`; a lower `rust-version` can now pull older dependency versions.

## Prohibitions

- Do not flip `edition` first and then chase errors; `cargo fix --edition` must run on the old edition to see the migration lints.
- Do not `#![allow(rust_2024_compatibility)]` or allow `static_mut_refs`, `never_type_fallback_flowing_into_unsafe`, or `unsafe_op_in_unsafe_fn` wholesale; each hides a soundness or drop-order change.
- Do not treat the inserted `unsafe {}` blocks and `unsafe extern` keywords as an audit; they preserve behavior, not soundness.
- Do not combine the edition switch with refactors or dependency upgrades in one commit; keep the migration diff reviewable and revertible.

## Replacement APIs Worth Adopting

- `#[diagnostic::do_not_recommend]` on blanket impls to improve downstream error messages; `FromIterator` and `Extend` for tuples up to 12 elements; `midpoint`; `Waker::noop`; `ptr::fn_addr_eq`.
