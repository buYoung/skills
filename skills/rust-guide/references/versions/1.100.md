# Rust 1.100

## Deprecations and Removals

- `box` patterns are no longer syntactically allowed. They were only available on nightly through `#![feature(box_patterns)]`, which rustc now lists as removed and superseded by the unstable `deref_patterns` feature.
- `i686-pc-windows-msvc` is demoted to Tier 1 without host tools and `i686-pc-windows-gnu` to Tier 2 without host tools. The 1.100.0 distribution ships `rust-std` for both targets but no `rustc` or `cargo`, so a toolchain can no longer be installed on a 32-bit Windows host. Build 32-bit Windows binaries by cross-compiling from a supported host such as 64-bit Windows.

## Migration Instructions

- The never type fallback is `!` in every edition; edition 2024 already used it ([1.85](1.85.md)). In editions 2015 through 2021, inference that relied on the old `()` fallback, for example ignoring the result of a function that returns a generic parameter, can stop compiling, and more code can be reported as unreachable. Write the intended type explicitly as described in [1.92](1.92.md). `dependency_on_unit_never_type_fallback` is removed because the code it reported no longer compiles; `never_type_fallback_flowing_into_unsafe` remains deny-by-default. If a dependency fails because of this change, update it first; the announcement notes that fixes were released for affected public crates.
- `Infallible` is now a type alias of `!`.
- On ARM targets, `-Ctarget-feature` and `-Ctarget-cpu` values that would alter the ABI are rejected as hard errors.
- From 1.94 up to 1.100, several ARMv7-A hardfloat targets wrongly included `d32` in their baseline features and therefore required a `VFPv3-D32` FPU. Builds broken by the correction can pass `-Ctarget-feature=+d32`.
- Cargo uses a new directory layout for intermediate build artifacts. The layout is not a stable interface; tools that inspected the build directory should locate artifacts through Cargo's JSON messages.
- Cargo reports some warnings as lints controlled in `[lints.cargo]`, keyed by the lint name without the `cargo::` prefix. `cargo::unused_dependencies` warns by default about unused `[dependencies]` and `[build-dependencies]` entries; it fires only when every target that can use a dependency table is built, and `[dev-dependencies]` are not checked.
- `cargo install` uses the lockfile shipped in the `.crate` tarball by default; `--locked` is a no-op.

## Behavior Changes Requiring Attention

- Closures capture variables used in `if let` more precisely, dyn-compatibility is checked in more places, and some `Box` impls are generalized to arbitrary allocators. Each can produce new compile errors in existing code.
- `Iterator::min`, `max`, `min_by_key`, and `max_by_key` call different `Ord` methods. Results can change only for types with inconsistent `Ord` implementations.
- The standard library uses Unicode 18.0.0, and `str::escape_debug` always escapes grapheme extenders. The WASI SDK moves from 33 to 34. Enabling SSE or AVX on an x86 softfloat target is an error.

## Replacement APIs Worth Adopting

- The never type `!` can be named in any type position (`Result<T, !>`); `!` implements `AsRef<T>` and `AsMut<T>`.
- Custom allocators: the `Allocator` trait with `Global` and `System`, `Box::new_in`, `Vec::new_in`, `Vec::with_capacity_in`, and the matching raw-parts functions. `Vec` and `Box` are currently the standard types that accept them.
- `core::mem::DropGuard` runs a closure on every exit path, and `DropGuard::dismiss` returns the value without running it. `mem::conjure_zst` (unsafe) creates a zero-sized value instead of transmuting `()` or calling `MaybeUninit::uninit().assume_init()`.
- `Box::take`, `Box::map`, `Rc::map`, `Arc::map`; `Vec::from_fn`; `bool::toggle`; `str::trim_prefix`, `trim_suffix` and the slice forms; `Path::trim_prefix`; `UnsafeCell::replace`, `as_ref_unchecked`, `as_mut_unchecked`; `Default` for `Once`.
- Cargo: `[registry] global-min-publish-age` in `.cargo/config.toml` makes the resolver skip versions published more recently than the configured age unless they are already in `Cargo.lock`. Targets: `wasm32-wasip3` Tier 2.
