# Rust 1.99 and 1.100 Coverage Record (2026-11-27)

## Scope

Extended release coverage from 1.98.1 to 1.100.0. Both releases contain official deprecations, removals, or migration notes, so each has a file under `references/versions/` and an index row, following the procedure in `2026-09-18-sources-and-verification.md`.

Statements that the new releases made stale were corrected: the never-type rows in `1.85.md` and `1.92.md`, the inherited `default-features` row in `1.85.md`, the i686 Windows toolchain note and benchmark harness advice in `1.88.md`, incremental compilation in CI, `cargo install --locked`, unused-dependency detection and the toolchain pin example in `build-configuration.md`, C-variadic definitions in `unsafe-and-ffi.md`, and inherited defaults in `workspaces-and-monorepos.md`. `build-configuration.md` also warns against writing PR-readable `target/` caches from jobs that hold secrets. The 1.93.0 index row now names the third 1.93.1 fix listed in RELEASES.md, `wasm32-wasip2` file descriptor leaks. Availability tables gained 1.99 and 1.100 rows where the releases affect their topic. The benchmark harness recommendation now follows the adoption floor (below).

The 0.1.100 counts are the group labels on the [stable lint list](https://rust-lang.github.io/rust-clippy/stable/index.html), whose total of 832 matches their sum. The Clippy changelog marks Rust 1.100 as current stable. `cargo clippy -- -W help` on the local Clippy 0.1.99 gave the same counts except suspicious 85 and complexity 144; the difference is the two lints added in 1.100, `option_zip_none` (suspicious) and `needless_nonzero_get` (complexity). The "Added in" labels on the lint list were not used to date lints.

Group moves since 0.1.95, from the [Clippy changelog](https://github.com/rust-lang/rust-clippy/blob/master/CHANGELOG.md): in 1.97 `overly_complex_bool_expr` moved from correctness to pedantic and `nonminimal_bool` from complexity to pedantic; in 1.98 `empty_enums` moved from pedantic to nursery and `from_iter_instead_of_collect` was deprecated. None of these lints is named in the references.

## Verification

Performed locally with rustc 1.99.1 and Cargo 1.99.1 (aarch64-apple-darwin); no 1.100.0 toolchain was installed.

- The 103 fenced `rust` blocks in `references/` were compiled one by one as libraries with edition 2024 and `--emit=metadata`. 97 compiled. The other six are parts of multi-file examples (a pool usage block, module and workspace layouts, the WASI binary) that need their companion files and were not assembled for this record.
- Small probes confirmed the 1.99 claims: a C-variadic definition compiles, `std::i32::MAX` warns as deprecated, a generic `#[unsafe(no_mangle)]` function fails with "functions generic over types or consts must be mangled", and `#[allow(no_mangle_generic_items)]` reports a removed lint.
- 1.100-only APIs and behavior (`!` fallback in edition 2021, `Allocator`, `DropGuard`, `[lints.cargo]`) were taken from the sources above and not compiled.
- The divan example (`rust,ignore`) was not compiled against divan itself; building it would run the downloaded crate's procedural macros. Its crate layout was checked with `cargo bench --no-run --offline`: a library crate exporting `checksum`, the documented `[[bench]]` target with `harness = false`, and the block copied verbatim as `benches/checksum.rs`, built against a locally written stub exposing the same `divan` paths.
- Local Markdown links and anchors in the changed files were checked, and `evals.json` was parsed for shape and unique IDs. Evals 17 and 18 are specifications, not executed model runs.
