# Rust 1.99 and 1.100 Coverage Record (2026-11-27)

## Scope

Extended release coverage from 1.98.1 to 1.100.0. Both releases contain official deprecations, removals, or migration notes, so each has a file under `references/versions/` and an index row, following the procedure in `2026-09-18-sources-and-verification.md`.

Statements that the new releases made stale were corrected: the never-type rows in `1.85.md` and `1.92.md`, the inherited `default-features` row in `1.85.md`, the i686 Windows toolchain note and benchmark harness advice in `1.88.md`, incremental compilation in CI, `cargo install --locked`, unused-dependency detection and the toolchain pin example in `build-configuration.md`, C-variadic definitions in `unsafe-and-ffi.md`, and inherited defaults in `workspaces-and-monorepos.md`. `build-configuration.md` also warns against writing PR-readable `target/` caches from jobs that hold secrets. The 1.93.0 index row now names the third 1.93.1 fix listed in RELEASES.md, `wasm32-wasip2` file descriptor leaks. Availability tables gained 1.99 and 1.100 rows where the releases affect their topic. The benchmark harness recommendation now follows the adoption floor (below).

## Release Calendar Metadata

- `1.99.md`: Released 2026-10-01; point release 1.99.1 on 2026-10-15. The 1.99.1 announcement calls its fixes "regressions from prior releases" without naming the first affected version. The first affected versions come from the issues and pull requests linked from the 1.99.1 release notes and the stable backport [#164232](https://github.com/rust-lang/rust/pull/164232):
  - `wcslen`: [#163614](https://github.com/rust-lang/rust/issues/163614) reports 1.98.1 working and 1.99.0 failing; 1.99.0 moved to LLVM 23.
  - FFI `bool`: [#163911](https://github.com/rust-lang/rust/issues/163911) compares 1.98.0 and 1.99.0 code generation; the cause, [#159317](https://github.com/rust-lang/rust/pull/159317), carries the 1.99.0 milestone.
  - `rust-lld`: [#163947](https://github.com/rust-lang/rust/issues/163947) traces the failure to [#157205](https://github.com/rust-lang/rust/pull/157205) (dynamic LLVM on `aarch64-apple-darwin`), which carries the 1.98.0 milestone. The issue title says "regression from 1.96.1" because the report compares only with 1.96.1; the 1.98.0 and 1.98.1 reproductions under Verification confirm the earlier start.
- `1.100.md`: Released 2026-11-12. No 1.100.x point release appears in the release notes at tag 1.100.0.

The 0.1.100 counts are the group labels on the [stable lint list](https://rust-lang.github.io/rust-clippy/stable/index.html), whose total of 832 matches their sum. The Clippy changelog marks Rust 1.100 as current stable. `cargo clippy -- -W help` on the local Clippy 0.1.99 gave the same counts except suspicious 85 and complexity 144; the difference is the two lints added in 1.100, `option_zip_none` (suspicious) and `needless_nonzero_get` (complexity). The "Added in" labels on the lint list were not used to date lints.

Group moves since 0.1.95, from the [Clippy changelog](https://github.com/rust-lang/rust-clippy/blob/master/CHANGELOG.md): in 1.97 `overly_complex_bool_expr` moved from correctness to pedantic and `nonminimal_bool` from complexity to pedantic; in 1.98 `empty_enums` moved from pedantic to nursery and `from_iter_instead_of_collect` was deprecated. None of these lints is named in the references.

## Verification

Performed locally with rustc 1.99.1 and Cargo 1.99.1 (aarch64-apple-darwin), then repeated with rustc 1.100.0 and Cargo 1.100.0 installed through rustup into a separate `RUSTUP_HOME`.

- The 103 fenced `rust` blocks in `references/` were compiled one by one as libraries with edition 2024 and `--emit=metadata`. 97 compiled. The other six are parts of multi-file examples (a pool usage block, module and workspace layouts, the WASI binary) that need their companion files and were not assembled for this record.
- Small probes confirmed the 1.99 claims: a C-variadic definition compiles, `std::i32::MAX` warns as deprecated, a generic `#[unsafe(no_mangle)]` function fails with "functions generic over types or consts must be mangled", and `#[allow(no_mangle_generic_items)]` reports a removed lint.
- With 1.100.0, 98 of 104 `rust` blocks compiled; the count adds the four-backtick doc-comment example in `error-handling.md`, and the six failures are the multi-file parts above. Both `compile_fail` blocks failed as intended. Editions 2024 and 2021 gave the same results on 1.99.1 and 1.100.0.
- 1.100 probes: `foo()?` on `fn foo<T: Default>() -> Result<T, ()>` fails with E0277 (`!: Default`) in editions 2015 and 2021, where 1.99.1 reports `dependency_on_unit_never_type_fallback`; with `#[allow(dependency_on_unit_never_type_fallback)]` 1.99.1 compiles it and 1.100.0 reports the lint as removed and still fails. `never_type_fallback_flowing_into_unsafe` still denies `unsafe { mem::zeroed() }` in a diverging `if`. A `box` pattern fails with "`box` patterns have been removed" instead of E0658. `Result<T, !>`, passing `Result<(), Infallible>` where `Result<(), !>` is expected, and `<! as AsRef<str>>` compile. A user `Allocator` works with `Vec::with_capacity_in`, `Box::new_in`, `Vec::into_raw_parts_with_allocator`/`from_raw_parts_in`, and `Box::into_raw_with_allocator`/`from_raw_in`; `Rc`, `Arc`, `VecDeque`, `BTreeMap`, and `LinkedList` `new_in` are still unstable (`allocator_ext`). `DropGuard` ran its closure on early return, normal return, and unwinding, and `DropGuard::dismiss` returned the value without running it. `conjure_zst` on `u8` panics. The other APIs named in `1.100.md` compiled and ran.
- Cargo 1.100.0: `cargo::unused_dependencies` reported unused `[dependencies]` and `[build-dependencies]` path dependencies under `cargo build`, did not report `[dependencies]` under `cargo check --lib`, and never reported `[dev-dependencies]`; `[lints.cargo] unused_dependencies = "deny"` failed the build, `"allow"` silenced it, and a `cargo::`-prefixed key failed to parse. With `[registry] global-min-publish-age = "10 months"` a fresh resolution picked criterion 0.8.1 instead of 0.8.2 (published 2026-02-04), and a build kept 0.8.2 already in `Cargo.lock`. Bench executables moved from `target/release/deps/` (1.99.1) to `target/release/build/<package>/<hash>/out/` (1.100.0).
- The divan example was built and run with `cargo bench` on 1.100.0 against divan 0.1.21 from crates.io: a library crate exporting `checksum` (the block above made `pub`), the documented `[[bench]]` target with `harness = false`, and the block copied verbatim as `benches/checksum.rs`. It printed one `checksum_64_kib` row with fastest, slowest, median, mean, samples, and iters columns.
- 1.99.1 regressions, reproduced with rustup toolchains 1.97.1, 1.98.0, 1.98.1, 1.99.0, and 1.99.1 on aarch64-apple-darwin: `rust-lld -flavor wasm --version` run directly loads `@rpath/libLLVM.dylib` and fails in 1.98.0 through 1.99.0, and works in 1.97.1 (no `libLLVM` dependency) and 1.99.1 (extra rpath `@loader_path/../../../`). The FFI `bool` function from #163911 compiled for `x86_64-unknown-linux-gnu` with `-C opt-level=3` lacks `andb $1, %al` only in 1.99.0. A `u16` length loop compiled for `x86_64-unknown-uefi` calls `wcslen` in 1.99.0 and 1.99.1 but not in 1.98.1, and only the 1.99.1 `compiler_builtins` defines a weak `wcslen`.
- Local Markdown links and anchors in the changed files were checked, and `evals.json` was parsed for shape and unique IDs. Evals 17 and 18 are specifications, not executed model runs.
