# 문서 작성 평가 하네스 개선 요구사항

이 명세는 하네스 유지보수자가 실행 조건과 평가 근거를 일관되게 보존하도록 요구되는 동작과 완료 기준을 정의한다. 기준일은 2026-09-06이며, 이번 산출물은 요구사항 문서다. 하네스 구현, 평가 실행, 테스트 추가, 릴리스 변경은 포함하지 않는다.

사용자가 수용한 FDD 정책 적용범위 보존 수정은 `9a44c4d`로 커밋된 해결 사항이다. 이를 미해결 스킬 결함으로 다시 분류하지 않는다. 이 세션에서 확인한 최근 측정은 생성 `gpt-5.6-luna` / `high`, 분석 `gpt-6-astra` / `medium`의 단일 실행이며, 표적 정책범위 보존은 `1/3`에서 `3/3`으로 개선됐다. 이 수치는 전체 FDD 품질이나 정식 `production_ready` 통과를 뜻하지 않는다.

## 적용 범위와 근거 해석

- **세션 관찰**은 이번 세션의 수동 실행과 도구 기록에서 확인·정정한 사실이며, **사용자 결정**은 사용자가 수용하거나 요청한 범위다. 수동 실행 관찰을 기존 정식 실행기의 동일 결함을 입증하는 코드 증거로 확대하지 않는다.
- **코드 확인**은 아래에 연결한 현재 저장소 원문의 동작이다. 함수명과 행 번호는 기준일의 탐색 위치이며 이후 변경될 수 있다.
- **수정 요구**는 이후 하네스가 충족해야 할 계약이다. **미정**은 이 문서가 확정하지 않은 구현 선택이다.
- 아래의 완료 기준은 후속 수정의 수용 조건이다. 이번 작성 과정에서 실행해 통과시킨 검증 결과가 아니다.
- 실행 기록(receipt)은 하네스가 작업·응답·파일 목록에서 계산한 기록을 뜻한다. 세션 증거는 호스트가 제공한 실제 요청·도구 호출·결과 기록을 뜻하며, 두 기록의 증명 범위는 다르다.

## R1 실행 환경과 지침 격리

**관찰 근거:** 이 세션의 수동 경량 실행 기록에서는 `fork_turns: none`이어도 실제 사용자 메시지에 저장소 `AGENTS.md`가 전달됐다. 따라서 대화 이력 미상속만으로 저장소 지침까지 격리됐다고 볼 수 없다. 기존 정식 실행기도 같은 유입을 일으켰는지는 미확인이다.

**현재 보장:** [실행기](../scripts/run_production_evals.py)의 `worker_dispatch_message`와 `execution_policy_for_case`(385–426행)는 제공 스킬 사본과 작업공간만 사용하고 형제 실행·기존 평가 근거를 보지 않도록 지시한다. `direct_behavior_prepare_stage`는 작업별 디렉터리와 스킬 사본을 생성한다. 이 코드는 작업 전달문을 만들며, 호스트의 실제 지침 주입까지 입증하지 않는다.

**수정 요구:** 평가가 허용한 지침과 호스트가 실제 제공한 관련 지침의 출처를 실행에 연결해야 한다. 선언된 격리 설정, 확인된 유입 지침, 확인 불가능한 영역을 구분해야 한다. 상충 지침이 결과에 영향을 주는 실행을 스킬 단독 실패로 확정해서는 안 된다.

**완료 기준:** 저장소 언어 지침이 유입된 수동 실행은 환경 영향을 식별할 수 있어야 한다. 격리가 확인되지 않으면 그 상태와 비교 제한을 표시해야 한다. 형제 실행·이전 점수·비공개 기대값을 생성자에게 전달하지 않는 기존 경계는 유지해야 한다.

## R2 응답과 산출물 언어

**관찰 근거:** 수동 실행에는 ‘한국어 서술’과 ‘저장소 산출물 영어 기본’이 함께 유입됐다. 이 때문에 언어 오류를 스킬 단독 문제로 본 초기 결론은 철회됐다. 이는 이 세션에서 확인한 환경 진단이며, 현재 스킬의 미해결 결함 목록에 넣지 않는다.

**현재 보장:** `public_direct_task`(360–382행)는 원래 `prompt`를 전달한다. `execution_policy_for_case`의 `response_contract`에는 질문 수만 선택적으로 들어간다. 별도의 응답 언어·파일 언어 필드는 이 공개 작업 계약에 없다. [스킬](../SKILL.md)의 출력 위치·보존 규칙과 사용자의 명시 지시는 계속 유효하다.

**수정 요구:** 평가가 기대하는 대화 응답 언어와 저장 파일의 서술 언어를 각각 식별하고, 명시 사용자 요청인지 환경 기본값인지 출처를 남겨야 한다. 언어가 평가 대상이면 생성자가 받은 계약과 채점자가 적용하는 계약이 같아야 한다. 원문 코드 블록·경로·식별자를 번역 대상으로 잘못 판정해서는 안 된다.

**완료 기준:** 사용자 요청과 환경 규칙이 충돌한 결과에는 충돌 근거가 남아야 한다. 언어 계약이 불명확한 실행에 임의의 정답 언어를 붙여 기존 점수를 변경해서는 안 된다. 언어 조건을 바꾼 실행은 별도 조건으로 식별해야 한다.

## R3 작업 경계와 출력 위치

**관찰 근거:** 수동 실행에서는 작업 경계인 `workspace`와 사용자 지정 출력루트가 구분되지 않아 FDD가 작업공간 바로 아래에 생성되기도 했다. 문서 위치 오류와 색인 자체 부재는 서로 다른 산출물 문제다.

**현재 보장:** 공개 작업은 `workspace`, `response_path`, 허용 쓰기 경로를 전달한다. [FDD 작성 규칙](../references/document-types/feature-design-doc/feature-design-doc-create.md)은 기본 본문 경로 `docs/FDD/<kebab-case-feature-name>.md`와 `docs/FDD/index.md`를 명시한다. [스킬의 파일 출력 규칙](../SKILL.md)은 사용자 지정 위치를 우선한다.

**코드 경계:** 실행기의 `select_primary_fdd`(554–568행)는 `workspace/docs/FDD`에서만 본문을 찾고 `index.md`를 제외한다. `run_deterministic_validators`는 이 결과를 FDD 검사기에 전달한다. 따라서 사용자 지정 위치 지원을 작업 메시지에만 추가하면 최종 검사 위치가 일치하지 않을 수 있다.

**수정 요구:** 작업 경계, 사용자가 지정한 출력루트, 기본 상대 경로, 실제 확정 출력 위치를 구별해야 한다. 사용자 지정이 없으면 기본 경로를 작업 경계 아래에서 해석해야 한다. 명시 경로는 허용 쓰기 범위·파일 탐색·검사기·검토 묶음에 일관되게 전달해야 한다. 본문 선택 성공이 색인 완전성을 대신해서는 안 된다.

**완료 기준:** 기본 FDD 경로와 사용자 지정 경로 양쪽에서 실제 저장 위치와 검사 대상이 같아야 한다. 색인 누락은 본문 위치 오류와 별도로 보고해야 한다. 허용 범위를 벗어난 경로는 기존 경계를 우회하거나 조용히 다른 위치로 바꾸지 않고 계약 오류로 식별해야 한다.

## R4 역할별 모델과 추론 강도

**관찰 근거:** 사용자가 요청한 생성 설정은 `gpt-5.6-luna` / `high`, 분석 설정은 `gpt-6-astra` / `medium`이다. 이는 지원해야 할 조합이며 정식 기본값 변경 결정은 아니다.

**현재 보장:** [평가 모음](../evals/production-suite.json)의 `runtime`은 `gpt-5.6-luna` / `medium`이다. 실행기 상수(39–40행)를 `public_direct_task`와 `direct_grading_prepare_stage`가 공유한다. 현재 CLI에는 역할별 모델 설정 인자가 없다. [패키지 검사기](../scripts/validate_package.py)의 `validate_production_suite`는 같은 고정값을 요구한다.

**현재 보장과 한계:** 실행 기록은 작업의 `model`, `reasoning_effort`를 복사하고 [실행 검사기](../scripts/validate_eval_run.py)(518–519행)는 일치를 검사한다. `validate_independent_grading`도 채점 작업과 결과의 모델·강도 일치를 검사한다. 다만 이 일치가 실제 호스트 모델을 증명하지는 않는다. 채점 출처 문자열도 현재 `independent-luna-grader-output`에 묶여 있다.

**수정 요구:** 생성과 분석의 모델·추론 강도를 별도로 확정하여 실제 호출, 전달 작업, 실행 기록 또는 채점 기록, 검사기, 집계, 보존 근거까지 전달해야 한다. 실제 호스트 확인값과 요청값은 구별해야 한다. 전역 상수 하나만 변경하거나 모델 이름을 결과 JSON에 적는 것으로 지원 완료를 선언해서는 안 된다.

**완료 기준:** 요청 조합이 두 역할에 각각 적용된 근거가 있어야 하며, 불일치·미확인은 드러나야 한다. 집계에서도 두 역할을 복원할 수 있어야 한다. 기존 Luna `medium` 기록은 당시 설정으로 읽혀야 한다. 새 CLI·JSON 키와 기본값은 미정이다.

## R5 운영 시점의 원시 증거

**관찰 근거:** 수동 실행 원시 도구 로그를 나중에 `~/.codex/sessions`에서 찾아 참조 실제 열람, 잘린 출력 복구, 검증 호출, 산출물 재열람과 교정을 확인했다. 모델의 완료 설명만으로는 이 동작을 입증할 수 없었다.

**현재 보장:** [평가 설명](../evals/README.md)의 스키마 3 경계와 `build_harness_execution_receipt`(476–494행)는 작업·응답 해시·전후 파일 목록에서 실행 기록을 계산한다. 도구 증거가 없으면 `telemetry.status: unavailable`, `capability_evidence.status: unverified`를 유지한다. 생성자에게 도구 기록이나 변경 목록을 자기보고하게 하지 않는 기존 원칙은 유지한다.

**수정 요구:** 실행 시점에 가능한 호스트 증거를 실행 식별자에 연결해야 한다. 대상은 실제 전달 프롬프트, 목적에 필요한 유효 지침의 관련 규칙·출처·해시, 역할별 모델 설정, 도구 호출과 결과, 원본 응답·산출물이다. 호출 성공 여부와 결과 잘림·복구 관계도 확인할 수 있어야 한다.

**보존 경계:** 비공개 추론, `system`·`developer` 메시지 전체, 비밀값을 새로 수집하는 요구가 아니다. 민감 정보는 제외하거나 가리고 그 제한을 표시해야 한다. 보존 위치·기간·호스트 연계 방식은 미정이며, 세션 증거와 하네스 계산 기록의 출처를 섞어서는 안 된다.

**완료 기준:** ‘참조를 읽었다’는 판정에서 관련 호출·결과를 찾을 수 있거나 증거 미확인을 확인할 수 있어야 한다. 없는 원시 기록을 모델 자기보고로 채워서는 안 된다. 나중에 발견된 세션 증거는 발견 시점과 기존 기록의 관계를 남겨야 한다.

## R6 판단 기준의 버전과 재채점

**관찰 근거:** 이 세션에서는 동일한 수정 직전 산출물이 한 분석에서 `4/7`, 이후 재채점에서 `3/7`로 판정됐다. 추가 기각 사유를 기준 밖 소견으로 둘지 해당 기준의 실패로 볼지 해석이 달라졌기 때문이다. 별도 이전 산출물의 `5/7`까지 섞어 이 값들을 모두 동일 조건의 실행 성능 차이로 비교해서는 안 된다.

**현재 보장:** 실행기는 평가 기대값을 채점 작업에 전달하고 `validate_independent_grading`(850–873행)이 기대값별 기록 수·원문·합계를 확인한다. [패키지 검사기](../scripts/validate_package.py)의 `contract_digest`(295–315행)는 선택된 `evals.json` 항목의 `prompt`와 `expectations`를 포함하며, 582–583행은 저장 해시와 현재 해시를 비교한다. 기준 원문의 변경 감지는 이미 존재한다.

**비교 경계:** 현재 정식 흐름은 [평가 설명](../evals/README.md)의 ‘현재 버전만 실행’ 계약이며, 이전 버전과의 비교나 반복 실험을 이미 제공한다고 설명하지 않는다. 원문 해시 일치만으로 원문을 해석하는 기준까지 동일했다고 입증할 수는 없다.

**수정 요구:** 판단 기준의 원문뿐 아니라 적용범위·해석 변경도 식별 가능한 버전으로 관리해야 한다. 비교 시 이전·수정 결과를 동일 버전 기준으로 재채점해야 한다. 과거 점수는 원래 기준과 함께 보존하고 재채점 결과를 구별해야 한다. 산출물과 기준이 달라진 경우 단순 점수 정정으로 덮어쓰지 않는다.

**완료 기준:** 동일 산출물의 `4/7 → 3/7` 재채점과 실제 산출물 변경에 따른 점수 변화를 구분할 수 있어야 한다. 같은 기준으로 양쪽을 다시 채점하지 못하면 직접 비교 불가를 표시해야 한다. 기존 원문 동결·해시 검증은 유지하며 상세 경계는 R9를 따른다.

## R7 판정 종류와 집계 범위

**관찰 근거:** 언어·경로 환경 문제, 문서 편집 규약, 실제 정책 동작의 보존 여부를 같은 실패로 취급하면 원인이 뒤섞인다. 표적 정책범위 보존 `3/3`도 전체 FDD 통과와 다른 측정이다.

**현재 보장:** `aggregate_stage`(986–1090행)는 실행 유효성, 결정적 검사, 독립 채점 형식, 의미 통과를 분리한다. 점수 가능 조건과 전체 범위 통과도 따로 계산한다. 채점이 없으면 평균은 `null`이며, 표적 범위는 정식 범위 적격성을 얻지 않는다. 이 보호 장치를 없는 기능으로 기술하거나 약화해서는 안 된다.

**수정 요구:** 환경 때문에 판정할 수 없는 상태, 편집 규약 불충족, 실제 제품 동작 오류를 구분하여 기존 판정 계층에 연결해야 한다. 환경 무효를 의미 실패나 통과로 치환해서는 안 된다. 종류별 분모, 미채점 수, 표적 항목, 실행 횟수를 드러내야 한다.

**완료 기준:** 언어 지침 충돌은 정책범위 보존 실패와 구분되어야 한다. `1/3 → 3/3`은 해당 표적과 단일 실행이라는 제한을 유지해야 한다. 의미 채점 형식이 유효해도 환경·전체 산출물 계약이 미충족이면 정식 통과로 승격되지 않아야 한다.

## R8 빈 작업공간과 증거 보존

**적용 계약:** 쓰기가 금지된 검토·질문 실행에서는 작업공간에 파일이 없는 결과도 유효할 수 있다. 파일 없음과 작업공간 누락은 구별해야 한다.

**관찰 근거:** 기준일에 확인한 `eval-10`과 `eval-27`의 보존 자료에서는 `workspace` 디렉터리가 없었지만, 두 실행의 이후 목록은 `exists: true`, `entries: []`, `files: {}`를 기록했다. 원래 파일이 있는 산출물이 유실됐다는 증거는 아니며, 정확한 디렉터리 소실 경로는 미확인이다. 실행 결과는 이제 저장소에 보관하지 않으므로 현재 동작은 평가를 다시 실행해 확인한다.

**현재 보장과 한계:** 실행기 `evidence_stage`(1264–1285행)는 존재하는 작업공간을 복사하고 경로를 기록한다. 패키지 검사기(502–509행)는 해당 디렉터리가 없으면 실패하며, 있으면 파일 해시와 이후 목록을 비교하고 심볼릭 링크를 거부한다. 이 복사 구간에는 빈 디렉터리의 배포·복원을 위한 별도 표현이 없다.

**수정 요구:** 빈 작업공간을 포함한 실행 결과를 보존하고 새 체크아웃에서 검증할 수 있어야 한다. 보존 형식은 작업공간 존재와 파일 목록을 함께 복원하거나 확인할 수 있어야 한다. 검증을 통과시키려고 사용자 산출물에 임의의 표식 파일을 추가해서는 안 된다.

**완료 기준:** Git 체크아웃·아카이브·복제 이후에도 파일이 없는 유효 실행의 전후 상태와 응답을 다시 확인할 수 있어야 한다. 파일이 있어야 하는 작업공간의 누락·변조·심볼릭 링크는 계속 실패해야 한다. 목록에서 빈 상태를 복원할지 별도 보존 표현을 둘지는 미정이다.

## R9 결과 동일성과 재사용

**현재 보장:** [평가 설명](../evals/README.md)의 선택 결과 재사용은 설명문·데이터셋·기존 증거의 SHA-256 일치를 요구한다. 기준일에 확인한 실행 결과는 `diagnostic-failed`, `targeted-failed`, `production_ready: false`, `trust_boundary: local-unattested`를 명시했다. 실행 결과 파일은 현재 평가를 실행할 때 로컬에 생성하며, 과거 수동 측정을 새 실행 결과로 대체하지 않는다.

**코드 확인:** `contract_digest`는 `SKILL.md`, 일부 스크립트, 디자인 시스템 유형 참조, 공유 참조 3개와 평가 입력을 포함한다. 그러나 FDD와 일반 8종의 유형 참조 및 `validate_fdd.py`는 포함하지 않는다. 정식 범위에 FDD 평가가 있으므로 이 누락은 실제 실행 의존자료의 변경을 현재성 해시가 모두 감지하지 못하는 경계다.

**수정 요구:** 실행 결과를 재사용하거나 비교할 때 스킬 사본, 프롬프트, 판단 기준 버전, 산출물 종류, 언어, 확정 경로, 두 역할의 모델·강도, 유효 지침 조건의 동일성을 판단할 수 있어야 한다. 비교 실험에서 의도적으로 바꾼 조건은 변경 변수로 명시하고, 그 외 조건의 동등성은 따로 확인해야 한다.

**수정 요구:** 현재성 검사는 실제 실행 입력과 그 의존자료를 빠짐없이 포함해야 한다. FDD 참조만 수정해도 관련 현재성 해시는 바뀌어야 한다. 이 요구는 이번 `updates/` 문서처럼 실행 입력이 아닌 모든 파일을 무조건 해시에 추가하라는 뜻은 아니다.

**완료 기준:** 조건 변경 뒤 과거 점수를 조용히 재사용하여 통과 상태를 갱신할 수 없어야 한다. 원본 산출물과 연결되지 않거나 필수 조건이 미확인인 결과는 제한을 표시해야 한다. 기존 진단 실패 기록은 당시 계약과 결과를 유지하고, 전체 범위와 필수 검증을 요구하는 패키지 검사기(602–605행)의 승격 제한도 유지해야 한다.

## 호환성과 미정 선택

- 기존 스키마 3 기록의 의미와 실패 상태를 보존해야 한다. 패키지 검사기는 현재 `unavailable`·`null`인 측정값과 `unverified`인 빈 도구 증거를 요구하므로, 새 세션 증거 지원에는 스키마와 소비자 호환성 검토가 필요하다. 새 필수 정보가 없는 과거 기록은 미확인으로 취급하고 당시 실행값을 추정해 채우지 않는다.
- 역할별 설정의 CLI·JSON 키, 기본값 변경 여부, 새 증거 스키마 버전과 호환 읽기 방식은 미정이다.
- 환경 격리의 호스트 구현, 유효 지침 확인 방식, 세션 증거 저장 위치·보존기간·비식별 처리 방식은 미정이다.
- 출력루트의 표현, 기본 경로 해석 결과의 저장 위치, 범위 밖 사용자 경로를 다루는 구체 오류 형식은 미정이다.
- 판정 종류별 상태 이름과 집계 형식, 기준 해석 버전의 표현, 빈 작업공간 보존 형식은 미정이다. 구현 선택은 이 문서의 요구되는 동작을 충족해야 한다.
- `skills/document-writing-workspace/`는 로컬 참고 영역이며 새 체크아웃에 없고 정식 검증 근거가 아니다. 이 문서의 코드 근거는 패키지 내부 상대 링크로 제공한다.

문서의 코드 근거는 연결된 원문의 관련 구간을 읽어 확인했다. 요구사항 구현과 새 모델 측정은 수행하지 않았으며, 위 완료 기준은 후속 수정에서 확인할 대상이다.
