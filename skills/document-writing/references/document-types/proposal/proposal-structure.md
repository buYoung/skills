# Proposal structure

## Default structure

Use the smallest set of sections that makes the decision easy. The responsibilities below are a checklist, not a requirement to render nine separate sections.

For a short, self-contained proposal, prefer:

1. Title
2. Recommendation and decision requested
3. Decision context, evidence, and assumptions
4. Options and tradeoff comparison
5. Decision-changing rationale, risks or conditions, and the exact commitment

Split problem, criteria, impact, risk, mitigation, or unresolved questions into separate sections only when they add information that cannot be understood at the point of decision. Do not create a second inventory of facts or a second summary of the recommendation merely to fill the structure.

## Opening contract

The opening should let the decision-maker answer:

- What are you recommending?
- What decision is needed?
- By when, if timing matters?
- What changes if the decision is accepted?

## Alternatives

Compare credible options against the same criteria. Each option must represent one mutually exclusive operating state. Include the status quo when it is a real option and treat it as continuation of the current operating state unless the source defines it otherwise.

If the current state, cost, or continuation boundary is ambiguous, do one of the following before comparing options:

- State one explicit comparison assumption and show how the decision changes if it is wrong.
- Split the plausible status-quo meanings into distinct scenarios.
- Mark the option as not decision-ready and request the missing definition.

Do not put multiple operating meanings into one row, redefine status quo as shutdown merely to complete a table, or invent weak alternatives to make the recommendation look stronger.
