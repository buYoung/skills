# Authoring an explanatory overview

## Required context

Establish the audience, their likely prior knowledge, the main misconception or knowledge gap, and the takeaway they should retain.

## Drafting sequence

1. Write the conclusion or definition in plain language.
2. Identify two to five ideas needed to support it.
3. Order those ideas from foundational to dependent.
4. Add one concrete example for the hardest abstraction.
5. Remove background that does not change understanding.
6. Add caveats where they affect interpretation.

## Writing patterns

- Introduce a technical term in plain language before using the term repeatedly.
- Use the same word for the same concept.
- Prefer causal explanations over lists of disconnected facts.
- Use analogy only when its limits are stated or unlikely to mislead.
- Keep examples close to the concept they illustrate.

## Avoid

- A table of contents for a short document
- Repeating the summary under every heading
- Lists that replace necessary explanation
- Generic claims such as "improves efficiency" without saying how
- Writing for both novice and expert audiences without declaring the primary reader
