# 로컬 API 서버 실행 가이드

이 문서는 처음 합류한 개발자가 저장소의 로컬 API 서버를 실행하고, 서버와 데이터베이스 연결이 정상인지 단계별로 확인할 수 있도록 안내합니다. 완료되면 API 서버가 `http://localhost:3000`에서 실행되고 `GET /health` 요청에 `{"status":"ok"}`를 반환합니다.

## 사전 조건

다음 도구를 미리 준비합니다.

- Node.js 22 이상
- Docker
- Git

또한 저장소에 접근할 수 있어야 합니다.

## 실행 절차

### 1. 저장소 준비

Git으로 작업할 저장소를 준비한 뒤 저장소의 루트 디렉터리로 이동합니다. 이후 단계의 명령은 이 디렉터리에서 실행합니다.

**확인:** `.env.example`, `package.json`, `docker-compose.yml` 또는 이에 해당하는 Compose 설정 파일이 저장소 루트에서 보이는지 확인합니다.

### 2. 환경 파일 준비

저장소 루트의 `.env.example` 파일을 같은 위치에 `.env`라는 이름으로 복사합니다. 기존 `.env`가 있다면 그 파일을 덮어쓸지 먼저 확인합니다.

**확인:** 저장소 루트에 `.env`가 존재합니다.

### 3. PostgreSQL 시작

저장소 루트에서 다음 명령을 실행합니다.

```bash
docker compose up -d postgres
```

**확인:** 명령이 오류 없이 끝나고 PostgreSQL 컨테이너가 시작됩니다.

### 4. Node.js 의존성 설치

같은 저장소 루트에서 다음 명령을 실행합니다.

```bash
npm ci
```

**확인:** 명령이 오류 없이 끝나고 의존성 설치가 완료됩니다.

### 5. 개발 서버 실행

같은 저장소 루트에서 다음 명령을 실행합니다.

```bash
npm run dev
```

**확인:** 터미널 로그에 다음 문구가 표시됩니다.

```text
Server running on http://localhost:3000
```

개발 서버가 실행 중인 터미널은 종료하지 말고 열어 둡니다.

## 완료 확인

서버가 실행 중인 상태에서 `http://localhost:3000/health`로 `GET /health` 요청을 보냅니다.

정상 응답은 다음과 같습니다.

```json
{"status":"ok"}
```

위 로그와 응답을 모두 확인했다면 로컬 API 서버 실행이 완료된 것입니다.

## 흔한 문제

### 포트 3000 사용 중

서버 시작 시 포트 3000이 이미 사용 중이라는 오류가 표시되면 다른 프로세스가 해당 포트를 사용하고 있는지 확인합니다. 해당 프로세스를 정리하거나 팀에서 정한 방법으로 포트를 비운 뒤 `npm run dev`를 다시 실행합니다. 프로젝트가 다른 포트를 지원하는지는 이 가이드에서 확인되지 않았으므로 임의의 포트 변경은 하지 않습니다.

### `DB connection failed`

데이터베이스 연결 실패가 표시되면 다음을 순서대로 확인합니다.

1. `docker compose up -d postgres`가 오류 없이 완료되었는지 확인합니다.
2. PostgreSQL 컨테이너가 실행 중인지 확인합니다.
3. `.env`가 `.env.example`에서 복사되었고 저장소가 요구하는 데이터베이스 설정을 포함하는지 확인합니다.
4. 확인 후 `npm run dev`를 다시 실행합니다.

이 가이드에는 저장소별 데이터베이스 값이나 별도의 진단 명령이 제공되지 않았으므로, 확인되지 않은 설정값이나 명령은 추가하지 않습니다.
