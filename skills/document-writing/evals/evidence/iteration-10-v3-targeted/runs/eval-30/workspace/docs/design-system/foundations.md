# Foundations

## 공통 원칙

1. **정보가 먼저 보인다.** 제목, 핵심 값, 현재 상태, 다음 행동의 위계를 장식보다 우선한다.
2. **정밀함은 구조에서 만든다.** 정렬, 반복, 명확한 대비와 일관된 형태 언어로 신뢰감을 만든다.
3. **친근함은 제한적으로 쓴다.** 모서리의 완화와 의미 있는 전환의 움직임에서만 드러내며, 정보 구조를 흐리지 않는다.
4. **같음은 원칙에 둔다.** 웹 표와 iOS 흐름, 큰 로고와 16px 아이콘은 동일한 모양이 아니라 동일한 위계·무게·절제 원칙을 공유한다.

## 결정 분류

| 영역 | 불변 | 가변·조건 | 금지 | 검증 |
| --- | --- | --- | --- | --- |
| 색상 | 의미와 상태가 장식보다 우선 | 환경·상태별 표현은 승인된 의미를 보존 | 색으로만 핵심 상태 전달 | 색을 제거해도 라벨·형태로 의미를 이해할 수 있는가 |
| 타이포그래피 | 위계가 한눈에 읽힘 | 웹 밀도와 iOS 폭에 따라 줄바꿈·크기 조정 | 위계가 비슷한 크기로 평탄화됨 | 표의 열 정보와 완료 흐름의 다음 행동이 먼저 읽히는가 |
| 간격·레이아웃 | 정렬과 그룹 관계가 명확함 | 정보량·화면 폭에 따라 밀도와 여백 변화 | 모든 맥락에 같은 밀도 강제 | 조밀한 표에서도 행·그룹 경계가 분명한가 |
| 형태 | 정밀한 기하와 절제된 무게 | 큰 로고는 존재감, 16px 아이콘은 단순성 우선 | 작은 크기에 세부 묘사 추가 | 축소해도 실루엣과 의미가 유지되는가 |
| 깊이·이미지 | 기능을 돕는 최소 표현 | 브랜드가 필요한 접점에서만 표현 강화 | 장식이 정보 계층을 앞섬 | 시각 효과를 줄여도 행동 순서가 유지되는가 |
| 움직임 | 의미 있는 상태 변화만 안내 | iOS 전환과 웹 상태 피드백은 맥락에 맞게 조정 | 주의를 끄는 반복·불필요한 장식 모션 | 모션을 줄여도 상태와 완료가 이해되는가 |

## 대표 검증 해석

- 조밀한 웹 데이터 표에서는 위계·정렬·행 경계가 우선이며, 친근함은 모서리와 상태 피드백에 국한한다.
- 짧은 iOS 완료 흐름에서는 다음 행동과 완료 확인이 우선이며, 화면 폭과 네이티브 전환에 맞춰 밀도와 움직임을 조정한다.
- 큰 헤더 로고는 브랜드 존재감을 허용하지만 제품 UI의 정보 위계를 압도하지 않는다.
- 16px 기능 아이콘은 공통 형태 언어를 유지하되 세부를 덜어 판독성을 확보한다.
