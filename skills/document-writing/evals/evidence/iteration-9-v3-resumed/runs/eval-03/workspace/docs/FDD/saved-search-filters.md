# Saved Search Filters Feature Design Doc

## 1. Document Intent

이 문서는 관리자 웹 대시보드의 Saved Search Filters v1.0이 무엇이며 어떤 사용자 경험과 정책을 제공해야 하는지 정의하는 현재 결정 원본이다. 구현자는 이 문서에 정의된 동작, 권한, 저장 범위, 부분 적용, 결과 상태를 보존해야 한다.

이 문서는 구현 작업 목록, 파일·함수 이름, 작업 순서, 테스트 계획이 아니다.

## 2. Background / Problem

워크스페이스 관리자는 반복적으로 같은 사용자 검색을 수행하지만, 현재는 매번 필터 조합을 다시 설정해야 한다. 이 반복 작업은 검색에 드는 시간을 늘리고, 이전과 동일한 조건을 재현하기 어렵게 만든다.

Saved Search Filters는 현재 필터 조합을 이름과 함께 보존하여 이후 목록에서 다시 적용하도록 한다. 필터 조건의 일부가 나중에 제거되더라도 남아 있는 유효한 조건으로 검색을 계속할 수 있어야 하며, 사용자는 그 결과가 부분적으로 적용되었음을 알아야 한다.

## 3. Feature Definition

Saved Search Filters는 관리자가 현재 사용자 검색 조건을 이름 붙여 저장하고, 자신의 저장 목록에서 적용·이름 변경·삭제할 수 있게 하는 개인 검색 재사용 기능이다.

### This feature is

- 관리자 웹 대시보드에서 반복 검색 조건을 재사용하는 기능이다.
- 사용자와 워크스페이스 조합에 귀속된 개인 저장 필터 기능이다.
- 저장된 필터를 서버에서 JSON으로 보존하고 검색 화면에서 다시 적용하는 기능이다.

### This feature is not

- 여러 관리자가 함께 사용하는 워크스페이스 공유 필터 기능이 아니다.
- 검색 결과나 개인정보 원문을 보존하는 기능이 아니다.
- 검색 필터를 자동으로 기본값으로 선택하거나 사용자가 임의로 정렬하는 기능이 아니다.

## 4. Goals & Non-Goals

### Goals

- 관리자가 반복 검색을 이름으로 저장하고 빠르게 재적용할 수 있게 한다.
- 저장 목록에서 필터를 적용하고, 이름을 변경하고, 삭제할 수 있게 한다.
- 저장된 조건 중 현재도 지원되는 유효한 조건만 적용하며, 누락된 조건은 사용자에게 명확히 알린다.
- 사용자·워크스페이스별 소유권과 이름 고유성을 일관되게 보장한다.
- 키보드만으로 목록 작업을 수행할 수 있고 유니코드와 번역을 지원한다.

### Non-Goals

- 팀 또는 워크스페이스의 검색 지식을 공유하거나 공동 편집하는 것을 목표로 하지 않는다.
- 저장 필터를 검색 화면의 기본 상태로 자동 적용하는 것을 목표로 하지 않는다.
- 검색 사용 패턴에 따라 필터를 자동 정렬하거나 추천하는 것을 목표로 하지 않는다.

## 5. User Model & Core Concepts

### User Model

Users think of this feature as:

- “내가 이 워크스페이스에서 자주 쓰는 사용자 검색을 이름으로 저장하는 목록”이다.
- “목록에서 선택하면 당시의 조건이 현재 검색 화면에 채워지는 기능”이다.
- “일부 조건이 사라졌다면 무엇이 빠졌는지 알려 주는 안전한 복원”이다.

Users should not need to understand:

- 서버 저장 형식이 JSON이라는 사실이나 그 내부 표현 방식.
- 권한 검사나 저장소의 기술적 구조.
- 제거된 필터 필드가 왜 더 이상 적용되지 않는지에 대한 내부 구현 세부사항.

### Core Concepts

| Concept | Meaning |
| ------- | ------- |
| 저장 검색 필터 | 이름과 검색 조건의 조합으로, 한 사용자의 한 워크스페이스에 귀속된다. |
| 필터 조건 | 검색 대상 필드, 연산자, 검색값으로 구성된 재사용 가능한 조건이다. |
| 소유자 | 해당 사용자·워크스페이스 범위에서 저장 필터를 생성하고 관리하는 관리자다. |
| 유효한 조건 | 현재 검색 기능에서 필드와 연산자를 모두 지원하여 적용할 수 있는 조건이다. |
| 부분 적용 | 저장된 조건 중 유효한 조건만 적용하고 나머지는 제외하는 결과다. |

## 6. Relationship to Existing Features

| Existing Feature | Relationship |
| ---------------- | ------------ |
| 관리자 인증 | Reused: 저장 필터의 모든 조회·변경은 기존 관리자 인증을 전제로 한다. |
| 사용자 검색 | Extended: 현재 검색 화면의 필드, 연산자, 검색값을 저장·복원하는 기반이 된다. |
| 워크스페이스 컨텍스트 | Reused: 필터는 현재 워크스페이스 범위 안에서만 식별되고 관리된다. |

## 7. Primary User Flows

### 7.1 Main Flow

```text
관리자가 사용자 검색 조건을 구성하고 저장을 선택한다
  -> 시스템이 이름과 현재 조건을 저장한다
  -> 관리자가 자신의 저장 필터 목록에서 항목을 확인한다
  -> 관리자가 항목을 적용한다
  -> 시스템이 저장 조건을 현재 검색 화면에 반영한다
  -> 관리자가 같은 검색을 다시 실행한다
```

저장 필터 목록은 현재 사용자와 워크스페이스에 속한 항목만 보여 준다. 이름 변경은 기존 항목의 이름만 바꾸며, 새 이름이 같은 범위에서 이미 사용 중이면 변경을 거부한다. 삭제는 사용자가 명시적으로 선택한 자신의 항목에만 적용된다.

### 7.2 Secondary Flow

```text
관리자가 저장 필터 목록에서 이름 변경을 선택한다
  -> 시스템이 새 이름을 입력받는다
  -> 이름이 해당 사용자·워크스페이스 안에서 고유하면 저장한다
  -> 목록에 변경된 이름을 보여 준다
```

```text
관리자가 저장 필터 목록에서 삭제를 선택한다
  -> 시스템이 삭제 대상과 소유권을 확인한다
  -> 해당 저장 필터를 제거한다
  -> 목록에서 항목이 사라졌음을 보여 준다
```

### 7.3 Failure / Partial Success Flow

```text
관리자가 저장 필터를 적용한다
  -> 시스템이 저장 조건을 현재 지원되는 필드·연산자와 대조한다
  -> 유효한 조건만 적용한다
  -> 제외된 조건과 부분 적용 결과를 안내한다
  -> 관리자가 현재 조건을 확인한 뒤 검색을 계속한다
```

이름이 중복되거나 저장 한도에 도달한 경우 저장·이름 변경을 완료하지 않고 원인을 안내한다. 인증이 없거나 소유권 검사가 실패하면 해당 항목의 존재나 내용을 노출하지 않고 작업을 거부한다.

## 8. Design

### 8.1 Behavior

저장 시점에 현재 검색 조건의 필드, 연산자, 검색값을 저장 검색 필터에 캡처한다. 검색 결과, 검색된 사용자 레코드, 개인정보 원문은 저장하지 않는다. 저장 필터는 사용자와 워크스페이스 조합으로 범위가 정해지며, 한 조합에서 최대 20개까지 둘 수 있다.

목록 조회는 현재 인증된 관리자와 현재 워크스페이스 범위로 제한한다. 적용은 저장된 조건을 현재 검색 화면의 조건으로 복원하며, 현재 지원되지 않는 필드 또는 연산자는 적용하지 않는다. 적용 결과가 완전하지 않으면 어떤 조건이 제외되었는지와 현재 적용된 조건이 부분 적용임을 함께 안내한다.

이름 변경은 필터의 조건을 바꾸지 않고 이름만 갱신한다. 삭제는 해당 저장 필터를 목록과 서버 저장 데이터에서 제거한다. 저장, 적용, 부분 적용, 삭제의 결과는 관측 가능한 이벤트 또는 결과 기록으로 남아 운영자가 각 결과를 확인할 수 있어야 한다.

### 8.2 Conceptual Data Model

| Entity | Meaning |
| ------ | ------- |
| Saved Search Filter | 한 사용자·워크스페이스 범위에서 재사용할 검색 조건과 이름을 가진 저장 항목이다. |
| Filter Condition | 필드, 연산자, 검색값으로 이루어진 검색 조건이다. |

| Field | Meaning |
| ----- | ------- |
| owner | 저장 항목을 소유한 관리자 사용자다. |
| workspace | 저장 항목이 유효한 워크스페이스다. |
| name | 사용자에게 표시되는 필터 이름이다. 동일 소유자·워크스페이스 범위에서 대소문자를 구분하지 않고 고유해야 한다. |
| conditions | 필드, 연산자, 검색값만 포함하는 JSON 검색 조건 목록이다. |

### 8.3 Failure Handling

- 인증되지 않은 요청은 저장 필터를 조회하거나 변경할 수 없다.
- 현재 사용자 또는 워크스페이스와 소유권이 일치하지 않는 항목은 조회·적용·이름 변경·삭제할 수 없다. 존재 여부나 내용도 유추할 수 있는 방식으로 노출하지 않는다.
- 같은 사용자·워크스페이스 범위에서 대소문자만 다른 이름을 포함한 중복 이름은 거부한다.
- 한도에 도달한 상태에서 새 항목을 저장하려는 요청은 기존 항목을 자동 삭제하거나 덮어쓰지 않고 거부한다.
- 저장된 필드나 연산자가 제거된 경우 유효한 조건만 적용하고 부분 적용 결과를 표시한다.
- 서버 저장 또는 변경이 실패하면 화면의 목록과 검색 조건을 성공한 것처럼 갱신하지 않고 실패 결과를 안내한다.

## 9. Policy Decisions

### 9.1 Ownership and Visibility Policy

Decision:

- 저장 필터는 생성한 사용자와 워크스페이스에 귀속된다.
- 소유자만 자신의 저장 필터를 보고 적용·이름 변경·삭제할 수 있다.
- 모든 조회·변경에서 기존 관리자 인증과 소유권 검사를 수행한다.

Rationale:

- 개인 검색 작업을 다른 관리자에게 노출하지 않으면서 권한 경계를 단순하고 예측 가능하게 유지하기 위해서다.

### 9.2 Name Uniqueness Policy

Decision:

- 이름은 같은 사용자·워크스페이스 안에서 대소문자를 구분하지 않고 고유해야 한다.
- 저장과 이름 변경 모두 중복 이름을 거부한다.

Rationale:

- 목록에서 항목을 명확히 식별하고, 대소문자 차이만으로 혼동되는 이름을 방지하기 위해서다.

### 9.3 Capacity Policy

Decision:

- 사용자·워크스페이스 조합마다 저장 필터를 최대 20개까지 허용한다.
- 20개에 도달하면 새 저장을 거부하며 기존 항목을 임의로 교체하지 않는다.

Rationale:

- 목록을 관리 가능한 크기로 유지하고 사용자가 명시하지 않은 데이터 손실을 막기 위해서다.

### 9.4 Degradation Policy

Decision:

- 적용 시점에 현재 존재하지 않거나 지원되지 않는 조건은 제외하고 유효한 조건만 적용한다.
- 하나라도 제외된 조건이 있으면 결과를 부분 적용으로 분류하고 사용자에게 안내한다.

Rationale:

- 필드 변화 때문에 저장 필터 전체를 사용할 수 없게 되는 상황에서도 유효한 검색 의도를 보존하되, 조용히 다른 검색을 실행하지 않기 위해서다.

### 9.5 Persistence and Data Minimization Policy

Decision:

- 저장 데이터는 서버의 JSON 표현으로 보존한다.
- 저장 범위는 필드, 연산자, 검색값과 표시 이름 및 소유 범위로 한정한다.
- 개인정보 원문이나 검색 결과 자체는 저장하지 않는다.

Rationale:

- 여러 기기에서 동일한 사용자가 접근할 수 있는 지속성을 제공하면서 저장 데이터의 민감도와 노출 범위를 줄이기 위해서다.

## 10. Alternatives Considered

### Alternative: localStorage 저장

Description:

- 브라우저의 로컬 저장소에 사용자의 필터를 보존하는 방식이다.

Why not chosen:

- 여러 기기에서 같은 저장 필터를 사용할 수 없으므로 관리자 업무의 지속성과 재사용 요구를 충족하지 못한다.

### Alternative: 워크스페이스 공유 필터

Description:

- 워크스페이스의 여러 관리자가 함께 보고 사용하는 저장 필터 방식이다.

Why not chosen:

- 권한과 소유권 모델이 복잡해지고, v1.0의 개인 필터 문제를 해결하는 데 필요한 범위를 넘어선다.

## 11. Cross-cutting Concerns

### 11.1 Security

- 기존 관리자 인증을 모든 저장 필터 조회·변경의 전제로 사용한다.
- 조회·적용·이름 변경·삭제마다 사용자와 워크스페이스 소유권을 검사한다.
- 권한이 없는 항목의 내용과 존재 여부가 유추되지 않도록 한다.

### 11.2 Privacy

- 개인정보 원문과 검색 결과는 저장하지 않는다.
- 저장 데이터는 필드, 연산자, 검색값 및 기능에 필요한 이름·소유 범위로 제한한다.
- 검색값 자체가 민감할 수 있으므로 기존 관리자 데이터 보호 경계 안에서 저장·조회한다.

### 11.3 Permissions

- 소유자만 자신의 필터를 볼 수 있고 관리할 수 있다.
- 워크스페이스가 바뀌면 이전 워크스페이스의 필터를 현재 목록이나 작업 대상으로 사용하지 않는다.
- 공유·대리 관리 권한은 v1.0에서 제공하지 않는다.

### 11.4 Observability

- 저장, 적용, 부분 적용, 삭제 결과를 구분해 관측할 수 있어야 한다.
- 부분 적용에서는 제외된 조건이 있었음을 결과에 포함해 운영 및 사용자 문제 분석이 가능해야 한다.
- 관측 데이터에 개인정보 원문이나 불필요한 검색 결과를 포함하지 않는다.

### 11.5 Accessibility

- 키보드만으로 목록 탐색, 적용, 이름 변경, 삭제를 수행할 수 있어야 한다.
- 성공, 거부, 실패, 부분 적용 안내는 보조 기술이 인식할 수 있는 방식으로 제공한다.
- 이름 중복과 저장 한도 등 입력·작업 오류의 원인을 명확히 전달한다.

### 11.6 Internationalization

- 필터 이름과 사용자 안내 문구는 유니코드를 지원한다.
- 이름 비교의 대소문자 비구분 규칙은 지원 언어와 유니코드 입력을 고려해 일관되게 적용한다.
- 사용자에게 노출되는 상태와 오류 문구는 번역 가능해야 하며, 조건 값의 의미를 임의로 번역해 저장하지 않는다.

## 12. Scope

### In Scope for v1.0

- 현재 사용자 검색 조건의 이름 지정 저장과 서버 JSON 보존
- 사용자·워크스페이스별 최대 20개 저장 필터
- 소유자 전용 목록 조회
- 저장 필터 적용, 이름 변경, 삭제
- 같은 사용자·워크스페이스 안에서 대소문자를 구분하지 않는 이름 고유성 및 중복 거부
- 제거된 필드 또는 연산자에 대한 유효 조건만의 부분 적용과 안내
- 기존 관리자 인증, 소유권 검사, 결과 관측
- 키보드 접근성, 유니코드 이름, 번역 가능한 안내 문구

### Out of Scope for v1.0

- 공유 필터 또는 워크스페이스 공동 소유
- 기본 필터 지정 또는 자동 적용
- 사용자 지정 정렬
- 브라우저 `localStorage` 기반 저장

## 13. Risks & Open Questions

### Risks

- 필터 필드와 연산자 변경이 잦으면 부분 적용이 자주 발생하여 사용자가 검색 결과를 오해할 수 있다. 적용 전에 제외 조건과 현재 적용 조건을 분명히 보여 주어야 한다.
- 검색값에 민감한 정보가 포함될 가능성이 있으므로 데이터 최소화와 기존 관리자 데이터 보호 경계를 유지해야 한다.
- 유니코드 이름의 대소문자 비교는 언어별 입력 특성에 따라 사용자가 예상하지 못하는 중복 판정을 만들 수 있다. 비교 규칙을 사용자 경험과 일관되게 노출해야 한다.

### Open Questions

- [NEEDS INPUT: 이름의 최대 길이, 공백 정규화 및 빈 이름 허용 여부]
- [NEEDS INPUT: 저장·적용·부분 적용·삭제 관측 결과의 보존 기간과 운영자가 조회할 구체적 범위]
- [NEEDS INPUT: 필터 조건의 최대 개수와 검색값별 허용 크기]

## 14. Platform Design

### 14.1 Common Design

단일 웹 플랫폼에서 동작한다. 브라우저와 서버 사이의 저장·조회 결과는 인증된 관리자와 현재 워크스페이스 범위에 맞아야 하며, 화면은 저장 필터의 완전 적용·부분 적용·실패 결과를 구분해 보여 준다.

## 15. Result Semantics

| State | Meaning | User-visible? |
| ----- | ------- | ------------- |
| 저장 성공 | 이름과 현재 조건이 소유자·워크스페이스 범위에 저장되었다. | Yes |
| 저장 거부: 중복 이름 | 같은 범위에 대소문자를 구분하지 않는 동일 이름이 있어 저장되지 않았다. | Yes |
| 저장 거부: 한도 초과 | 해당 범위의 저장 필터가 이미 20개이므로 새 항목이 저장되지 않았다. | Yes |
| 적용 성공 | 저장된 조건이 모두 현재 지원되어 검색 화면에 적용되었다. | Yes |
| 부분 적용 | 일부 조건만 현재 유효하여 유효한 조건만 적용되고 제외 조건이 안내되었다. | Yes |
| 변경 성공 | 소유자 필터의 이름이 새 이름으로 변경되었다. | Yes |
| 삭제 성공 | 소유자 필터가 삭제되어 목록에서 제거되었다. | Yes |
| 권한 거부 | 인증 또는 소유권 검사를 통과하지 못해 대상의 조회·변경이 수행되지 않았다. | Yes |
| 작업 실패 | 저장소 또는 서비스 오류로 요청한 저장·적용·변경·삭제가 완료되지 않았다. | Yes |
