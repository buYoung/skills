# 공통 시각 자산 시스템

## 핵심 원칙

실제 제품 화면과 경험을 주인공으로 삼고 장식은 절제한다. 제품의 핵심을 읽게 하는 중립적 바탕 위에 한 가지 선명한 강조색만 사용해 진취적인 인상을 만든다. 강조색은 계층·상태·호출 문구를 묶는 신호이지 배경 장식의 반복 패턴이 아니다.

### 불변 결정

- 실제 제품 화면 또는 제품 경험이 모든 자산의 증거가 된다.
- 장식은 화면 이해를 돕는 범위로 제한한다.
- 선명한 강조색은 한 가지로 통일한다.
- 자산 사이의 색·타이포그래피·톤은 서로 보완되어야 한다.

### 가변 결정

- 화면 순서와 선택 기능은 release의 핵심 사용자 가치에 따라 바꾼다.
- localization마다 번역 길이, 캡처 데이터, 자막·음성을 바꿀 수 있다.
- 강조색의 정확한 색상 토큰과 여백 값은 제품 브랜드 토큰 소유자가 별도로 관리한다.

### 금지 결정

실제 기능을 과장하는 합성 화면, 장식이 UI를 가리는 구성, 여러 강조색의 경쟁, 타사 상표·배지·스토어 아이콘의 무단 사용, 순위·수상·가격·할인을 암시하는 표현, 불필요한 call-to-action을 사용하지 않는다.

## 자산 역할과 관계

| 자산 | 주된 질문 | 관계 |
| --- | --- | --- |
| App icon | “이 앱을 빠르게 식별할 수 있는가?” | 최소 단위의 브랜드 식별자. feature graphic을 복제하지 않고 같은 시각 언어를 공유한다. |
| Screenshots | “설치하면 무엇을 실제로 하게 되는가?” | 실제 제품 화면을 기능 가치 순서로 증명한다. 첫 세 장은 UI를 우선한다. |
| Preview video | “사용 경험이 어떻게 흐르는가?” | 핵심 경험을 가능한 이르게 움직임으로 보여 준다. screenshots보다 먼저 노출될 수 있다. |
| Feature graphic | “이 경험의 맥락과 중심 인상은 무엇인가?” | preview video의 cover가 될 수 있는 넓은 정적 맥락이다. icon의 단순 복제는 피한다. |

자산의 관계는 **식별(icon) → 증거(screenshots) → 흐름(video) → 맥락(feature graphic)** 순서로 설계한다. 어떤 자산도 다른 자산의 기능·정책 주장을 대신하지 않는다.

## 제작 규칙

- 화면은 가장 중요한 상태와 결과를 먼저 보여 주고, 제품에 없는 장식 UI를 덧붙이지 않는다.
- 텍스트 overlay는 화면을 설명하는 최소량만 사용하며, 읽을 수 없는 작은 글자나 반복 문구를 만들지 않는다.
- 중심 피사체와 핵심 UI는 다양한 crop을 견디도록 중앙 안전 영역에 둔다.
- 동영상은 음소거 재생을 고려해 자막 또는 화면 내 맥락을 제공한다.
- 모든 자산은 같은 제품 버전의 기능·문구·브랜드 토큰을 참조해야 한다.

## Localization

언어·지역별 listing을 별도 변형으로 관리한다. 번역은 글자 수를 줄이기 위해 의미를 바꾸지 않으며, UI·overlay·자막·음성을 같은 언어로 맞춘다. 캡처 데이터가 지역별로 달라지는 경우 개인정보와 날짜·통화·단위를 해당 지역 기준으로 검토한다. 번역되지 않은 UI나 잘린 문구가 남으면 전달하지 않는다.

## 전달 및 버전 규칙

각 자산은 `product / surface / locale / app-version / asset-version` 메타데이터와 원본·출력 파일을 함께 전달한다. 파일명은 동일한 순서와 locale 코드를 사용하고, 화면 순서가 바뀌면 asset-version을 올린다. 기능 변경으로 화면·문구·정책 적합성이 영향을 받으면 관련 자산 묶음을 함께 재검토한다.

검수자는 (1) 실제 제품과 일치하는지, (2) 한 가지 강조색 원칙을 지키는지, (3) localization이 완전한지, (4) store 전용 규격을 만족하는지, (5) 권리·정책 위반 표현이 없는지를 기록한다. 승인된 묶음만 Play Console에 업로드한다.
