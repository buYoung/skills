# Tokens

## Contract

This file owns approved token values, semantic aliases, and component bindings. No exact token values were supplied or verified in this brief, so values remain unresolved rather than inferred from convention.

## Required layers

When values are approved, record them in this order: source tokens, semantic aliases, then component bindings. A component must consume a semantic meaning rather than bypassing the shared meaning with an unexplained local value.

## Unresolved values

The following require an authoritative decision: color roles and values, typography families and scales, spacing and sizing steps, corner geometry, elevation or depth treatment, motion durations and easing, and responsive breakpoints. The web and iOS owners may map these values differently only when a platform constraint is documented; they must not silently create competing common values.

## Verification

Token review checks that each value has a meaning, a single owner, and a consumer; that the dense table and short completion flow preserve hierarchy; and that the 16px icon and large logo use size-appropriate bindings without changing their semantic roles.
