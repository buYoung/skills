# iOS platform adaptation

## Scope

This file covers the iOS app. It preserves the common direction in [foundations.md](../foundations.md) while documenting native interaction and completion-flow context.

## Conditional rules

- The short completion flow may give one next action stronger emphasis and more breathing room than a dense web table.
- Use iOS-native navigation, input, accessibility semantics, and user settings where they are the platform's established convention.
- Completion must be explicit in content and state; motion may reinforce it but cannot be required to perceive it.
- Reduced-motion settings must be honored for nonessential transitions.

## Contextual variation

The iOS flow may be more spacious and transition-oriented than the web administrator table. This variation supports task completion while preserving calm precision, clear hierarchy, and restrained friendliness.

## Unresolved platform values

Exact layout units, supported OS versions, native-component mappings, typography behavior, and motion durations were not supplied and remain implementation decisions.
