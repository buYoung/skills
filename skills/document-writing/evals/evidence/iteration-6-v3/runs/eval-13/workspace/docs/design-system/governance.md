# Governance

## Current status

The direction is approved by the product owner and supported by two representative validation situations. The document set is the current design-system source for the web product, with token values, terminology, component inventory, and lifecycle details still unresolved where the supplied brief provides no decision.

## Decision and review

Changes that alter the approved direction, primary-action hierarchy, or common accessibility contract require product-owner review and renewed checks in both representative situations. Local component or pattern changes must remain within the common direction and record their conditional web consequences in the owning document.

## Validation gate

Before adopting a changed rule, inspect a simple settings screen and an information-dense data table. Check hierarchy, density, perception, keyboard and pointer operation, semantics, focus, scaling, and reduced motion. If a check fails, identify whether the failure belongs to direction, a shared rule, a component/pattern rule, or web adaptation before revising it.

## Unresolved lifecycle decisions

The supplied brief does not define named owners, release cadence, compatibility policy, contribution workflow, deprecation process, or status labels. These must be supplied before this section is treated as an operational process.
