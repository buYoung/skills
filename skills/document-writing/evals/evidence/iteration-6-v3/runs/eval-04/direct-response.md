# Idempotency-Key 계약

## 범위

이 문서는 SDK 구현자가 `POST` 요청에 적용되는 idempotency key 계약을 빠르게 조회할 수 있도록 정의한다. 개념 소개나 설치 절차는 범위에 포함하지 않으며, 키와 요청 본문 조합에 따른 서버 응답 및 충돌 조건을 규정한다.

## 빠른 참조

| 항목 | 계약 |
| --- | --- |
| 적용 메서드 | `POST` 요청에 적용한다. |
| 자동 재시도 | 수행하지 않는다. SDK가 자동 재시도를 추가해서는 안 된다. |
| 키 형식 | UUID를 사용한다. UUID의 세부 버전·직렬화 규칙은 이 계약에서 지정하지 않는다. |
| 같은 논리 작업 | 같은 논리 작업의 재요청에는 같은 UUID를 재사용한다. |
| 새 논리 작업 | 새 논리 작업에는 새 UUID를 사용한다. |
| 보관 기간 | idempotency key를 24시간 보관한다. 보관 기간의 시작 시점과 만료 후 동작은 이 계약에서 지정하지 않는다. |
| 응답 식별 단위 | idempotency key와 요청 본문의 조합으로 식별한다. |
| 동일 키·동일 본문 | 동일한 논리 작업의 재요청으로 처리한다. 서버는 해당 조합에 대한 응답을 재사용해야 한다. |
| 동일 키·다른 본문 | 충돌로 처리하며 `409 Conflict`를 반환한다. |
| 다른 키·동일 본문 | 다른 idempotency key를 사용한 별도 조합이다. 이 계약은 추가적인 중복 판정이나 응답 세부 사항을 지정하지 않는다. |

## 적용 규칙

### 요청 범위

- idempotency key는 `POST` 요청에 적용한다.
- 자동 재시도는 수행하지 않는다. 재시도가 필요하면 호출자가 같은 논리 작업에 사용한 UUID를 직접 재사용해야 한다.

### 키 생성과 재사용

| 상황 | 사용할 키 |
| --- | --- |
| 네트워크 오류 등으로 같은 논리 작업을 다시 요청 | 최초 요청과 같은 UUID |
| 사용자가 새 작업을 시작 | 새 UUID |
| 동일한 UUID로 요청 본문을 변경해 재요청 | 변경된 본문과의 조합이므로 허용되지 않으며 `409 Conflict` |

키를 논리 작업의 식별자로 관리한다. 요청을 다시 보내는지 여부가 아니라 논리 작업이 같은지 여부에 따라 UUID를 재사용한다.

## 키·본문 조합별 서버 응답

| 이전에 같은 키로 저장된 요청 본문 | 현재 요청 본문 | 서버 처리 및 응답 |
| --- | --- | --- |
| 없음 | 임의의 본문 | 조합을 새로 기록하고 해당 요청을 처리한다. 최초 처리의 구체적인 성공·실패 응답 형식은 이 계약에서 지정하지 않는다. |
| 같음 | 같음 | 같은 논리 작업의 재요청으로 처리하고, 최초 조합에 대한 서버 응답을 재사용한다. |
| 다름 | 다름 | 같은 키를 다른 요청에 사용한 것으로 간주하고 `409 Conflict`를 반환한다. |

핵심 판정은 키만으로 하지 않고 `idempotency key + request body` 조합으로 한다. 따라서 같은 키를 유지한 채 본문을 바꾸어 새 작업처럼 보내서는 안 된다.

## 오류와 예외

### `409 Conflict` 조건

다음 조건을 모두 만족하면 서버는 `409 Conflict`를 반환한다.

1. 이전 요청과 현재 요청이 같은 idempotency key를 사용한다.
2. 현재 요청의 본문이 이전 요청의 본문과 다르다.

이는 같은 UUID를 서로 다른 논리 작업에 재사용한 충돌이다. SDK는 이 응답을 자동 재시도로 해결해서는 안 되며, 호출자가 논리 작업을 확인한 뒤 올바른 키를 선택해야 한다.

### 보관 기간 경계

키는 24시간 보관한다. 24시간의 시작 시점, 만료된 키의 재사용 시 처리, 만료된 조합의 응답은 제공된 계약에 정의되어 있지 않으므로 SDK가 별도 동작을 추론해서는 안 된다.

## 구현 예시와 반례

### 올바른 사용

```text
논리 작업 A: UUID-1로 POST
논리 작업 A 재요청: UUID-1로 같은 본문을 POST
논리 작업 B: UUID-2로 POST
```

논리 작업 A의 재요청은 같은 UUID와 같은 본문 조합을 사용한다. 논리 작업 B는 새 논리 작업이므로 새 UUID를 사용한다.

### 충돌하는 사용

```text
첫 요청: UUID-1 + 본문 P
재요청:  UUID-1 + 본문 Q
```

`P`와 `Q`가 다르면 서버는 `409 Conflict`를 반환한다. 본문 `Q`를 새 논리 작업으로 처리하려면 새 UUID를 사용해야 한다.

## 미지정 사항

다음은 이 계약의 범위를 벗어나므로 구현 시 별도 권위 있는 API 문서를 확인해야 한다.

- UUID 세부 버전, 헤더 필드명, 직렬화 방식
- 24시간 보관의 시작 시점과 만료 직후의 처리
- 최초 요청의 성공·실패 응답 스키마
- 동일 키·동일 본문 재요청 시 응답 본문의 세부 형식
- 키가 없거나 UUID 형식이 아닌 경우의 오류 코드
