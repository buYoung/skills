3. 테스트 2는 오타가 있는 README가, 테스트 3은 작은 샘플 프로젝트가 필요합니다 (각 테스트 섹션 참고).

## 테스트 1 — 본격 코드 작업 (전체 루프 검증)

**목적**: 세션 생성 → 패널 선택 → 작업자 빌드 → 병렬 리뷰 → 병합 → 개선 → 요약 → 정리까지 전체 흐름.

**프롬프트** (복사해서 사용):

```
다음 스킬 파일을 읽고 그 절차를 그대로 따라서 작업해줘: <SKILL_PATH>/SKILL.md
(references/ 안의 파일들도 필요한 시점에 읽어.)

작업 내용: CSV 파일을 입력받아서 중복 행을 제거하고, 각 숫자 컬럼의
합계/평균/최솟값/최댓값을 요약해서 출력하는 Python CLI 스크립트를 만들어줘.
인자로 CSV 경로를 받고, --output 옵션을 주면 중복 제거된 CSV를 그 경로에
저장해줘. 잘못된 파일 경로나 빈 파일도 적절히 처리해줘.
```

**관찰 체크리스트**:

- [ ] 시작 시 패널을 한 줄로 공지했는가 (예상: 정확성, 요구사항 충족, 단순성)
- [ ] `.agents/agents-community/<날짜>-<슬러그>/task_request.md`가 생성됐는가
- [ ] 작업자/리뷰어 프롬프트에 문서 **경로만** 들어가고 내용이 인라인되지 않았는가 (트랜스크립트 확인)
- [ ] 리뷰어들이 같은 턴에 병렬로 실행됐는가
- [ ] `reviews/<렌즈>_0.md` 파일이 렌즈별로 생성됐는가
- [ ] 차단급/주요 지적이 있었다면 `merged_findings_0.md`가 생성되고 작업자에게 **경로로** 전달됐는가
- [ ] 2회차 리뷰가 축소 재검 모드(자기 이전 리뷰 경로 전달)로 돌았는가
- [ ] 최종 요약이 내부 용어 없이 한국어 15줄 이내였는가
- [ ] 전원 통과 시 세션 디렉터리가 삭제됐는가
- [ ] (보너스) `.agents/`가 `.gitignore`에 추가됐는가

## 테스트 2 — 사소한 작업 (단순성 게이트 검증)

**목적**: 게이트가 작동해서 질문 도구로 물어보는지, 거절 시 깨끗하게 빠지는지.

**사전 준비**:

```bash
echo "This tool will recieve a CSV file and clean it." > README.md
```

**프롬프트**:

```
다음 스킬 파일을 읽고 그 절차를 그대로 따라서 작업해줘: <SKILL_PATH>/SKILL.md
(references/ 안의 파일들도 필요한 시점에 읽어.)

작업 내용: README.md에 있는 오타 'recieve'를 'receive'로 고쳐줘.
```

**관찰 체크리스트** — **거절 경로** (질문이 나오면 "일반 방식으로 처리" 선택):

- [ ] 작업자/리뷰어를 띄우기 **전에** 질문 도구로 물어봤는가
- [ ] 질문이 평이한 언어였는가 (내부 용어 없이)
- [ ] 거절 후 세션 디렉터리가 삭제됐는가
- [ ] 오타는 일반 편집으로 고쳐졌는가 (작업 요청 자체를 버리지 않았는가)
- [ ] 서브 에이전트가 하나도 생성되지 않았는가

**같은 프롬프트로 한 번 더 실행 — 허용 경로** ("그래도 루프 진행" 선택):

- [ ] 허용 후 다시 묻지 않고 4단계(작업자 빌드)로 진행했는가
- [ ] 사소한 작업이라 패널이 과하게 크지 않았는가 (2~3인 기대)

## 테스트 3 — 계획 문서 작업 (패널 자동 선택 + scout 검증)

**목적**: 산출물 유형에 따라 렌즈가 바뀌는지(실행 가능성 포함, 보안/단순성 제외), scout가 돌고 그 결과가 작업자에게만 가는지.

**사전 준비** (작은 샘플 웹 프로젝트):

```bash
mkdir -p src && cat > src/index.html <<'EOF'
<!DOCTYPE html><html><head><link rel="stylesheet" href="style.css"></head>
<body><h1>My App</h1><script src="app.js"></script></body></html>
EOF
echo "body { background: #fff; color: #111; }" > src/style.css
echo "console.log('hello');" > src/app.js
```

**프롬프트**:

```
다음 스킬 파일을 읽고 그 절차를 그대로 따라서 작업해줘: <SKILL_PATH>/SKILL.md
(references/ 안의 파일들도 필요한 시점에 읽어.)

작업 내용: 이 프로젝트에 다크 모드를 추가하기 위한 실행 계획 문서를
docs/dark-mode-plan.md 로 작성해줘. 단계별 작업 목록, 예상 리스크,
기존 코드에서 손대야 할 부분을 포함해줘.
```

**관찰 체크리스트**:

- [ ] 패널에 **실행 가능성(feasibility)** 렌즈가 포함되고, 보안 렌즈는 빠졌는가
- [ ] scout가 실행되어 `research/context.md`를 작성했는가
- [ ] scout 보고서 끝에 `verdict: simple|substantial`이 있는가
- [ ] **리뷰어 프롬프트에 `research/context.md` 경로가 절대 들어가지 않았는가** (격리 계약의 핵심)
- [ ] 산출물(`docs/dark-mode-plan.md`)은 실제 저장소 경로에, 조정 문서는 세션 디렉터리에만 있는가

## 공통 기록 사항

각 테스트 후 다음을 메모해 주세요 (다음 반복 개선에 사용):

1. 스킬이 절차를 건너뛰거나 임의로 변형한 지점
2. 서브 에이전트 프롬프트에 세션 문서 **내용이 인라인된** 사례 (경로 규칙 위반)
3. 리뷰어가 받으면 안 되는 경로를 받은 사례 (블라인드 붕괴)
4. 토큰/시간이 과하게 느껴진 구간 (특히 사소한 작업 대비)
5. 최종 요약이 바이브 코더 기준으로 읽기 쉬웠는지
6. 비정상 종료가 발생했다면: 세션 디렉터리가 보존되고 경로가 안내됐는지
