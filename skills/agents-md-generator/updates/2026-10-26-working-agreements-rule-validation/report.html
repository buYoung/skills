Working Agreements 규칙 실측 검증

규칙 후보 5개(C0~C4)를 TypeScript·Python의 같은 코딩 과제에 적용해 Sonnet 하위 에이전트가 쓴 코드를 비교했습니다. 후보와 언어마다 3회씩, 모두 30회 실행했습니다. 이어서 같은 로직이 다시 필요해지는 상황과 분기가 셋인 계산을 2차 실험(18회)으로 확인했습니다. 반영안 v5를 스킬에 적용하고, 적용 전·후 스킬로 실제 생성한 AGENTS.md로 코딩을 비교했습니다(생성 4회, 코딩 24회). 마지막으로 실제 문서에서 약했던 N8 문구 2안을 비교해 A안을 채택했습니다(코딩 12회).

규칙 분류: 필요한 규칙과 다시 볼 규칙

1차 30회, 2차 18회, 전후 비교 24회, N8 문구 실험 12회 모두 동작 테스트와 타입 검사를 통과했습니다. 차이는 코드 모양과 수정 범위에서 났습니다. 수치는 모두 3회 중 규칙에 맞게 행동한 횟수이고, 아래 매트릭스에서 칸을 누르면 실행별 근거가 열립니다.

규칙별 신호 매트릭스

숫자와 색 농도는 3회 중 규칙에 맞게 행동한 횟수(0~3회)입니다. ● 일반화 규칙 있음, ○ 원문 규칙 있음, 표시 없음은 해당 규칙이 없는 후보입니다. 행은 위 분류 순서대로 묶었고, 칸을 누르면 실행별 근거가 열립니다.

2차 실험: 같은 로직이 다시 필요할 때와 분기가 셋일 때

1차 기능의 할인 로직이 handleCheckout 한 곳에 인라인으로 들어간 저장소에서 시작했습니다. 같은 로직이 필요한 미리보기 기능과 세 단계 배송비(무료·299·499)를 요청했습니다. 후보는 C0 기존 규칙, C1 최종안, C1T(최종안에 "삼항식은 한 단계까지" 규칙 N14를 더한 안)입니다. 칸을 누르면 실행별 근거가 열립니다.

스킬 변경 전·후 비교: 실제로 생성한 AGENTS.md

v5를 적용하기 전과 후의 스킬로 같은 저장소(1차 과제 시작 상태)의 AGENTS.md를 Sonnet이 실제로 생성했습니다. 두 스킬은 working_agreements.md 한 파일만 다릅니다. 생성된 문서를 그대로 두고 1차 과제와 2차 과제를 각각 3회씩 코딩시켰습니다(2차 과제 저장소에도 같은 문서를 넣었습니다). 칸을 누르면 실행별 근거가 열립니다.

N8 문구 실험: 외부 데이터 검사 문장

변경 후 스킬로 생성한 AGENTS.md에서 N8 한 줄만 바꿔 1차 과제를 3회씩 실행했습니다. v5 문구 열은 전후 비교의 변경 후 실행을 재사용했습니다. 칸을 누르면 실행별 근거가 열립니다.

변경 크기와 반복 일관성

1차 실험 기준입니다. 점 하나가 실행 하나이고, 가로축은 추가된 줄 수입니다. TypeScript에서는 외부 JSON 검사 함수를 넣은 C1·C2가 50~67줄로 길고, 기존 + 원문(C4)은 22~23줄로 가장 짧습니다. Python에서는 C3·C4가 22~26줄로 짧고 일관됐고, 검사 함수를 따로 만든 C2가 50~70줄로 가장 깁니다. 최종안(C1)은 22~46줄로 회차마다 차이가 컸습니다.

실험 방법과 한계

  • 과제: 같은 쇼핑몰 기능(레거시 쿠폰을 할인 코드로 교체)을 TypeScript와 Python 픽스처 저장소에 하나씩 두었습니다. 과제 안에 규칙별 함정을 넣었습니다: 한 번만 쓰는 할인 계산, 이미 검증된 주문, 외부 JSON 파일, 파일 누락, 사용 횟수 저장(경합 유혹), 미사용이 되는 레거시 함수, 무관한 죽은 코드, 바꿔야 하는 함수 안의 기존 줄.
  • 실행: 후보 5개 × 언어 2개를 1회차로 하고 3회 반복했습니다(Sonnet 하위 에이전트 30개). 에이전트는 사용자와 대화할 수 없어, 질문이 필요하면 보고서에 적도록 했습니다.
  • 측정: diff를 정규식으로 분석하고, 핵심 함정은 직접 확인했습니다. 동작 테스트 8개와 tsc --noEmit(Python은 컴파일)를 직접 실행했습니다.
  • 한계: 과제가 한 종류이고 반복이 3회라 작은 차이는 우연일 수 있습니다. 하위 에이전트에는 사용자 전역 지침(CLAUDE.md)과 기본 시스템 지침이 함께 로드됐을 수 있어, 프롬프트로 AGENTS.md만 따르라고 지시했지만 완전히 배제됐는지는 확인하지 못했습니다. 질문 여부는 에이전트의 자기 보고입니다.
  • 2차 실험: 1차 기능이 인라인으로 들어간 같은 픽스처에서 미리보기 기능과 세 단계 배송비를 요청했습니다. 후보 3개 × 언어 2개 × 3회로 Sonnet 하위 에이전트 18개를 실행했고, 동작 테스트 9개(배송비 4단계, 미리보기 할인·사용 횟수 유지·거절, 결제 시 사용 횟수 증가)를 직접 돌렸습니다.
  • 전후 비교: v5 적용 전·후 스킬(차이는 working_agreements.md 한 파일)로 1차 과제 저장소의 AGENTS.md를 TypeScript·Python 각각 생성했습니다. 이 문서로 1차·2차 과제를 3회씩 실행했습니다(Sonnet 코딩 24회). 1회(1차 과제·Python·변경 후·2회차)는 보고서를 남기지 않았고 직접 실행하며 config/discounts.json을 바꿔 두었습니다. 동작 테스트는 모든 실행에서 원본 데이터로 시작했습니다.
  • N8 문구 실험: 변경 후 스킬이 생성한 AGENTS.md에서 N8 한 줄만 A안·B안으로 바꿔 1차 과제를 언어별 3회씩 실행했습니다(Sonnet 12회). v5 문구 기준은 전후 비교의 변경 후 실행 6회를 재사용했습니다.
  • N5(일회용 변수)는 따로 측정하지 않았고, N3 함정 줄의 일회용 변수 subtotal에만 반영했습니다.
  • "차이 없음"은 "필요 없음"이 아닙니다. 이번 과제에서는 모든 후보가 이미 그렇게 행동했다는 뜻입니다.
