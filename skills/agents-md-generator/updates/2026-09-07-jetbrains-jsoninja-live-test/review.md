# JSONinja 실제 적용 검증

`gpt-5.6-sol`의 `medium` 설정에서 사용자 입력을 `agents-md-generator` 한 줄로 주고 기존 JSONinja 저장소의 문서를 갱신했다. 관리 표식이 없는 원본에 대해 변경안을 먼저 제시하고 최초 편입 확인을 받은 뒤 적용했으며, 사용자 영역 3개와 영역별 글자 수 한도를 보존했다.

## 실행 조건

| 항목 | 값 |
| --- | --- |
| 실행일 | 2026-09-07 |
| 대상 | JetBrains JSONinja — `intellij-json-helper2` 저장소의 `AGENTS.md` |
| 모델 / 추론 수준 | `gpt-5.6-sol` / `medium` |
| 사용자 입력 전체 | `agents-md-generator` |
| 사용 스킬 | 저장소의 [수정본 SKILL.md](../../SKILL.md) |
| 실행 구성 | 대화 이력을 전달하지 않은 하위 에이전트 1개; 승인 후 같은 에이전트가 적용 |
| 초기 상태 | 단일 저장소, 관리 표식 없음, 표준 영역 5개 및 사용자 영역 3개 |
| 저장소 규모 | LOC 34,426, 관리 영역 한도 12,000자 |

대상 경로, 수정본 스킬 경로, 기존 변경 보존 및 결과 전달 지침은 실행 환경 정보로 별도 제공했다. 사용자 입력에는 추가 생성 요구사항을 붙이지 않았다. `codemap-search`는 대상이 허용 작업 공간 밖이어서 사용할 수 없었고, 에이전트는 범위를 제한한 읽기 전용 명령과 스킬의 번들 스크립트를 사용했다. Serena는 사용하지 않았다.

## 관찰 결과와 적용

- 파서는 원본을 `unmarked`로 판정했다. 표준 제목이 모두 일치해도 즉시 덮어쓰지 않고 변경안을 완성한 뒤 편입 확인을 요청했다.
- 사용자가 결과 보관과 JSONinja 반영을 요청한 후, 적용 직전에 대상이 보관 원본과 바이트 단위로 같은지 확인했다. 승인된 제안본을 복사한 뒤 실제 대상과 제안본의 바이트 일치도 확인했다.
- 생성본은 `management_status=managed`, `generated_doc_type=single_repo`이며, 관리 표식은 1개다. 필수 영역 누락과 표준 영역 중복은 없다.
- 표준 영역 5개 본문을 갱신했다. 기존 소유 경계를 재분석하고 설정 저장, 온보딩, 접기 동작의 안정적인 경계와 최근 변경 경로를 구분했다. 전체 교체 내용은 [비교 패치](agents.patch)에서 확인할 수 있다.
- `## 6. User Custom`, `## When Extending`, `## Threading Rules`는 원본과 바이트 단위로 같다. 관리 표식 삽입 이외의 서문은 유지했다.
- 대상 저장소의 기존 `.codemap/config.toml` 수정과 `assets/`, `docs/design-system-icons/` 미추적 상태는 유지됐고, 이 실행에서는 `AGENTS.md` 수정만 추가됐다.

## 글자 수 및 검증

글자 수는 UTF-8로 읽은 문자의 수이며, 제목과 줄바꿈을 포함한다. 사용자 영역은 예산에서 제외하고 서문과 관리 영역만 합산했다. 보관 과정에서도 Python으로 다시 계산해 아래 값을 확인했다.

| 영역 | 글자 수 | 한도 |
| --- | ---: | ---: |
| 서문 및 관리 표식 | 69 | 전체 한도에 포함 |
| Overview | 209 | 600 |
| Ownership Map | 3,842 | 4,200 |
| Core Behaviors & Patterns | 2,979 | 3,000 |
| Conventions | 2,395 | 2,400 |
| Working Agreements | 995 | 1,800 |
| 관리 영역 합계 | 10,489 | 12,000 |

실행 에이전트는 파서 출력, 사용자 영역 비교, 관리 영역의 금지 문구 검색, Git 변경 상태를 확인했다. 적용 후 `git diff --check -- AGENTS.md`도 통과했다. 보관 과정에서 실제 대상과 생성본의 일치, 사용자 영역 보존, 관리 표식 및 영역별 한도를 별도로 확인했다.

## 검증 범위와 한계

이번 실행은 기존 문서의 갱신과 최초 편입, 사용자 확인 이후 실제 적용을 확인한 단일 실행이다. 이전 스킬이나 스킬 없는 실행과의 모델 비교는 하지 않았으므로 생성 품질 향상률이나 반복 성공률을 의미하지 않는다. 신규 문서 생성, 여러 줄 Gradle 선언 탐지, 루트 문서가 없는 패키지 생성은 이 저장소 실행으로 검증하지 않았다.

코드 변경이 없어 Gradle 빌드나 타입 검사는 실행하지 않았다. 문서에 기록된 모든 플러그인 동작을 실제 IDE에서 실행 검증한 것은 아니다.
